# Отчёт по членам СРО: НОСТРОЙ + Чеко

Собирает таблицу по членам СРО из реестра НОСТРОЙ, дополняя её контактами
и реквизитами из [Чеко](https://checko.ru/).

Колонки итогового отчёта:

| Колонка | Источник |
|---|---|
| Название компании | НОСТРОЙ, сокращено до `ООО «…»`, `АО «…»`, `ЗАО «…»`, `ИП Фамилия И. О.` |
| ИНН | НОСТРОЙ |
| Телефон | Чеко |
| Email | Чеко |
| Адрес | Чеко, **один** — юридический |
| ФИО руководителя | Чеко; у ИП — из наименования, без запроса к API. Если компанией руководит управляющая организация, пишется её название вместе с ООО/АО |
| Дата вступления в СРО | НОСТРОЙ |
| Статус членства | НОСТРОЙ |

Колонки «Дата исключения из СРО» нет: в выгрузке она была пуста во всех строках.
Исключённые члены видны по колонке «Статус членства» и подсвечены розовым.

## Как пользоваться

```bash
pip install -r requirements.txt

# 1. Пересобрать отчёт из уже имеющихся данных — без единого запроса к API
python3 build_report.py --source final_report_20260820.xlsx

# 2. Посмотреть, кому не хватает данных и сколько это запросов
python3 enrich.py --source final_report_20260820.xlsx --dry-run

# 3. Добрать недостающее через API (ключ — только через переменную окружения)
export CHECKO_API_KEY='ваш-ключ'
python3 enrich.py --source final_report_20260820.xlsx --limit 3   # сначала проба
python3 enrich.py --source final_report_20260820.xlsx             # затем весь дневной лимит

# Если нужен гарантированно достоверный адрес по всем 200 ИНН, а не только
# там, где его не хватает — запрос юрадреса из ЕГРЮЛ для каждой строки:
python3 enrich.py --source final_report_20260820.xlsx --all-addresses

# 4. Пересобрать отчёт уже с добранными данными
python3 build_report.py --source final_report_20260820.xlsx
```

Исходный файл не перезаписывается никогда: `build_report.py` откажется писать
в него и требует отдельный `--out` (по умолчанию `Отчёт_СРО.xlsx`).

## Суточный лимит 100 запросов

`enrich.py` считает запросы сам и не даёт превысить лимит:

* каждый ответ Чеко кладётся в `cache/checko/<ИНН>.json` — повторный запуск
  скрипта не тратит на этот ИНН ни одного запроса;
* расход за сегодня хранится в `cache/checko/_quota.json` и сбрасывается
  в полночь по локальному времени;
* при исчерпании лимита скрипт останавливается и печатает, сколько ИНН осталось;
* ИНН запрашиваются по важности пропуска: сперва те, у кого нет адреса
  и руководителя, в последнюю очередь — те, кому не хватает только email.

Пробить 110 оставшихся ИНН = два дня по 100 запросов.

## Откуда берётся один адрес вместо нескольких

Первый прогон склеивал в одну ячейку через `;` всё, что нашлось: юридический
адрес, адреса филиалов и — у 192 строк из 200 — адрес самого СРО.

`lib/address.py` выбирает из них один:

1. **Адреса СРО отбрасываются.** Собственный адрес компании уникален, а адрес
   СРО повторяется у сотен строк — он определяется по доле строк автоматически,
   без ручного списка.
2. **Регион сверяется с ИНН.** Первые две цифры ИНН — код региона регистрации;
   адрес в этом регионе получает решающий приоритет. Так у АО «Аварийно-технический
   центр Росатома» из восьми адресов выбирается петербургский, а не подмосковный.
3. **Формат ФИАС.** Строка с `вн. тер. г.` — это то, что Чеко отдаёт в поле
   `ЮрАдрес`, а не адрес филиала.
4. **Старый формат КЛАДР** (`Санкт-Петербург г, Фонтанки наб`) штрафуется:
   так пишет выгрузка НОСТРОЙ, Чеко — никогда.

Выбранный адрес чистится от административного шума: фрагмент
`вн. тер. г. муниципальный округ Такой-то` из формата ФИАС удаляется
(он есть у 87 адресов и растягивает ячейку на три строки, из-за чего один
адрес читается как несколько), а `вн. тер. г. город Кронштадт` сжимается
до `г. Кронштадт`. Медианная длина адреса падает со 106 символов до 76.

Если после этого два кандидата равны, строка попадает на лист
**«Требуют уточнения»**, и `enrich.py` запросит по ней точный `ЮрАдрес`.

На данных первого прогона: 168 адресов выбраны однозначно, 11 спорных,
21 отсутствует.

## Структура

```
build_report.py   сборка xlsx (без сети)
enrich.py         добор данных через API Чеко
lib/names.py      сокращение названий, ФИО предпринимателя из наименования
lib/address.py    выбор одного адреса
lib/checko.py     клиент API: кэш, суточный лимит, разбор ответа
cache/checko/     ответы Чеко (в git не попадает)
```

## Если поля API не совпали

Клиент написан по документированной схеме Чеко v2 (`ЮрАдрес.АдресРФ`,
`Руковод.ФИО`, `Контакты.Тел`, `Контакты.Емэйл`) и переживает отсутствие любого
поля. Первый запуск делайте с `--limit 3` и загляните в `cache/checko/*.json`:
если структура ответа окажется другой, править нужно только функцию
`extract()` в `lib/checko.py`.

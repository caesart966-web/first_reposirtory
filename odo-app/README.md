# ОДО‑проверка — веб‑приложение для проверяющего СРО

Оболочка над движком `/.claude/skills/sro-odo`: загрузили договор со сметами —
получили вывод «входит / не входит в ОДО» с нормой закона под каждым шагом,
реестр по компании с итоговой суммой, разбор писем‑возражений и базу прецедентов.
Работает в браузере, ставится на обычный компьютер или на сервер.

## Установка (5 минут)

Нужен Python 3.11+ и папка репозитория целиком (движок лежит рядом, в `.claude/skills/sro-odo`).

```bash
cd odo-app
pip install -r requirements.txt
python -m server            # или ./run.sh, на Windows — run.bat
```

Откройте http://127.0.0.1:8765. Данные (база SQLite и загруженные файлы)
лежат в `odo-app/data/` — резервная копия = копия этой папки. Она в `.gitignore`:
договоры реальных компаний в репозиторий не попадают.

Необязательно:

| Переменная | Что делает |
|---|---|
| `ODO_PASSWORD` | Пароль на вход (HTTP Basic, любое имя). Обязательно, если приложение открыто в сети. |
| `ANTHROPIC_API_KEY` | Включает ИИ‑разбор договоров произвольной формы (модель `ODO_LLM_MODEL`, по умолчанию `claude-sonnet-5`). Без ключа контракты по 44‑ФЗ разбираются правилами, остальное дозаполняется в форме. |
| `ODO_HOST`, `ODO_PORT` | Адрес и порт (по умолчанию 127.0.0.1:8765). Для доступа с других компьютеров — `ODO_HOST=0.0.0.0` и пароль. |
| `ODO_DATA_DIR` | Куда класть базу и файлы. |
| `ODO_ENGINE_DIR` | Где лежит движок, если репозиторий разложен иначе. |
| `ODO_REPORTS_DIR` | Папка для заключений, ответов и реестров. В .exe — «ОДО‑отчёты» рядом с программой. |
| `ODO_CASES_DIR` | Куда писать прецеденты. По умолчанию — в базу скилла (`.claude/skills/sro-odo/cases`), общую с Claude Code; их можно коммитить: записи анонимны. |

Сканы без текстового слоя распознаются, если установлен `tesseract` с русским
языком (`apt install tesseract-ocr tesseract-ocr-rus`). Иначе данные из скана
вносятся в форму руками — приложение об этом предупредит.

Docker (из корня репозитория): `docker build -f odo-app/Dockerfile -t odo .`
и `docker run -p 8765:8765 -v odo-data:/data -e ODO_PASSWORD=… odo`.

## Как работать

1. **Компании** — добавьте члена СРО (название, ИНН, при желании уровень по ОДО из реестра СРО, он показывается справочно).
2. **Загрузить договор** — выберите сразу все файлы: договор (docx/pdf), сметы (объектный и сводный расчёты), акты КС‑2/КС‑3, дополнительные соглашения. Тип каждого файла определится по содержимому.
3. **Карточка** — всё, что прочитано из документов, уже заполнено, с подсказкой «откуда». Жёлтые поля программа установить не смогла — заполните. Нажмите «Рассчитать».
4. **Заключение** — вывод крупно, три причины, разбор по шести шагам с нормами, виды работ по Перечню 624, похожие прецеденты. Скачивается в .docx/.md/.json.
5. **Решение** — «Согласен с расчётом» или «Решить иначе» с объяснением. Решение уходит в базу прецедентов без имён и номеров; следующий похожий договор получит на него ссылку. Расхождения с расчётом видны на странице «Прецеденты» как заготовки правил.
6. **Папка отчётов** — каждое заключение само сохраняется в Word в папку «ОДО‑отчёты» рядом с программой
   (при запуске из исходников — `data/отчёты`), по папке на компанию, с именем вида
   «ООО КИТ — договор 0145… — заключение — 2026‑09‑24.docx». Туда же ложатся ответы на письма и реестры
   в Excel. Кнопка «Открыть папку» есть на странице договора, компании и в настройках.
7. **Реестр компании** — таблица договоров, итог «в совокупный размер», выгрузка в Excel и печатный отчёт. Предупреждения: дробление (несколько договоров одного заказчика ниже порога за 90 дней), просроченные уведомления в СРО (3 рабочих дня, ч. 4 ст. 55.8).
8. **Письмо‑возражение** — вставьте текст или файл; программа найдёт доводы по каталогу из 15 типов, вы проверите типы, получите разбор каждого довода с нормами и проект ответа (.docx). Срок на возражения по положению СРО — 15 календарных дней — подставляется в ответ.

Правила практики (только конкурентные договоры, порог 10 млн, добровольный тендер = прямой договор и т. д.) — в `../.claude/skills/sro-odo/scripts/data/policy.json`; страница «Настройки» их показывает и умеет прогнать тесты движка.

## Что где

```
odo-app/
  server/main.py           маршруты и страницы (FastAPI)
  server/parse_contract.py черновик карточки правилами: номер, ИКЗ, цена, стороны, торги, сметы, акты, ДС
  server/extract.py        текст из docx / pdf / xlsx, OCR при наличии tesseract
  server/llm.py            необязательный ИИ‑разбор (Anthropic API), числа всё равно от правил
  server/engine.py         вызовы движка: assess, objection, cases, law.json, policy.json
  server/letters.py        поиск доводов в письме по ключевым словам
  server/export.py         .docx из markdown, реестр .xlsx
  server/db.py             SQLite: компании, договоры, файлы, письма, журнал
  server/templates, static страницы (Jinja2), стили, три строки JS
  tests/                   вымышленные договор, сметы, письмо; сквозной тест через HTTP
```

Тесты: `python -m pytest tests`. Вымышленные компании в `tests/fixtures/` — единственные данные, которые хранятся в репозитории.

## Что расчёт делает и чего не делает

- Считает детерминированно: одинаковые данные — одинаковый вывод; каждая норма — из реестра `law.json` с отметкой, чем сверена.
- Не выносит вердикт «уровень превышен»: показывает сумму и, справочно, уровень из реестра СРО. Решение — за проверяющим.
- Не читает ЕИС и правовые базы из сети: начальную цену закупки и статус заказчика подтверждает человек (в карточке есть ссылка на закупку в ЕИС по номеру).
- Не хранит решения с именами: прецеденты анонимны.

## Настольная версия (.exe для Windows)

Собирается автоматически на Windows‑машине GitHub (`.github/workflows/build-odo-app.yml`)
при каждом изменении `odo-app/` или движка и лежит в разделе **Releases** репозитория
под тегом `odo-app-latest`:

- `ODO-proverka.exe` — один файл, двойной щелчок. Первый запуск несколько секунд.
- `ODO-proverka-folder.zip` — то же папкой, запускается быстрее.

Внутри: сервер приложения, движок скилла и окно со встроенным браузером Windows
(WebView2). Если WebView2 на компьютере нет, откроется обычный браузер и маленькое
окно состояния. Данные — в папке «ОДО‑данные» рядом с .exe (если туда нельзя писать —
в `%LOCALAPPDATA%\ODO-proverka`). Прецеденты хранятся там же, в `cases/`: при первом
запуске копируются из сборки.

Локальная сборка на Windows: `pip install pyinstaller pywebview` и из корня репозитория
`pyinstaller --clean odo-app/desktop/odo.spec` — результат в `dist/`.
Проверка без окна: переменная `ODO_SMOKE=1` — .exe поднимает сервер, пишет `smoke.ok`
в папку данных и выходит.

# Разбор писем-возражений

Компания пишет в СРО: «этот договор учитывать не надо, потому что …».
Скилл раскладывает письмо на доводы, каждому подбирает тип из каталога
`scripts/data/objections.json`, применяет юридический тест к фактам и
выдаёт статус с нормами. Из статусов собирается проект ответа.

## Пятнадцать типовых доводов

| Тип | Довод | Когда обоснован |
|---|---|---|
| `not_podryad` | это поставка / услуги / аренда | когда результата работ нет; смешанный договор делится по частям |
| `not_capital_object` | объект некапитальный, разрешение не требуется | некапитальный объект, ИЖС и приравненные, текущий ремонт; **не** капремонт ОКС |
| `customer_not_developer` | мы субподрядчик | заказчик — генподрядчик или иное лицо; **не** застройщик, техзаказчик, эксплуатант, региональный оператор |
| `below_threshold` | сумма ниже 10 млн (1 млн для сноса) | с учётом всех ДС; для ПИР порога нет; дробление — обход |
| `not_competitive` | договор без торгов | по букве ч. 3 ст. 55.8 — да; после 309-ФЗ — по положению СРО; без позиции СРО — «частично» |
| `executed` | договор исполнен | есть итоговый акт; частично — уменьшает остаток |
| `terminated` | договор расторгнут | есть документ о расторжении |
| `works_not_in_list` | работы не влияют на безопасность | весь предмет вне Перечня и не капремонт; для разделения цены — строки вне Перечня и «*» на обычном объекте |
| `state_exempt` | заказчик/подрядчик — учреждение, ГУП, МУП | только если под ч. 2.2 ст. 52 подпадает **подрядчик** |
| `individual_housing` | ИЖС, садовый дом, вспомогательная постройка | подтверждён вид объекта |
| `design_threshold` | проект дешевле 10 млн | никогда: порога для ПИР нет |
| `technical_customer_is_intermediary` | техзаказчик — посредник | никогда: техзаказчик назван в законе рядом с застройщиком |
| `before_2026` | договор старый | полностью исполнен до 01.03.2026 |
| `price_includes_supply` | в цене оборудование | выделенная в договоре самостоятельная поставка; материалы подрядчика — нет |
| `not_member_at_signing` | не были членом при подписании | никогда: считается по действующим договорам |

Нетиповой довод — `type: "other"`, статус «решает человек».

## Что заполняет Claude

`schemas/objection.schema.json`: реквизиты письма, краткая суть и список
доводов. У довода — `quote` (дословно), `type`, `facts` — только то, что
подтверждено документами (приложениями к письму или карточкой договора).
Факты карточки подставляются сами; факты претензии их перекрывают.

## Статусы

`founded` — довод принимается, договор исключается или остаток уменьшается;
`partially` — принимается в части (смешанный договор, частичное
исполнение, разделение цены); `unfounded` — отклоняется; `needs_facts` —
просим документы (список в `missing`); `needs_human` — нетиповой.

Итог по письму: если хотя бы один довод `founded` и остальные решены —
«обоснованы»; если есть `needs_facts`/`needs_human` — «требуют документов»;
если только `partially` и `unfounded` — «частично обоснованы»; иначе
«не обоснованы».

## Проект ответа

Строится из статусов: по каждому доводу — принимается / частично /
не может быть принят / нужны документы, объяснение и нормы. Это черновик
для юриста СРО: тон, реквизиты и подпись — человек. Перед отправкой
сверить формулировки норм с действующей редакцией (сеть среды закрыта,
нормы в `law.json` не сверены с официальным текстом).

## Команды

```bash
python3 scripts/objection.py objection.json --card card.json --assessment assessment.json -o objection.json --md otvet.md
python3 scripts/cases.py add --from-objection objection.json --decision "…" --note "…"
```

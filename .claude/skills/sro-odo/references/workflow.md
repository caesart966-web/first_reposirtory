# Рабочий процесс

Восемь шагов, три точки участия человека. Все команды — из каталога скилла.

## 1. Приём документов

- Собрать список файлов, снять md5, отбросить дубли.
- Сканы отрендерить постранично и прочитать; электронные PDF — текстом.
- Составить опись: файл → вид документа → договор → период → итог.
  Опись показать пользователю до заполнения реестра: на этом шаге
  всплывают дубли, чужие документы и пропуски (нет КС-2 за период,
  за который есть КС-3).

## 2. Реестр

Заполнить `register.json` по `schemas/register.schema.json`
(правила чтения — `references/documents.md`):

- `subject` — проверяемая компания и её СРО (уровни — из выписки);
- `objects` — объекты с категорией по ст. 48.1 (пока `unknown`);
- `contracts` — все договоры из документов, включая те, где компания —
  заказчик;
- `documents` — каждый файл;
- `line_items` — строки актов и смет; классификация пустая (`null`).

Идентификаторы: `obj_*`, `ctr_*`, `doc_*`, `li_*`. Суммы — как в документе,
без пересчётов.

## 3. Чекпоинт A — подтверждение человеком

Показать пользователю таблицу договоров и попросить подтвердить или
поправить:

1. роль компании в каждом договоре (подрядчик / заказчик);
2. статус каждого заказчика (застройщик, техзаказчик, эксплуатант,
   региональный оператор, генподрядчик, иное) и чем подтверждён;
3. способ заключения (конкурентный / прямой);
4. цену с учётом ДС и статус договора;
5. категорию каждого объекта (обычный / ст. 48.1) и чем подтверждена.

Без ответа расчёт идёт с `unknown` и соответствующими пометками —
это допустимо для черновика, но не для отчёта проверяющему.

## 4. Валидация

    python3 scripts/validate.py register.json

Схема, ссылки между сущностями, сумма строк против итогов документов.
Расхождение суммы — либо пропущена строка, либо неверно снято число:
вернуться к документу.

## 5. Классификация строк

    python3 scripts/classify.py register.json

Скрипт печатает строки, ушедшие на проверку. Проверка одной строки:
`--text "…" --object ordinary`.

## 6. Чекпоинт B — спорные строки

По каждой строке `pending` Claude:

- смотрит расшифровку в документе и предмет договора;
- предлагает код Перечня (или «не в Перечне» / «не работы») с основанием;
- пишет решение в `classification` (`review_status: corrected` или
  `confirmed`, `human_note`) **после** подтверждения пользователем.

Если пользователь недоступен, строки остаются `pending`: их сумма в отчёте
выводится как «не решено», а не прибавляется ни к «СРО», ни к «не СРО».

## 7. Расчёт

    python3 scripts/odo.py register.json -o result.json --md summary.md

Сводка в Markdown печатается и записывается. Прочитать раздел
«На проверку человеку» и «Предупреждения»: выполнено больше цены,
договор без документов, объект без категории.

## 8. Отчёт и чекпоинт C

    python3 scripts/report.py result.json -o report.html --register register.json

Отчёт информационный (дисклеймер в шапке). Пользователю передаются три
файла: `register.json` (данные), `summary.md` (сводка), `report.html`
(отчёт). В сопроводительном письме (`templates/report.md`) — что не сверено
и какие решения приняты человеком.

Данные реальных компаний (цены, акты) в репозиторий не коммитятся;
в `examples/` — только вымышленный пример.

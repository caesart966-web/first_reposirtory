# Обязательства члена СРО (`/sro-odo`)

Скилл превращает пачку документов компании — договоры, сметы, КС-2, КС-3,
УПД, уведомления в СРО — в реестр, где каждая сумма разнесена на «СРО» и
«не СРО», и в отчёт проверяющему: сколько у компании обязательств по
договорам подряда на самом деле, отдельно по строительству, проектированию
и изысканиям.

## Что делает и чего не делает

**Делает:**
- извлекает из документов договоры (стороны, предмет, цена, ДС, способ
  заключения), объекты и построчные суммы актов и смет — каждую с ссылкой
  на документ и страницу;
- относит договор к виду СРО и решает, входит ли он в совокупный размер
  обязательств (подрядчик ли компания, подряд ли это, кто заказчик);
- относит каждую строку к виду работ Перечня 624 и выводит: СРО / не СРО /
  решает человек;
- считает цену, выполненное по актам и остаток, и долю СРО в каждом —
  по договорам и по видам СРО, в двух выборках (все подходящие договоры
  и только конкурентные);
- выдаёт реестр JSON, сводку Markdown и отчёт HTML с очередью спорных
  вопросов человеку.

**Не делает (см. `references/human-in-the-loop.md`):**
- не выносит вердикт «превышение»: уровень ответственности приводится
  справочно, сравнение с фактическим уровнем — по реестру СРО и решению
  человека;
- не назначает категорию объекта (ст. 48.1 ГрК РФ) и статус заказчика
  (застройщик, техзаказчик) сам — только по подтверждению;
- не переводит спорную строку в «СРО» без основания: сомнительное остаётся
  в «не решено» отдельной суммой;
- не додумывает цифры: скан не читается — `null` и пометка, а не догадка.

## Принципы

1. **Каждая сумма — из документа.** В реестре у строки есть `source`
   (документ, страница). Числа со сканов получают `extraction_confidence`
   не выше 0,8 и сверяются с итогами документа (`validate.py`).
2. **Классификация детерминирована.** `classify.py` применяет правила
   `scripts/data/rules.json` по Перечню 624; Claude заполняет реестр
   и разбирает строки, ушедшие на проверку, а не классифицирует «на глаз».
3. **Арифметика — скриптом.** `odo.py` считает суммы; вручную суммы не
   складываются и не переписываются.
4. **Два уровня, три вида.** Сначала договор (входит ли), потом строки
   (что внутри); строительство, проектирование и изыскания — отдельно.
5. **Отсутствие факта дешевле факта, за который нельзя ответить.**

## Рабочий процесс

Подробно — `references/workflow.md`. Кратко:

1. **Приём документов.** Сканы рендерятся постранично (`pymupdf`), читаются
   как изображения; электронные PDF — текстом. Одинаковые файлы (md5)
   отбрасываются, КС-3 и счета-фактуры — дубли КС-2 за тот же период.
2. **Реестр.** Заполняется `register.json` по `schemas/register.schema.json`:
   компания, объекты, договоры, документы, строки. Правила чтения каждого
   вида документа — `references/documents.md`.
3. **Чекпоинт A (человек):** роль компании в каждом договоре, статус
   заказчика, способ заключения, категория объекта по ст. 48.1, цена с ДС.
4. `python3 scripts/validate.py register.json` — схема, ссылки, суммы.
5. `python3 scripts/classify.py register.json` — разметка строк.
6. **Чекпоинт B (человек):** строки `review_status: pending`. Claude
   предлагает решение с основанием, человек подтверждает; решения пишутся
   в `classification` (`corrected`/`confirmed`, `human_note`).
7. `python3 scripts/odo.py register.json -o result.json --md summary.md` —
   расчёт и сводка.
8. `python3 scripts/report.py result.json -o report.html --register register.json` —
   отчёт проверяющему.
9. **Чекпоинт C:** отчёт помечен как информационный; выводы о соответствии
   уровню делает человек по выписке из реестра СРО.

## Быстрая проверка

```bash
cd .claude/skills/sro-odo
python3 scripts/test_rules.py                       # правила: все случаи сходятся
python3 scripts/validate.py examples/demo/register.json
python3 scripts/classify.py examples/demo/register.json
python3 scripts/odo.py examples/demo/register.json -o /tmp/r.json --md /tmp/s.md
python3 scripts/report.py /tmp/r.json -o /tmp/report.html --register examples/demo/register.json
python3 scripts/classify.py --text "Устройство кровли из рулонных материалов" --object ordinary
```

Зависимости: Python 3.10+, стандартная библиотека; `jsonschema` — для
полной валидации (без него проверяются только обязательные поля);
`pymupdf` — чтобы рендерить сканы (сам скилл его не импортирует).

## Ограничения, о которых надо сказать пользователю

- Перечень 624 воспроизведён по консолидированной редакции без сверки с
  официальным текстом (сеть среды закрыта); 52 позиции со звёздочкой
  сверены с разбором заказчика. Флаг `verified_against_official_text`.
- После 309-ФЗ не снято, привязан ли совокупный размер по ОДО только
  к конкурентным договорам; отчёт даёт обе выборки.
- Разделение цены на «СРО/не СРО» — по Перечню 624 как классификатору;
  закон оперирует ценой договора целиком. Оба числа в отчёте рядом.

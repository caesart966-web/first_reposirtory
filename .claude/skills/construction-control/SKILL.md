# ИИ-ассистент строительного контроля (`/construction-control`)

Оркестратор строительного контроля по документам и видеообходам. Превращает
договор, смету, график, планы, техкарты и видео обхода объекта в структурированные,
доказательные выводы об отклонениях, дефектах и рисках — и в недельный отчёт.

## Что этот skill делает и чего НЕ делает

**Делает:** извлекает структуру проекта из документов, оценивает фактическую
готовность работ по кадрам видео, считает отклонения от графика обычной
арифметикой, выявляет дефекты и риски, ранжирует проблемы, предлагает
корректирующие мероприятия, формирует недельный отчёт — всё в виде строгого JSON
с ссылками на кадры и пункты документов.

**НЕ делает (жёсткие ограничения — см. `references/human-in-the-loop.md`):**
- не подписывает и не формирует акты приёмки (КС-2/КС-3, АОСР);
- не подтверждает скрытые работы по видео;
- не принимает работы окончательно;
- не выдаёт категоричных выводов без достаточных доказательств;
- любой критический вывод и всё, что влечёт юридические/финансовые последствия,
  помечает `requires_human_review: true` и уходит человеку.

## Базовые принципы (соблюдать всегда)

1. **Доказательность.** Ни одно наблюдение о факте не публикуется без ссылки на
   `EvidenceFrame` (кадр). Ни одна ссылка на пункт договора/сметы/графика не
   «додумывается»: нет данных — ставь `null` и снижай `confidence`.
2. **Строгий JSON.** Каждый агент возвращает только JSON по своей схеме из
   `schemas/`. Свободный текст — лишь внутри строковых полей (`evidence_description`,
   `executive_summary`). Перед сохранением валидируй по схеме
   (`scripts/validate.py`).
3. **Разделяй факт и вывод.** Visual Progress фиксирует наблюдаемое; Schedule/Quality
   интерпретируют; Chief синтезирует. Наблюдение ≠ приёмка. «Визуально завершено» ≠
   «принято».
4. **Уверенность обязательна.** Везде `confidence` (0..1) и `confidence_level`
   (low/medium/high). Низкая уверенность → на человека, не в отчёт как факт.
5. **Human-in-the-loop.** Правки пользователя сохраняются (`review_status`,
   корректирующие значения) и используются для оценки качества системы.

## Пять агентов

Каждый агент запускается как отдельный субагент (Agent tool) со своим системным
промптом, своим набором MCP-инструментов и своей выходной схемой. Подробные
промпты и правила — в `references/agents.md`.

| Агент | Роль | Выходная схема |
|---|---|---|
| **Document Extraction** | Разбирает договор/смету/график/доки, извлекает обязательства, объёмы, сроки, связи между документами | `schemas/document-extraction.output.schema.json` |
| **Visual Progress** | По кадрам определяет помещение, работы, статус, % готовности, уверенность, кадры-доказательства | `schemas/visual-progress.output.schema.json` |
| **Schedule Control** | Сравнивает план/факт, считает отклонение, просрочку, последовательность, прогноз | `schemas/schedule-control.output.schema.json` |
| **Quality Control** | Проверяет визуальные требования, отделяет подтверждённый дефект от подозрения, список инструментальных проверок | `schemas/quality-control.output.schema.json` |
| **Chief Construction** | Объединяет всё, ранжирует, недельный отчёт, спорное — на человека | `schemas/weekly-report.output.schema.json` |

Порядок вызова по умолчанию: **Document Extraction → (проверка человеком) →
Visual Progress → Schedule Control ∥ Quality Control → Chief Construction**.
Schedule и Quality независимы и запускаются параллельно.

## Рабочий процесс (13 шагов)

Полное описание — `references/workflow.md`. Кратко:

1. Первичная загрузка документов (`get_project_documents`).
2. Извлечение структуры проекта (Document Extraction Agent).
3. **Проверка пользователем извлечённых данных** (HITL-чекпоинт).
4. Привязка сметы и графика к помещениям (ручная в MVP).
5. Загрузка видеообхода (`Inspection` + видеофайлы).
6. Разбиение видео на помещения и эпизоды (`VideoSegment`) — см. `references/video-pipeline.md`.
7. Анализ ключевых кадров (Visual Progress Agent).
8. Сравнение с предыдущим обходом (дельта готовности).
9. Сравнение с графиком и сметой (Schedule Control Agent).
10. Выявление отклонений и дефектов (Schedule + Quality → `Issue[]`).
11. Формирование рекомендаций (`CorrectiveAction[]`).
12. **Проверка человеком** критических/спорных выводов (HITL-чекпоинт).
13. Выпуск недельного отчёта (Chief Construction Agent).

Между шагами 3 и 4, а также перед 13, — обязательные точки участия человека.

## Как запускать (оркестрация)

При активации skill определи, на каком шаге находится проект (какие данные уже
есть в БД проекта через `get_*`-инструменты), и выполни недостающие шаги.

- **Только документы загружены** → запусти Document Extraction Agent, сохрани
  сущности, покажи пользователю сводку и попроси подтвердить/поправить (шаг 3).
- **Структура подтверждена, есть видео** → построй сегменты
  (`references/video-pipeline.md`), запусти Visual Progress Agent, сохрани
  `ProgressObservation` через `save_progress_observation`.
- **Есть наблюдения** → параллельно Schedule Control и Quality Control; их `Issue[]`
  сохрани через `create_issue`.
- **Есть issues за неделю** → Chief Construction Agent → `generate_weekly_report`;
  всё критическое/спорное → `request_human_review`.

Каждый субагент получает: (а) ссылку на нужные MCP-инструменты, (б) свою выходную
схему, (в) требование «верни ТОЛЬКО валидный JSON по схеме, без пояснений».

## Инструменты (MCP)

Полные сигнатуры — `references/mcp-tools.md`. Набор:
`get_project_documents`, `search_contract`, `get_estimate_items`,
`get_schedule_tasks`, `get_floor_plan`, `get_video_segments`,
`get_evidence_frames`, `save_progress_observation`, `create_issue`,
`update_issue`, `generate_weekly_report`, `request_human_review`.
Плюс низкоуровневые тул-функции: чтение PDF/DOCX/XLSX, извлечение кадров, ASR,
векторный поиск по документам и видеоархиву, сравнение версий документов,
создание задач в системе управления проектами, отправка уведомлений.

## Модель данных и схемы

- Модель данных и связи — `references/data-model.md`.
- Все JSON Schema — каталог `schemas/` (ядро — `entities.schema.json`,
  центральный объект проблемы — `issue.schema.json`).
- Каждая выявленная проблема возвращается как **`Issue`** с полным набором полей
  (объект, помещение, работа, подрядчик, ссылки на договор/смету/график, план/факт,
  отклонение, дни просрочки, критичность, уверенность, доказательства и кадры,
  причины, последствия, рекомендации, ответственный, срок, флаг проверки человеком).

## Логика расчётов и видео

- Разбиение видео, привязка к помещениям, отбор ключевых кадров —
  `references/video-pipeline.md`.
- Плановая готовность, отклонение, дни просрочки, прогноз, последовательность —
  `references/deviation-logic.md` (формулы + `scripts/deviation.py`).

## MVP без BIM

Реализация без BIM-модели: планы помещений + **ручная** привязка задач/сметы к
помещениям + ключевые кадры. Никакого обучения своей нейросети на первом этапе —
только готовые мультимодальные модели, OCR, ASR, векторный поиск и обычные
программные расчёты. Границы MVP, критерии приёмки, тест-сценарии — 
`references/mvp.md`, `references/acceptance-and-testing.md`.

## Риски

Технические и юридические ограничения (галлюцинации мультимодальной модели,
слепые зоны съёмки, юридический статус выводов, персональные данные на видео) —
`references/risks.md`. Читать перед продакшн-внедрением.

# Архитектура решения

## Обзор

Система — многоагентный оркестратор поверх готовых мультимодальных моделей и
классических программных расчётов. Никакого обучения собственных нейросетей на
первом этапе.

## Слои

1. **Слой представления** — интерфейс загрузки, просмотра кадров с наложенными
   выводами, очередь подтверждения (human-in-the-loop), недельные отчёты.
2. **Слой оркестрации (этот skill)** — управляет последовательностью агентов,
   состоянием проекта, точками участия человека. Здесь живут промпты агентов и
   правила «когда что запускать».
3. **Слой агентов** — пять специализированных субагентов, каждый со строгой
   выходной JSON-схемой.
4. **Слой инструментов (MCP)** — единственный способ агентов трогать данные:
   чтение документов, кадров, запись наблюдений и проблем, отчёты, уведомления.
5. **Слой данных** — три хранилища за единым API:
   - **реляционное** — сущности модели данных (Project…CorrectiveAction, Issue);
   - **объектное** — видеофайлы, кадры, миниатюры;
   - **векторное** — эмбеддинги текста документов и расшифровок/подписей кадров
     для семантического поиска (`search_contract`, поиск по видеоархиву).
6. **Внешние готовые модели** — мультимодальная LLM для анализа кадров и текста,
   OCR, ASR, эмбеддинги. Вызываются как сервисы, не дообучаются.

## Потоки данных (высокоуровнево)

- **Документы → структура.** PDF/DOCX/XLSX → парсеры/OCR → Document Extraction
  Agent → сущности (`ContractObligation`, `EstimateItem`, `ScheduleTask`, `Room`…)
  → БД. Пользователь проверяет.
- **Видео → наблюдения.** Видео → извлечение кадров + ASR → сегментация по
  помещениям → Visual Progress Agent → `ProgressObservation` (+ кадры) → БД.
- **Факт vs план → проблемы.** Наблюдения + график/смета → Schedule Control и
  Quality Control → `Issue[]`, `Defect[]`, `Risk[]` → БД.
- **Проблемы → отчёт.** Chief Construction Agent → недельный отчёт + очередь на
  подтверждение → пользователь → задачи в системе управления проектами +
  уведомления.

## Принципы проектирования

- **Инструменты, а не свобода.** Агенты не имеют прямого доступа к файловой
  системе или БД — только через MCP. Это даёт аудируемость и контроль прав.
- **Трассируемость сквозная.** Любой вывод → `Issue` → кадры + пункты документов.
  Всегда можно «дойти до пикселя и до строки договора».
- **Идемпотентность обходов.** Каждый `Inspection` самодостаточен; сравнение с
  прошлым — отдельный шаг, не мутирует историю.
- **Деградация, а не отказ.** Плохое качество кадра/слепая зона → `coverage_gap`
  и снижение confidence, а не молчаливый пропуск.
- **Человек — арбитр.** Система советует и обосновывает; юридически значимые
  действия остаются за специалистом.

# Логика обработки видео

Цель: превратить сырой обход (обычная или 360°-камера) в набор `VideoSegment` с
привязкой к помещениям и в `EvidenceFrame` — ключевые кадры-доказательства.
Всё на готовых сервисах, без обучения своих моделей.

## Пайплайн

```
video → [1 нормализация] → [2 ASR] → [3 извлечение кадров] → [4 сегментация по
помещениям] → [5 отбор ключевых кадров] → [6 распознавание+OCR] → VideoSegment[] +
EvidenceFrame[] → Visual Progress Agent
```

### 1. Нормализация

- Привести к постоянному fps-семплированию для анализа; сохранить исходник в
  объектном хранилище.
- **360°:** развернуть в несколько перспективных проекций (например, 4–6 «окон»
  по азимуту) через equirectangular→perspective. Каждая проекция обрабатывается как
  обычный кадр; в `EvidenceFrame` сохраняется угол обзора.
- Снять таймкоды/при наличии — GPS/шаги (не обязательно в MVP).

### 2. Распознавание речи (ASR)

- `transcribe_audio(language: "ru")` → сегменты с таймкодами.
- Речь оператора — главный источник привязки к помещению («заходим в 305»,
  «санузел на третьем») и контекста работ. Пишется в `VideoSegment.transcript`.

### 3. Извлечение кадров

- `extract_frames` с двумя стратегиями одновременно:
  - равномерно (например, 1 кадр/сек) — базовое покрытие;
  - по сменам сцены (scene-change) — границы помещений/ракурсов.
- Каждому кадру — `quality_flags` (blurry/dark/overexposed/occluded/motion/ok).
  Плохие кадры не выбрасываются, но не могут быть единственным доказательством.

### 4. Сегментация по помещениям (ключевой шаг MVP)

Задача: разрезать поток на `VideoSegment`, каждый = одно помещение/зона.
Приоритет сигналов привязки (`room_assignment_method`):

1. **OCR таблички/маркировки** на кадре (`run_ocr`) → номер помещения на плане.
   Самый надёжный сигнал.
2. **Речь оператора** (ASR): упоминание номера/названия помещения.
3. **Визуальное сопоставление** с планом этажа (`get_floor_plan`): по геометрии/
   характерным признакам — эвристика, невысокий confidence.
4. **Ручная привязка** оператором в интерфейсе (fallback).

Границы сегмента определяются сменой сигнала помещения + scene-change. Если
помещение не определено ни одним способом — сегмент помечается и уходит в
`unassigned_segments` (ручная привязка), НЕ угадывается.

> В MVP допустима и полу-ручная схема: оператор при съёмке называет помещения
> вслух и/или снимает таблички — тогда сегментация почти автоматическая.

### 5. Отбор ключевых кадров (EvidenceFrame)

Из каждого сегмента отобрать немного (например, 3–8) информативных кадров:
- максимально резкие (`quality_flags = ok`), покрывающие разные ракурсы;
- показывающие целевые работы/узлы (стены, пол, потолок, инженерные разводки);
- дедупликация похожих кадров (перцептивный хэш/эмбеддинги), чтобы не дублировать.
Только эти кадры идут в анализ и становятся доказательствами в `Issue`.

### 6. Распознавание и OCR на кадрах

- `analyze_frames(prompt, schema)` — мультимодальная LLM: `detected_labels`
  (какие работы/конструкции видны), первичная оценка статуса/готовности.
- `run_ocr` — тексты на кадре (таблички, маркировка кабелей, штампы) → `ocr_text`.
- Результаты кладутся в `EvidenceFrame`; интерпретацию делает Visual Progress Agent.

## Сравнение с предыдущим обходом (шаг 8)

- Для каждой пары (room_id, work_name) сопоставить наблюдение текущего и прошлого
  обхода (`previous_inspection_id`).
- `delta_from_previous_percent = actual_now − actual_prev`.
- Флаги: **регресс** (стало меньше — возможна ошибка распознавания или демонтаж →
  на человека), **стагнация** (0 прироста при плановом продвижении → риск),
  **скачок** (резкий рост при плохом покрытии прошлого обхода → проверить).
- `search_video_archive` помогает найти прошлые кадры того же ракурса/узла.

## Обработка ограничений съёмки

- **Слепые зоны:** ожидаемые по плану помещения без сегментов →
  `coverage.rooms_missing` → `Issue(issue_kind = coverage_gap)`, снижение KPI
  покрытия. Молчаливого пропуска быть не должно.
- **Плохое качество:** если все кадры сегмента плохие — статус фиксируется с низким
  `confidence` и пометкой «нужен повторный съём».
- **Приватность:** лица людей на кадрах размываются на этапе нормализации
  (см. `risks.md`), в доказательства идут кадры работ, не людей.

## Производительность (ориентир MVP)

- Сначала лёгкие сигналы (ASR + OCR табличек) для сегментации, затем дорогая
  мультимодальная модель — только по отобранным ключевым кадрам (десятки, не тысячи).
- Кэш эмбеддингов кадров для `search_video_archive` и дедупликации.

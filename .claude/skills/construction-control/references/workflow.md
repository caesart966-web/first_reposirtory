# Рабочий процесс (13 шагов)

Оркестратор определяет текущий шаг по состоянию БД проекта и выполняет недостающее.
`🧑 = обязательная точка участия человека`.

| # | Шаг | Кто | Вход → Выход | Инструменты |
|---|---|---|---|---|
| 1 | Первичная загрузка документов | пользователь | файлы → документы в БД | `get_project_documents`, `read_pdf/docx/xlsx` |
| 2 | Извлечение структуры проекта | Document Extraction Agent | документы → `Project…ScheduleTask`, `cross_links` | `search_contract`, `read_schedule` |
| 3 🧑 | **Проверка извлечённых данных** | пользователь | сущности → подтверждённые/исправленные | `update_issue`, журнал правок |
| 4 | Привязка сметы и графика к помещениям | пользователь + система | ручная привязка `room_ids` | `get_floor_plan`, `db_upsert` |
| 5 | Загрузка видеообхода | пользователь | видео → `Inspection` + видеофайлы | объектное хранилище |
| 6 | Разбиение видео на помещения/эпизоды | видео-пайплайн | видео → `VideoSegment[]` | `extract_frames`, `transcribe_audio`, `run_ocr` |
| 7 | Анализ ключевых кадров | Visual Progress Agent | кадры → `ProgressObservation[]` | `get_evidence_frames`, `analyze_frames`, `save_progress_observation` |
| 8 | Сравнение с предыдущим обходом | Visual Progress / система | наблюдения → дельты, флаги регресса | `search_video_archive` |
| 9 | Сравнение с графиком и сметой | Schedule Control Agent | наблюдения + график → отклонения | `get_schedule_tasks`, `deviation.py` |
| 10 | Выявление отклонений и дефектов | Schedule ∥ Quality | → `Issue[]`, `Defect[]`, `Risk[]` | `create_issue` |
| 11 | Формирование рекомендаций | Chief / агенты | проблемы → `CorrectiveAction[]` | `create_pm_task` (по решению) |
| 12 🧑 | **Проверка человеком** | пользователь | `human_review_queue` → решения | `request_human_review`, `update_issue` |
| 13 | Выпуск недельного отчёта | Chief Construction Agent | всё за период → отчёт | `generate_weekly_report`, `send_notification` |

## Детализация ключевых шагов

**Шаг 2 — извлечение.** Document Extraction Agent разбирает договор (обязательства,
приёмка, штрафы), смету (виды/ед./объёмы), график (сроки, зависимости,
ответственные), планы (`Room`). Формирует `cross_links` между документами. Всё с
`source`. Спорное → `extraction_gaps(needs_human)`.

**Шаг 3 🧑 — проверка.** Система показывает сводку: N обязательств, M позиций сметы,
K задач графика, структуру этажей/помещений, и список `extraction_gaps`.
Пользователь подтверждает или правит. Это фундамент всех дальнейших сравнений —
без него дальше не идём.

**Шаг 4 — привязка (ручная в MVP).** На плане этажа пользователь (с подсказками
системы по названиям работ) сопоставляет позиции сметы и задачи графика помещениям:
заполняются `EstimateItem.room_ids`, `ScheduleTask.room_ids`. Система предлагает
привязку по совпадению названий/кодов, человек подтверждает.

**Шаги 5–8 — видео → наблюдения.** См. `video-pipeline.md`. На выходе — `Inspection`
с `ProgressObservation[]`, дельтами к прошлому обходу и картой покрытия.

**Шаги 9–11 — факт vs план → проблемы.** Schedule Control считает отклонения
(`deviation-logic.md`), Quality Control проверяет качество. Оба формируют `Issue`.
Chief добавляет `CorrectiveAction`.

**Шаг 12 🧑 — проверка.** Все критические/спорные `Issue` — специалисту
(подтвердить/отклонить/исправить). Правки сохраняются.

**Шаг 13 — отчёт.** Chief Construction Agent собирает недельный отчёт (KPI,
ранжированные проблемы, риски, рекомендации, очередь на подтверждение,
`disclaimer`). По решению пользователя — задачи в PM-систему и уведомления.

## Состояние и повторные обходы

- Каждую неделю повторяются шаги 5–13; шаги 1–4 — по мере изменения документов
  (новое доп. соглашение, обновлённый график → `diff_documents` покажет изменения).
- Проект хранит историю обходов; отчёты сравнимы неделя к неделе (тренды KPI).

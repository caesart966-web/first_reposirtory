# Contact Finder — массовый поиск контактов юрлиц РФ по открытым источникам

Приложение принимает список компаний (ИНН, ОГРН, название, домен сайта) и
собирает по каждой максимально полный набор **проверенных** контактов с
указанием источника и оценкой достоверности (0–100). Работает только с
общедоступными данными, соблюдает robots.txt и rate-limit источников,
не использует капча-солверы и обход антибот-защит.

## Возможности

- Вход: XLSX / CSV / TXT (список ИНН построчно), автоопределение колонок
  (ИНН, ОГРН, наименование, сайт, регион), валидация ИНН/ОГРН по контрольным
  суммам, брак — в `errors.xlsx` с причиной, дедупликация по ИНН.
- Источники (по приоритету, каждый — отдельный модуль-коннектор):
  - **Уровень A** — ФНС/ЕГРЮЛ (реквизиты, статус, руководитель), ЕИС Госзакупки
    (карточки организаций с e-mail/телефонами), реестры СРО НОСТРОЙ/НОПРИЗ;
  - **Уровень B** — сайт компании: /contacts, /kontakty, /about, футер, JSON-LD
    schema.org, обфусцированные почты («at», «[собака]»), tel:-ссылки, соцсети;
  - **Уровень C** — 2ГИС, Яндекс.Карты, Dadata (официальные API по ключам из `.env`);
  - **Уровень D** — подбор домена через официальные search API (Google PSE /
    Яндекс Search API) + WHOIS-сопоставление; домен засчитывается как
    подтверждённый только после нахождения ИНН/названия на самом сайте.
- Асинхронный сбор (asyncio + aiohttp), лимит 5 запросов/сек на домен,
  таймауты connect 10 с / read 30 с, backoff 2-4-8-16-32 с (до 5 попыток).
- SQLite: кэш ответов с TTL 30 дней, все промежуточные результаты пишутся
  сразу — остановка в любой момент не теряет данные, повторный запуск
  продолжает с последней необработанной компании.
- Circuit breaker: источник со стабильными ошибками ставится на паузу на
  15 минут, прогон продолжается по остальным.
- Валидация: e-mail (RFC-синтаксис, реальная MX-проверка DNS, стоп-листы
  шаблонных адресов и почт веб-студий), телефоны (нормализация +7XXXXXXXXXX,
  тип мобильный/городской/8-800).
- Кросс-сверка: одинаковый контакт из разных источников объединяется,
  достоверность растёт. Веса скоринга — в `config.yaml`.
- Выход: XLSX с листами «Результат», «Найдено полностью», «Частично»,
  «Не найдено» и «Источники» (URL каждого контакта — для проверки).
- Интерфейсы: CLI (основной) и GUI на Tkinter (файл, галочки источников,
  прогресс-бар с ETA, пауза/продолжение).

## Установка под Windows (пошагово)

1. Установите Python 3.11+ с [python.org](https://www.python.org/downloads/)
   (при установке отметьте галочку **Add python.exe to PATH**).
2. Скачайте/распакуйте папку проекта, например в `C:\contact-finder`.
3. Откройте командную строку (Win+R → `cmd`) и выполните:

   ```bat
   cd C:\contact-finder
   python -m venv .venv
   .venv\Scripts\activate
   pip install -r requirements.txt
   ```

4. Создайте файл настроек ключей:

   ```bat
   copy .env.example .env
   notepad .env
   ```

   Заполните `CONTACT_EMAIL` (обязателен — подставляется в User-Agent) и ключи
   API, которые у вас есть. Источники без ключей автоматически отключаются и
   попадают в лист «Недоступные источники».
5. Положите список компаний в `companies.xlsx` (или .csv/.txt с ИНН построчно).
6. Запуск:

   ```bat
   python finder.py --input companies.xlsx --output result.xlsx --sources all --threads 10 --depth full
   ```

   Либо просто двойной клик по **`run.bat`** — он сам создаст окружение,
   поставит зависимости, запустит сбор и в конце откроет папку с результатом.

GUI: `python gui.py`.

## CLI

```
python finder.py --input companies.xlsx --output result.xlsx
                 [--errors-file errors.xlsx]
                 [--sources all | egrul,zakupki,website,...]
                 [--threads 10] [--depth full|first_email]
                 [--config config.yaml] [--db data/finder.db]
                 [--fresh] [--verbose]
```

- `--depth first_email` — прекращать опрос источников по компании после
  первого валидного e-mail; `full` — опросить всё.
- `--fresh` — пересобрать всё с нуля (HTTP-кэш при этом сохраняется).
- Повторный запуск той же команды продолжает прерванный прогон: компании со
  статусом `done` пропускаются, `retry_later` уходят в конец очереди.

## Конфигурация

`config.yaml` — источники и их приоритеты, лимиты, TTL кэша, стоп-листы
доменов и почт, веса скоринга. `.env` — только ключи API и пул прокси
(`HTTP_PROXY_POOL=http://user:pass@host:port,...` — прокси проверяются на
живость перед стартом; мёртвые отбрасываются).

## Скоринг достоверности (0–100)

| Правило | Вес |
| --- | --- |
| Источник уровня A (официальный реестр) | +40 |
| Контакт найден на домене, подтверждённом по ИНН | +30 |
| Контакт встретился в 2+ независимых источниках | +15 |
| Домен почты совпадает с сайтом компании | +10 |
| Источник уровня D без верификации | −20 |
| Компания в статусе «ликвидировано» | −30 |

## Тесты

```bat
pytest tests -q
```

Покрыто: контрольные суммы ИНН/ОГРН, валидация e-mail и деобфускация,
нормализация телефонов, парсер контактной страницы (на сохранённом HTML),
кросс-сверка и скоринг.

## Правовые ограничения — прочтите обязательно

- Приложение собирает **только общедоступные контакты юридических лиц**,
  опубликованные самими компаниями (на их сайтах) или в открытых
  государственных реестрах (ЕГРЮЛ, ЕИС, реестры СРО).
- **152-ФЗ «О персональных данных»**: не собирайте и не храните персональные
  данные физических лиц, не относящиеся к деловому контакту организации.
  Приложение сознательно не извлекает личные телефоны и адреса сотрудников —
  только официальные контакты юрлица и ФИО руководителя из открытого
  госреестра (ЕГРЮЛ), где они публикуются по закону.
- **38-ФЗ «О рекламе», ст. 18**: рассылка рекламы по e-mail и телефонам
  допускается **только с предварительного согласия адресата**. Массовая
  рассылка по собранной этим приложением базе без согласия получателей —
  **незаконна** и влечёт штрафы (КоАП РФ, ст. 14.3). Используйте данные для
  адресного делового обращения, а не для спама.
- Соблюдайте условия использования API-сервисов (Dadata, 2ГИС, Яндекс,
  Google) — тарифы и лимиты вашего ключа.
- Для проверяемости каждый контакт в выгрузке сопровождается листом
  «Источники» с URL, откуда он взят.

## Архитектура

```
contact-finder/
├── finder.py            # CLI-вход
├── gui.py               # GUI-вход (Tkinter)
├── config.yaml          # настройки (без секретов)
├── .env.example         # шаблон ключей API
├── run.bat              # запуск под Windows
├── core/
│   ├── models.py        # Company, Contact, MergedContact, ConnectorResult
│   ├── config.py        # config.yaml + .env
│   ├── orchestrator.py  # очередь, приоритеты, circuit breaker, resume
│   └── scoring.py       # кросс-сверка и скоринг 0–100
├── connectors/          # плагины источников (BaseConnector + реестр)
│   ├── base.py          # базовый класс, регистрация, помощники
│   ├── egrul_fns.py     # A: ФНС ЕГРЮЛ (+ зеркало открытых данных)
│   ├── zakupki.py       # A: ЕИС Госзакупки
│   ├── sro.py           # A: НОСТРОЙ / НОПРИЗ
│   ├── website.py       # B: обход сайта, JSON-LD, деобфускация
│   ├── dgis.py          # C: 2ГИС Catalog API
│   ├── yandex_maps.py   # C: Яндекс.Карты (поиск по организациям)
│   ├── dadata.py        # C: Dadata findById/party
│   ├── domain_search.py # D: Google PSE / Яндекс Search API
│   └── whois_check.py   # D: WHOIS-сопоставление (.ru/.su/.рф)
├── validators/          # ИНН/ОГРН, e-mail (RFC+MX), телефоны
├── storage/db.py        # SQLite: очередь, контакты, HTTP-кэш, состояние источников
├── utils/               # HTTP-клиент, robots, логи, чтение/запись файлов
├── ui/                  # cli.py, gui_app.py
└── tests/               # pytest + сохранённый HTML контактной страницы
```

Добавление нового источника: создать файл в `connectors/` с классом-наследником
`BaseConnector` под декоратором `@register_connector`, добавить импорт в
`connectors/__init__.py` и (по желанию) секцию в `config.yaml`. Ядро менять
не нужно.

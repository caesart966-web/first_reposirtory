# Рабочее состояние ручного пробива телефонов (СРО-410)

Файлы, чтобы продолжить работу с того же места в новой сессии —
ничего не потеряется при перезапуске контейнера.

| Файл | Что это |
|---|---|
| `nostroy.json` | Полная выгрузка реестра НОСТРОЙ (1590 записей) |
| `recheck.json` | Очередь на пробив: действующие члены СРО, ЮЛ вперёд, ИП в конец |
| `nostroy_results.json` | Накопленный результат: `{ИНН: {name, phone, extra, src, conf}}` |
| `next.py` | Печатает следующие N непроверенных из очереди |
| `save2.py` | Дописывает результаты в `nostroy_results.json` (JSON со stdin) |
| `build2.py` | Собирает итоговый `Телефоны_СРО410_НОСТРОЙ.xlsx` |

## Как продолжить

```bash
cd contact-finder/work
python3 next.py 12                 # взять следующие 12 компаний
# ... пробить каждую отдельным поиском, сверяя ИНН ...
python3 save2.py <<'JSON'
{"7810827401": {"name": "...", "phone": "+7 (812) ...", "extra": "...",
                "src": "...", "conf": "высокая (ИНН совпал)"}}
JSON
python3 build2.py                  # пересобрать xlsx
```

## Правило записи

Телефон попадает в результат, **только если в источнике совпал ИНН**.
Совпадения по названию недостаточно: в СПб десятки одноимённых ООО, и
подставленный номер однофамильца хуже, чем пустая ячейка. Когда номер
отбракован — это пишется в поле `extra`, чтобы повторно его не «находить».

Поле `conf` — что именно подтвердилось: «высокая (ИНН совпал)»,
«нет данных (проверено, нет в ЕГРЮЛ)», «нет данных (карточка не найдена)».

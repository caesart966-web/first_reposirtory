# email-parser — сбор почт компаний с их сайтов

Два скрипта. Ничего не выдумывают: в результат попадает только то, что реально
снято со страницы сайта.

```
stage0_discover.py   ИНН -> сайт компании  (нужен, потому что колонка «Сайт» пустая)
stage1_sites.py      сайт -> email         (основной парсер по ТЗ)
```

## Почему два этапа

Во входном файле `Компании (4).xlsx` — 9 742 строки, у 1 199 пустая почта.
Но колонка «Сайт» заполнена всего у 70 строк на весь файл, и 65 из них —
у компаний, где почта **и так есть**.

| Условие | Строк |
|---|---|
| email есть + сайт есть | 65 |
| email есть + сайта нет | 8 478 |
| **email НЕТ + сайт есть** | **5** ← вход stage1 без stage0 |
| email НЕТ + сайта нет | **1 194** ← им сначала нужен stage0 |

То есть stage1 сам по себе закрывает 5 строк. Остальным 1 194 сначала нужно
найти URL — этим занимается stage0.

## Установка

```
pip install requests openpyxl
python --version    # 3.8+
```

## Запуск

```bash
# 1. тест на малом объёме
python stage1_sites.py --limit 30

# 2. найти сайты тем, у кого их нет (сначала тоже на 30)
python stage0_discover.py --limit 30
python stage0_discover.py                    # все 1 194

# 3. основной прогон, включая найденные на шаге 2 сайты
python stage1_sites.py --extra-sites result/discovered_sites.csv
```

Всё кладётся в `result/`. По окончании папка открывается автоматически
(Windows; на Linux/Mac просто пропускается).

## stage1_sites.py

Берёт строки, где **email пустой И сайт заполнен**. По каждому сайту обходит
`/`, `/contacts`, `/contact`, `/kontakty`, `/about`, `/o-kompanii`.

Достаёт почты:
- из `mailto:` в html;
- регуляркой из текста страницы;
- обфусцированные: `info (at) domain.ru`, `info[собака]domain.ru`,
  `info @ domain.ru`, `zakaz (собака) domain (точка) ru`.

Технически:
- 15 потоков, `requests` + `concurrent.futures` (не asyncio);
- timeout 10 c, 2 ретрая (до 3 попыток), при неудаче https — повтор по http;
- User-Agent обычного Chrome;
- **кодировка**: charset из заголовка → `<meta charset>` → `apparent_encoding`.
  На дефолт requests не полагаемся, иначе windows-1251 превращается в кашу;
- **чекпоинт**: строка дописывается в `result/progress.csv` после каждой
  компании. Перезапуск подхватывает и пропускает обработанные;
- любая ошибка пишется в `result/errors.log` и не роняет прогон.

Фильтр мусора: адреса на `.png/.jpg/.jpeg/.svg/.webp/.gif/.ico/.css/.js`,
а также `example.com`, `noreply@`, `no-reply`, `sentry`, `wixpress`,
`cloudflare`, `@2x`, `domain.com`, `yourdomain`, `test@test` и подобное.

Несколько почт сохраняются через `;`. Первой ставится та, чей домен совпадает
с доменом сайта, затем `info@`, `mail@`, `office@`, затем остальные.

**Выход** `result/stage1_emails.xlsx`:
- лист **Результат** — Название, ИНН, Сайт, Найденные почты, Источник
  (mailto / текст / текст (обфускация) — и с какой страницы), Статус
  (найдено / почт нет / сайт не открылся), Комментарий;
- лист **Необработанные** — строки, которые не попали в работу, с причиной.

## stage0_discover.py

Ищет официальный сайт по ИНН и **проверяет принадлежность**: кандидат
принимается, только если сам ИНН найден на его страницах (`/`, `/contacts`,
`/kontakty`, `/about`, `/o-kompanii`, `/rekvizity`, `/requisites`).

Совпадение названия не засчитывается — одноимённых ООО в России десятки, и
именно так в подобные таблицы попадают чужие почты. Не подтверждено ИНН —
сайт не берётся, строка помечается `не подтверждён`.

Из выдачи выбрасываются агрегаторы и справочники (rusprofile, checko, list-org,
sbis, 2gis, вк и т. д.) — там ИНН найдётся всегда, но это не сайт компании.

Поиск: DuckDuckGo HTML без ключа, 4 потока, пауза 1,5 c между запросами.
Если начнёт блокировать — задайте переменную окружения `SERPAPI_KEY`, скрипт
сам переключится на SerpAPI. Прогресс в `result/discovered_sites.csv`,
перезапуск безопасен.

## Важно про сеть

Скрипты рассчитаны на запуск **на вашей машине**. В облачной среде, где они
писались, исходящие соединения к `.ru` режет сетевая политика: прогон на пяти
реальных компаниях дал пять `сайт не открылся` с `Max retries exceeded` в
`errors.log`. Это ограничение среды, а не скрипта — логика парсинга проверена
отдельно на офлайн-тестах (mailto, текст, три вида обфускации, windows-1251,
фильтр мусора, порядок почт).

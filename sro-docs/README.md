# sro-docs — заполнение документов на вступление в СРО

Локальная программа под Windows: карточка компании → проверенные реквизиты →
заявление и доверенность по утверждённым бланкам Ассоциации.

Настроены шесть СРО, у каждой заявление о вступлении и доверенность:
**СССС**, **СИС**, **СФЕРА-А**, **СФЕРА ПРОЕКТИРОВЩИКОВ**,
**СФЕРА ИЗЫСКАТЕЛЕЙ**, **ЯРД**.

**Пользователю:** читайте [ИНСТРУКЦИЯ.md](ИНСТРУКЦИЯ.md) — там всё простым языком.
**Запуск:** двойной щелчок по `START.bat`.

Разбор бланков и обоснование технических решений — в
[АНАЛИЗ_ШАБЛОНОВ.md](АНАЛИЗ_ШАБЛОНОВ.md).

## Для разработчика

### Главные правила

1. **Оригиналы бланков неприкосновенны.** `sro/<СРО>/templates/_originals/`
   открывается только на чтение. Рабочие шаблоны получаются из них скриптом
   `scripts/prepare_templates.py`, который меняет текст строго указанных
   фрагментов и сверяется с ожидаемым содержимым: изменилась редакция бланка —
   разметка останавливается с понятной ошибкой, а не портит документ молча.
2. **Ничего не выдумывать.** Нет данных — программа перечисляет, чего не хватает,
   и не формирует документы. Никаких «нет данных», прочерков и догадок.
3. **Склонение только при уверенности.** `morphology.py` возвращает
   `Inflected(value, confident, reason)`; при `confident=False` значение уходит
   на подтверждение пользователю, а не в документ.
4. **Одна генерация — один объект компании.** `generate()` работает с копией
   `CompanyData`, значения переменных вычисляются заново.
5. **Готово только после контроля.** `quality_control.py` проверяет каждый
   выходной файл; не прошёл — документ не считается готовым.
6. **Цифровые идентификаторы — строки.** ИНН, ОГРН, КПП, счета никогда
   не превращаются в числа.

### Как это работает

DOCX — это ZIP с XML внутри. Движок `docx_engine.py` распаковывает шаблон,
подставляет значения только в тех частях, где встречаются `{{переменные}}`,
и запаковывает обратно; остальные части копируются без изменений.

Переменная, разорванная Word'ом на несколько `w:r`, склеивается: текст абзаца
собирается в строку, значение возвращается в первый фрагмент переменной —
вместе с его оформлением. Обрабатываются абзацы, таблицы (в том числе
вложенные), колонтитулы, сноски, надписи и адреса гиперссылок в `.rels`.

### Команды

```bash
# завести новую СРО
python scripts/new_sro.py "СФЕРА-А"

# разметить бланки заново (после новой редакции от Ассоциации)
python scripts/prepare_templates.py            # все СРО
python scripts/prepare_templates.py СИС        # только одну

# перечитать уровни ответственности из бланков в sro.json
python scripts/extract_levels.py

# пересобрать карту соответствия config/field_map.md
python scripts/make_field_map.py

# консольный режим
python -m src.cli --sro-list
python -m src.cli --sro СССС --card input/Карточка.docx
python -m src.cli --text "ООО «Ромашка» ИНН 7812345675 ..." --dry-run
python -m src.cli --card input/Карточка.docx --set actual_address="..." --no-pdf
python -m src.cli --map

# тесты (вымышленные компании)
python tests/test_all.py
```

### Несколько СРО

Каждая СРО — папка в `sro/<название>/`: `sro.json` (название, документы,
умолчания, автозаполнение), `attorney.json` (доверенное лицо) и `templates/`
с её бланками. `src/sro_registry.py` находит их сам — список выбора равен
списку папок, кода это не касается.

`Project` держит выбранную СРО в `self.sro`; всё, что от неё зависит
(`templates_dir`, `documents`, `defaults`, `auto_fill`, `attorney`) —
свойства, читающие профиль. Переключение — `use_sro()`; выбор пишется
в `config/app.json` (`remember=False` для служебных обходов всех СРО).

Явно названная, но несуществующая СРО — ОШИБКА, а не повод взять
запомненную: иначе документы уедут не в ту СРО.

`SroProfile.is_ready` / `readiness_note()` отвечают за случай «СРО заведена,
бланков ещё нет»: интерфейс показывает это в списке выбора, а генерация
останавливается с объяснением, что положить и куда.

Результат складывается в `output/<компания>/<СРО>/` — компания сверху,
потому что одну компанию нередко подают в несколько СРО.

Новая СРО заводится скриптом `scripts/new_sro.py "НАЗВАНИЕ"`.

### Значения по умолчанию

`sro/<СРО>/sro.json`, раздел `defaults` — подставляются в новую карточку
компании через `Project.new_company()`. Сейчас там номер доверенности «б/н».
Умолчания применяются к НОВОЙ карточке, а не при каждой проверке: если
пользователь очистил поле, оно останется пустым.

### Подстановка из соседнего поля

`sro/<СРО>/sro.json`, раздел `auto_fill` — `{целевое_поле: поле-источник}`.
Применяется `Project.apply_auto_fill()`: пустое поле берёт значение источника,
заполненное не трогается. Сейчас правило одно: `actual_address` ← `legal_address`.
Вызывается в окне (при разборе карточки и при проверке), в консольном режиме
и внутри `generate()` — там как страховка, поверх копии объекта.

### Правки вёрстки бланка

`scripts/prepare_templates.py` умеет не только подставлять переменные.
Каждая правка сверяется с ожидаемым содержимым и падает, если бланк изменился.

| Правка | Зачем |
| --- | --- |
| `op_text`, `op_find`, `op_regex` | заменить текст: по номеру фрагмента, по его содержимому, по образцу на весь абзац |
| `op_cell`, `op_mark` | ячейка таблицы; `op_mark` дополнительно делает отметку «V» крупной и по центру |
| `op_blank` | пропуск «______» без счёта подчёркиваний; `newline=True` разрезает абзац, если бланк держит подпись к строке и следующую строку вместе |
| `op_line`, `op_add_line` | место под запись, подчёркнутое рамкой: написать в пустой абзац или дописать строку, которой в бланке не хватает |
| `op_font`, `op_spacing`, `op_pad`, `op_tab`, `op_rstrip` | шрифт от соседнего фрагмента, интервалы абзаца, подложка из пробелов → табуляция с прижимом вправо |
| `op_unfield` | обезвредить «поля» Word: бланк СИС собран программой слияния, и Word пересчитывал поля, подменяя наши данные именем автора файла |
| `op_rel` | адрес гиперссылки (`mailto:`) в `.rels` |

Результат защищён тестами `test_every_placeholder_has_explicit_font`,
`test_signature_has_room_to_sign`, `test_header_cells_are_level`,
`test_tabs_survive_rewriting`, `test_caption_and_value_are_on_separate_lines`,
`test_word_fields_are_flattened`,
`test_no_data_from_sample_blanks_survives`.

### Бланки, присланные заполненными

Два бланка (СИС и один из образцов СССС) пришли с данными других компаний.
Это самое опасное, что может быть: документ выглядит готовым, а в нём чужие
ОГРН и ИНН. Такие значения перечислены в разметке как «ожидаемый текст» и
заменяются, `quality_control.py` ищет чужую почту и посторонние 13-значные
числа, а `test_no_data_from_sample_blanks_survives` прямым поиском проверяет
готовые документы всех СРО.

### Добавить документ

Положить DOCX в `sro/<СРО>/templates/`, расставить переменные
из `config/variables.json`, дописать блок в `sro/<СРО>/sro.json`. Кода это
не касается. Если в шаблоне встретится неописанная переменная, программа
откажется формировать документы и назовёт её.

### Что сознательно не сделано

Получение реквизитов по ИНН из ЕГРЮЛ, проверка компании по открытым источникам,
сведения о специалистах НРС, пакетная обработка нескольких компаний.
Первое требует обращения к внешнему сервису — это отдельное решение, которое
нужно обсуждать с точки зрения конфиденциальности; остальное усложнило бы MVP.
Архитектура их не блокирует.

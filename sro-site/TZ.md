Единый документ. Заменяет все предыдущие версии ТЗ.

Проект: `sro-site/` (React 18 + TS + Vite 5 + Tailwind 3 + lucide-react)
Прод: https://caesart966-web.github.io/first_reposirtory/sro/

Правила работы:
- Проект не переписывать, правки точечные, по задачам.
- Новых тяжёлых зависимостей не добавлять. Исключение: `sharp` в devDependencies для подготовки изображений, либо обработка вручную через ImageMagick - тогда зависимость не нужна.
- После каждого блока задач: `npm run build` должен проходить без ошибок TS.
- Контакты только из `src/content/contacts.ts`, никаких хардкодов телефона и почты в компонентах.
- Изображений людей на сайте нет. Ни портретов, ни стока с людьми, ни отзывов с аватарами. Весь визуал предметный: гравюра, чертежи, конструкции, приборы.

# ЧАСТЬ 1. БЛОКЕРЫ РЕЛИЗА

## T1. Заявка должна уходить на почту

Файл: `src/lib/lead.ts`

Сейчас `sendLead()` делает `console.info()` и возвращает `Promise<void>`. Человек проходит 4 шага квиза, вводит имя, телефон, e-mail, ставит галочку согласия - и заявка умирает в консоли, а на экране успеха ему предлагают самому переслать её в WhatsApp. Здесь теряется большая часть лидов.

### Что сделать

**1. Сервис приёма формы.** Сайт статический, бэкенда нет, поэтому используем сервис, который принимает POST и пересылает письмо на почту. Подходят:
- Web3Forms - https://web3forms.com - без регистрации аккаунта, выдаёт access key на указанную почту, POST JSON на `https://api.web3forms.com/submit`;
- Formspree - https://formspree.io - нужен аккаунт, бесплатный тариф ограничен по числу заявок в месяц, endpoint вида `https://formspree.io/f/{id}`.

Реализовать через переменные окружения, чтобы сервис можно было заменить, не трогая код:

```
VITE_LEAD_ENDPOINT=https://api.web3forms.com/submit
VITE_LEAD_ACCESS_KEY=<ключ, выданный сервисом>
```

**2. Код `sendLead`:**
- `POST` c `Content-Type: application/json`;
- тело: `access_key`, `subject`, `from_name`, `replyto` (e-mail клиента, если указан - тогда Игорь отвечает прямо из почты кнопкой «Ответить»), `message` = результат `buildLeadMessage(lead)`;
- тема письма: `Заявка с сайта СРО - {Имя}, {Телефон}`. Телефон в теме нужен, чтобы можно было перезванивать прямо из списка писем, не открывая;
- если `VITE_LEAD_ENDPOINT` не задан или ответ не `ok` - **бросить ошибку**. Молчаливого «успеха» быть не должно ни при каких условиях;
- таймаут запроса 10 секунд через `AbortController`, иначе при недоступности сервиса кнопка будет крутиться бесконечно.

**3. Антиспам.** Добавить honeypot: скрытое поле (`aria-hidden`, вне таб-порядка, спрятано CSS, а не `type="hidden"`). Если оно заполнено - показать пользователю обычный экран успеха, но запрос не отправлять. Ключ сервиса всё равно попадёт в собранный бандл - это нормально и предусмотрено такими сервисами, но защиту от ботов надо делать отдельно.

**4. Экран успеха переписать.** Сейчас заголовок «Заявка готова» и просьба отправить её самому. Должно быть:
- «Заявка отправлена. Отвечу в течение [N] часов» - `[N]` уточнить у заказчика;
- ниже вторичной строкой: «Хочется быстрее - напишите в WhatsApp или Telegram» с уже подставленным текстом заявки. Логику `buildLeadMessage` сохранить, она для этого и написана, но понизить в приоритете до вспомогательных кнопок.

**5. Обработка ошибки.** При падении запроса - явное сообщение «Не удалось отправить заявку» плюс рабочие кнопки: позвонить, WhatsApp, Telegram. Введённые данные не сбрасывать, дать кнопку «Попробовать снова».

### Что проверить после внедрения

- Тестовая заявка доходит до `9001330219@mail.ru`.
- **Письмо проверить в папке «Спам».** Первые письма от таких сервисов почти всегда туда и падают. Игорю нужно: найти письмо, нажать «Не спам», добавить отправителя в адресную книгу, сделать фильтр в отдельную папку «Заявки с сайта».
- Кнопка «Ответить» в почте отвечает клиенту, а не сервису (проверяется поле `replyto`).

### Риск, который надо держать в голове

Запрос уходит из браузера посетителя, который находится в России. Если сервис окажется недоступен у части пользователей, заявки будут теряться молча. Поэтому фолбэк из пункта 5 обязателен, а не опционален. Когда сайт переедет на реальный домен и российский хостинг, правильнее заменить внешний сервис на собственный обработчик (простой PHP-скрипт с `mail()` или функция в Яндекс.Облаке) - код при этом менять не придётся, поменяется только `VITE_LEAD_ENDPOINT`.

**Цены.** `src/components/Pricing.tsx`: три карточки с `от [ЦЕНА]`. Для юридической услуги это выглядит как недоделанный сайт. Выбрать одно:

**MAX.** `src/content/contacts.ts`: `max: '[MAX_LINK]'`. Сейчас кнопка MAX ведёт на `#contacts`, то есть сама на себя. Ссылки пока нет, поэтому:
- в `Contacts.tsx` карточка MAX не рендерится, если `CONFIGURED.max === false`;
- в `Footer.tsx` строка MAX не рендерится по тому же условию;
- в `MobileBar.tsx` сетка становится динамической: `grid-cols-3` при трёх активных каналах, `grid-cols-4` при четырёх. Захардкоженный `grid-cols-4` убрать.

Когда ссылка появится, заказчик меняет одну строку в `contacts.ts` и MAX возвращается на все три места автоматически. Логика `CONFIGURED` для этого уже написана, её нужно только начать использовать для скрытия, а не для подмены ссылки на якорь.

**Домен.** `index.html`: `canonical` и `og:url` = `https://example.com/`. Пока реального домена нет - оставить как есть и вернуться к задаче после его покупки. В `public/robots.txt` строку Sitemap тоже не трогать до этого момента.

## 3.2. T23. Подготовка файла

Гравюра лежит на состаренной бумаге. В лоб её ставить нельзя - получится грязное жёлтое пятно.

**Путь A, правильный: трассировка в SVG.** Чистые линии, `currentColor`, резкость на любом экране, тот же приём, что уже используется в проекте.

```bash
# 1. Скачать оригинал в максимальном разрешении со страницы Met (кнопка Download Image)
# 2. Поднять контраст и убрать бумагу
magick themis-src.jpg -colorspace Gray -normalize -level 35%,80% -threshold 55% themis-bw.pbm
# 3. Трассировать в вектор
potrace themis-bw.pbm -s -o themis.svg --turdsize 6 --alphamax 1.2
```

Дальше вычистить мусорные контуры, заменить `fill` на `currentColor`, положить в `src/components/illustrations.tsx` как компонент `ThemisEngraving`.

**Путь B, быстрый: WebP + blend mode.** Бумага убирается не вырезанием, а режимом наложения `multiply` - белое становится прозрачным само.

```bash
magick themis-src.jpg -colorspace Gray -normalize -level 30%,85% \
  -resize x2400 -quality 82 public/img/themis.webp
```

Начать с пути B, довести композицию, потом заменить на путь A.

## 3.4. T25. Главная ловушка: непрозрачные фоны

Подложка лежит позади контента. Сплошной белый фон секций перекроет её полностью, и на экране не будет ничего. Это самая частая ошибка при таком приёме - проверять в первую очередь.

1. `src/index.css`: `body` остаётся `bg-white`, контейнер контента `z-10` собственного фона не задаёт.
2. Секции с заливкой: `bg-neutral-50/70` -> `bg-neutral-50/55`. Секции без фона фон не получают.
3. Карточки внутри секций остаются непрозрачными `bg-white`. Контраст «плотная карточка на просвечивающем фоне» и создаёт глубину.
4. `Hero.tsx`: там уже есть `BlueprintGrid` и два размытых пятна. Два фоновых мотива друг на друге дают грязь. Либо дать герою собственный `bg-white/60`, либо начинать маску Фемиды ниже первого экрана.

## 3.5. T26. Границы вкуса

- прозрачность **не выше 0.06** на светлом фоне. На 0.1 это уже обои, а не водяной знак;
- **один** экземпляр во вьюпорте, никакого тайлинга;
- цвет только `text-accent-900` (#1E2A75) или нейтральный. Никакого золота, бронзы, мрамора;
- на `< sm` скрыть (`hidden sm:block`): на 360px крупный фрагмент читается как случайная линия;
- в тёмной секции квиза подложка скрыта самой секцией - так и надо, это «вдох» между половинами страницы;
- `@media print { .themis-backdrop { display: none } }`;
- никакого параллакса и `background-attachment: fixed` - на iOS Safari это даёт дёрганый скролл;
- контраст текста нигде не падает ниже 4.5:1.

Проверка: скриншот всей страницы, уменьшить до 25%, посмотреть с расстояния. Фемида должна читаться как фактура бумаги, а не как картинка на фоне.

## 4.5. T28. Компонент `Figure`

`src/components/ui/Figure.tsx` - один компонент на все слоты, чтобы не разъезжались размеры и скругления:

```tsx
type FigureProps = {
  src: string           // './img/design.webp'
  srcAvif?: string
  alt: string           // осмысленный, не «картинка»
  caption?: string
  ratio?: string        // 'aspect-[4/3]' | 'aspect-[20/7]'
  priority?: boolean    // true только для первого экрана
  className?: string
}
```

Внутри `<picture>` с `<source type="image/avif">`, обязательные `width`/`height`, `loading={priority ? 'eager' : 'lazy'}`, `decoding="async"`. Обёртка `rounded-2xl overflow-hidden border border-neutral-200/80`.

Без `width`/`height` вёрстка прыгает при загрузке и Lighthouse снимает баллы за CLS.

## 4.6. T29. Единая обработка: дуотон

Четыре картинки из четырёх источников будут выглядеть как четыре разных сайта. Лечится переводом всех в дуотон на фирменном синем - заодно прячется «стоковость».

```bash
magick input.jpg -colorspace Gray \
  \( -size 256x1 gradient:'#1E2A75-#E6ECFF' \) -clut \
  -resize 1200x -quality 82 public/img/design.webp
magick public/img/design.webp -quality 55 public/img/design.avif
```

Одна из четырёх может остаться в цвете как акцент - кандидат «стройка», если кадр действительно хорош. Остальные три строго дуотон.

## 4.7. T30. Бюджет по весу

- каждое изображение: AVIF <= 120 КБ, WebP <= 180 КБ;
- все изображения страницы суммарно: <= 600 КБ;
- Фемида отдельно: SVG после трассировки <= 150 КБ, либо WebP <= 200 КБ;
- ни одного PNG для фотографий; JPEG только как фолбэк внутри `<picture>`.

## 4.8. T31. Учёт лицензий

Завести `sro-site/public/img/CREDITS.md`: файл, URL источника, автор, лицензия, дата скачивания. Через год никто не вспомнит, откуда взялась картинка, а претензия придёт именно тогда.

Правовая гигиена (не юридическая консультация, а практика):

# Сайт частного специалиста по СРО

Одностраничный сайт (landing page) независимого эксперта, который помогает компаниям и ИП
вступить в СРО, подобрать и проверить СРО, подготовить документы, решить вопросы НРС и НОК
и получить сопровождение.

## Стек

- React 18 + TypeScript
- Vite 5
- Tailwind CSS 3
- lucide-react (иконки)
- Inter Variable (шрифт, локально через `@fontsource-variable/inter` — без внешних запросов)

Без роутера и без тяжёлых зависимостей. Фронтенд статический; единственная
серверная часть — обработчик заявок `public/api/submit.php` (см. «Заявки на
почту»), и она нужна только если сайт стоит на хостинге с PHP.

Графика двух родов: интерфейсные иконки и фоновые мотивы — SVG прямо в коде
(`components/icons.tsx`, `components/illustrations.tsx`), фотографии — WebP
с AVIF-дублем в `public/img/`.

## Запуск

```bash
cd sro-site
npm install
npm run dev        # http://localhost:5173
npm run build      # typecheck + прод-сборка в dist/
npm run preview    # локальный просмотр прод-сборки
```

## Перед публикацией: что осталось заполнить

Контакты (имя, телефон, e-mail, WhatsApp, Telegram) реальные и заданы в
`src/content/contacts.ts` — это единственное место, весь сайт обновляется сам.

| Что | Где | Пока не заполнено |
| --- | --- | --- |
| Ссылка на MAX | `src/content/contacts.ts` — вид `https://max.ru/u/…` (берётся в приложении MAX: «Поделиться» / QR-код; по номеру телефона ссылку получить нельзя) | MAX не показывается на сайте вообще — ни в контактах, ни в футере, ни в мобильной панели |
| Цены | `src/components/Pricing.tsx` | Карточки работают как форматы работы без цифр; стоимость называется после разбора задачи |
| Тексты политики и согласия | `src/components/LegalDocs.tsx` | Открываются шаблоны с предупреждением: нет реквизитов оператора (статус, ИНН, ОГРНИП, адрес) |
| Домен | `index.html` (canonical, og:url), `public/robots.txt` (Sitemap) | Стоит `https://example.com/` — меняется после покупки домена |

Как только в `contacts.ts` появится ссылка на MAX, он сам вернётся во все три
места: видимость каналов управляется флагами `CONFIGURED` из этого же файла.

## Приём заявок из квиза

Заявка уходит **на почту** `9001330219@mail.ru`. Код — в `src/lib/lead.ts`.

Приёмников два, выбор зависит от того, где стоит сайт:

| Где стоит сайт | Приёмник | Почему так |
| --- | --- | --- |
| Российский хостинг с PHP | `public/api/submit.php` — свой обработчик на том же домене | **Рабочий вариант.** Web3Forms — зарубежный сервис, из России без VPN не открывается, и заявки не дошли бы |
| GitHub Pages, зарубежный хостинг | Web3Forms (значение по умолчанию) | PHP там не выполняется |

- В письме: тема `Заявка с сайта СРО — Имя, Телефон` (можно перезванивать
  прямо из списка писем), в теле — контакты и все ответы квиза.
- Кнопка «Ответить» в почте отвечает **клиенту**, а не сервису (поле `replyto`).
- Таймаут 10 секунд. Если сервис не ответил, посетитель видит «Не удалось
  отправить заявку», введённые данные сохраняются, есть кнопка «Попробовать
  снова» и прямые каналы связи. Молчаливого «успеха» не бывает.
- Форма защищена honeypot-полем: заполнившему его боту показывается обычный
  экран успеха, но заявка не отправляется.

Сменить приёмник можно без правки кода — через переменные окружения
(см. `.env.example`). Формат запроса и ответа у своего обработчика намеренно
такой же, как у Web3Forms, поэтому фронтенд одинаков для обоих:

```
# Свой хостинг с PHP:
VITE_LEAD_ENDPOINT=/api/submit.php
VITE_LEAD_ACCESS_KEY=<любая строка, та же что FORM_TOKEN в submit.php>

# Web3Forms:
VITE_LEAD_ENDPOINT=https://api.web3forms.com/submit
VITE_LEAD_ACCESS_KEY=<ключ сервиса>
```

Без этих переменных используются значения по умолчанию из `src/lib/lead.ts`.
В GitHub Actions они пробрасываются из Secrets репозитория, если заданы.

### Свой обработчик: что заполнить

`public/api/submit.php` попадает в сборку сам и оказывается по адресу
`/api/submit.php`. Перед заливкой на хостинг в нём заполняются четыре строки:

| Константа | Что вписать |
| --- | --- |
| `MAIL_TO` | куда приходят заявки |
| `MAIL_FROM` | **адрес на домене сайта**, например `zayavka@вашдомен.ru`. Заводится в панели хостинга. Чужой домен нельзя: не сойдётся SPF, и письма уйдут в спам |
| `FORM_TOKEN` | та же строка, что в `VITE_LEAD_ACCESS_KEY` при сборке. Если не совпадёт — сайт покажет экран ошибки |
| `ALLOWED_HOST` | домен сайта, чтобы чужая страница не слала заявки от вашего имени |

Обработчик отсекает заголовочные инъекции, ограничивает частоту (10 заявок
с одного адреса в час) и кодирует русскую тему письма по MIME.

Проверить его, не рассылая почту, можно так — письмо запишется в файл:

```bash
SRO_MAIL_DRY_RUN=/tmp/lead.eml php -S 127.0.0.1:8000 -t dist
curl -X POST http://127.0.0.1:8000/api/submit.php \
  -d '{"access_key":"<FORM_TOKEN>","message":"проверка"}'
cat /tmp/lead.eml
```

**Первое письмо почти наверняка попадёт в «Спам»** — это нормально для таких
сервисов. Нужно найти его, нажать «Не спам», добавить отправителя в адресную
книгу и сделать фильтр в папку «Заявки с сайта».

Порядок секций на странице: герой → виды СРО → типовые ситуации → услуги →
процесс → документы → стоимость → о специалисте → контакты → FAQ → квиз.

Вопрос квиза задаётся ровно в двух местах: карточками в «Видах СРО» (там
выбирают вид) и в самом квизе. В герое его нет намеренно — раньше стоял, и
посетитель видел первый вопрос дважды: в герое и в квизе ниже.

## Принципы контента

На сайте нет отзывов, выдуманных цифр, достижений, лицензий, цен и сроков —
только описание услуг и формата работы. Всё, что требует реальных данных,
вынесено в плейсхолдеры вида `[ИМЯ]`; пока плейсхолдер не заменён, блок с ним
не показывается, а не выводит скобки на экран.

Фотографии есть — пять, все с подтверждённой лицензией; источник каждой записан
в `public/img/CREDITS.md`. Логотипы СРО, НОСТРОЙ, НОПРИЗ, Минстроя, гербы и
флаги не ставятся: чужие обозначения плюс намёк на аккредитацию, которой нет.

Обещаний результата и сроков («вступление за 1 день», «гарантия внесения в
реестр», «ответ за 24 часа») на сайте нет и быть не должно: это не зависит от
исполнителя.

Единственное прямое обязательство — бесплатная консультация: она бесплатна
всегда, а не только в первый разговор. Это условие задал заказчик, в исходном
ТЗ его не было. Сказано оно в шести местах — герой, «Стоимость» (подзаголовок
и карточка формата), «Контакты», FAQ, квиз, подвал; формулировки разные, смысл
один. Меняете условие — правьте все шесть, иначе сайт начнёт противоречить
сам себе.

## Цвет

Акцент — кобальтовый синий (`accent` в `tailwind.config.js`), единственный
акцентный цвет сайта. Нейтральная шкала переопределена на тёплую: на чистом
сером холодный акцент и синие фотографии давали ощущение мороза. Это greige —
серый со сдвигом в жёлтый, а не бежевый, поэтому деловой вид сохраняется.

Фотографии подчиняются тому же правилу: тёмная точка дуотона — фирменный синий,
светлая — кремовая (см. `public/img/CREDITS.md`). Меняете одно — проверяйте
второе, иначе интерфейс и снимки разойдутся по температуре.

Анимации лёгкие (fade/reveal/hover) и отключаются при `prefers-reduced-motion`.
Карточка приподнимается под курсором только если она кликается целиком:
подъём — это обещание клика (`src/components/ui/card.ts`).

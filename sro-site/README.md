# Сайт «Бизнес-Групп» — вступление в СРО

Рекламный сайт ООО «БИЗНЕС-ГРУПП»: помощь компаниям и ИП во вступлении в СРО, подбор
и проверка СРО, подготовка документов, специалисты НРС и НОК, сопровождение. Главная,
три страницы видов СРО и семь страниц услуг. Опубликован на https://biznesgrp.ru
(хостинг Timeweb).

С 24.09.2026 сайт **рекламный, без формы**: квиз, приём заявок и политика
конфиденциальности сняты по просьбе заказчика. Связь — телефон и мессенджеры
в разделе «Связаться» внизу каждой страницы.

## Стек

- React 18 + TypeScript
- Vite 5
- Tailwind CSS 3
- lucide-react (иконки)
- Шрифты локально, без внешних запросов: Onest Variable (`@fontsource-variable/onest`)
  — текст и интерфейс; Brygada 1918 Variable (`@fontsource-variable/brygada-1918`) — заголовки

Без роутера и без тяжёлых зависимостей. Сайт целиком статический: серверной
части нет (обработчик заявок `public/api/submit.php` удалён вместе с квизом).

Графика двух родов: интерфейсные иконки и фоновые мотивы — SVG прямо в коде
(`components/icons.tsx`, `components/illustrations.tsx`), фотографии — WebP
с AVIF-дублем в `public/img/`.

## Запуск

```bash
cd sro-site
npm install
npm run dev        # http://localhost:5173
npm run build      # typecheck + прод-сборка в dist/
npm run preview    # локальный просмотр прод-сборки
```

## Оформление (24.09.2026)

Заказчик попросил сделать сайт так, «чтобы было видно, что его делали люди,
а не ИИ», в духе apple.com и присланных примеров (сайт LeonHome, ролик
с переходами сайта «woodland»). Решения:

- **Палитра** — тёплая, без синего: графит `accent-950` `#1C1815`, крем
  `neutral-50` `#FBF9F5`, латунь `accent-500…700` как единственный акцент.
  Шкалы в `tailwind.config.js`. Контраст посчитан: `neutral-500` на креме
  4.56:1, `accent-600` на светлом ≥ 5:1, `accent-500` — только для декора
  (линии, знаки), текстом не используется.
- **Шрифты** — Brygada 1918 (антиква) в заголовках, Onest (гротеск в духе
  San Francisco, с кириллицей) в тексте. Заголовки обычным регистром,
  выровнены влево; в `.font-display` включены цифры по высоте прописных
  (`lining-nums`) — завелось при Cormorant, у которого «0 ₽» читалось
  как «о ₽».

  Brygada выбрана 24.09.2026 вместо Cormorant: заказчику тот показался
  тонким, а во всех его примерах (сайты юридических фирм) заголовки набраны
  плотной антиквой. На страницах сайта сравнивались десять антикв
  с кириллицей и несколько гротесков. **Playfair Display, Inter
  и Montserrat отброшены нарочно**: это шрифты по умолчанию у сайтов,
  собранных нейросетью, а заказчик просил, чтобы сайт так не выглядел.
  Jost отброшен за русскую «д» в виде «∂» («по∂ходящую»). Сам шрифт Apple
  (SF Pro) на сайт ставить нельзя — лицензия разрешает его только
  в программах и макетах для устройств Apple; Onest ближе всех к нему
  по духу.

  Brygada шире Cormorant, и замена вскрыла две тесноты: слово
  «компенсационные» в заголовке раздела на 320 px (кегль заголовков
  страниц видов и услуг теперь на ступень меньше до 360 px) и кружок-стрелку
  в карточках услуг, который при четырёх колонках выталкивало за край
  (он переехал отдельной строкой над заголовком). Меняете шрифт —
  прогоняйте `scripts/test-site.mjs`: он ловит горизонтальную прокрутку
  на пяти ширинах.
- **Движение** — медленное и мягкое: кривая `ease-silk`
  (`cubic-bezier(0.22,1,0.36,1)`), 0,7–1,1 с. Заголовки разделов проявляются
  по словам из-под маски (`RevealText`), блоки — выплыванием (`Reveal`);
  фотографии разделов стоят фоном и въезжают по прокрутке (`.scroll-settle`,
  шторка `RevealImage` снята 25.09.2026 вместе с последней фотографией
  в рамке). Всё отключается при
  `prefers-reduced-motion`. Наблюдатель срабатывает, как только блок зашёл
  в окно на 10% высоты экрана (`threshold: 0`), а не по доле площади блока:
  у высокого блока 15% площади на телефоне не набиралось никогда, и он
  оставался прозрачным.

  С 25.09.2026 к этому добавлено движение по прокрутке, как на apple.com:
  кадр первого экрана и шапок страниц видов медленно приближается, пока
  страница уходит вверх (`.scroll-drift`), а фотографии Фемиды и папок входят
  в кадр чуть крупнее и «садятся» на место (`.scroll-settle`). Сделано
  на CSS (`animation-timeline: scroll()` / `view()`), без скриптов и без
  единого лишнего килобайта: браузер двигает уже загруженную картинку.
  Браузер, который такой анимации не знает, просто оставляет кадр на
  месте — правило обёрнуто в `@supports`, и при `prefers-reduced-motion`
  не включается.
- **Первый экран** — «лист и окно»: текст и три вида СРО списком слева,
  кадр с краном справа, растворяется в бумаге и при загрузке «проявляется»

- **Переходы между страницами** — плавные, 0,4 с, кадр с главной перетекает

## Карточка в мессенджерах и карта сайта

Две вещи, которых на самой странице не видно, но без которых сайт работает хуже.

**Картинка карточки (`og:image`).** Когда ссылку отправляют в WhatsApp, Telegram
или ВКонтакте, мессенджер показывает карточку: заголовок, описание и картинку.
Фотографии со страницы он для этого не берёт — ему нужно прямое указание,
и до 08.09.2026 его не было: карточка приходила без изображения.

Картинка одна на все одиннадцать страниц и собрана из фирменных элементов
сайта: знак весов из `illustrations.tsx`, тёмный графит `accent-950` как
у раздела «Связаться», те же шрифты — Brygada 1918 и Onest (с 24.09.2026;
до того — синий фон и Inter). Фотографии в ней нет намеренно — карточка
в переписке показывается размером с ноготь, и любой кадр там превращается
в кашу, а знак и имя читаются.

Генератор — `scripts/build-og.mjs`, кладёт `public/og.png` размером 1200×630
(этого размера ждут все мессенджеры). Playwright в зависимостях сайта нет:
картинка пересобирается редко, и тащить браузер в прод-сборку ради неё незачем,
поэтому модуль берётся из переменной окружения:

```bash
PLAYWRIGHT=/путь/к/node_modules/playwright-core/index.js node scripts/build-og.mjs
```

Шрифт вшивается в страницу из `node_modules`, а не тянется из сети: среда
сборки может быть без интернета, и тогда картинка молча уехала бы системным
шрифтом — на глаз почти незаметно, а фирменный вид уже не тот.

**Карта сайта (`public/sitemap.xml`).** Список всех адресов для Яндекса
и Google. Поисковик находит главную, но не обязан догадаться, что есть ещё три
страницы видов СРО и семь страниц услуг: ссылки на них лежат в выпадающем меню,
которое собирается скриптом. Карта называет все двенадцать адресов прямо.

Список не пишется руками: `scripts/build-sitemap.mjs` собирает его из самих
файлов — каждая страница сайта это отдельный `index.html` со своей точкой входа
(см. `vite.config.ts`), появится новая — попадёт в карту сама. `lastmod`
намеренно нет: неверная дата хуже отсутствующей, а честную взять неоткуда.

**Домен подставляется одной командой.** Плейсхолдер `https://example.com` стоит
в четырнадцати файлах: canonical, og:url и og:image двенадцати страниц, карта
сайта и `robots.txt`. Пропустить одно место легко, а страница с чужим canonical
выпадает из поиска молча, без единой ошибки. Поэтому:

```bash
node scripts/set-domain.mjs sro-rostov.ru     # или https://sro-rostov.ru/
npm run build
```

Скрипт заодно убирает пометку TODO про домен и падает с ошибкой, если хоть
где-то `example.com` остался.

Сторожит всё набор `og-sitemap.mjs` (100 проверок): картинка отдаётся и ровно
1200×630, карта валидна и покрывает все страницы без дублей и лишнего, robots
её называет, а canonical каждой страницы указывает на неё саму и не совпадает
с соседней — копипаста здесь ничем другим не ловится.

## Микроразметка, страница 404 и иконка для iOS

**Микроразметка Schema.org.** Поисковик читает страницу как текст и не знает,
что «6164132279» — это ИНН, а «+7 900 133-02-19» — телефон компании, а не
случайное число. Разметка называет это прямо: по ней собирается карточка
организации в поиске и путь под ссылкой (хлебные крошки).

Пишется в статический HTML, а не выводится из React: Яндекс выполняет скрипты
не всегда, и разметка, появляющаяся только после запуска приложения, для него
может не существовать вовсе. Генератор `scripts/build-jsonld.mjs` берёт данные
из тех же файлов, что и сам сайт — `contacts.ts`, `facts.ts`, `regions.ts`
и заголовки страниц, — второго источника правды нет. На каждой странице
`Organization`, на десяти внутренних ещё и `BreadcrumbList`.

Тип `Organization`, а не `LocalBusiness`: последний означает место, куда
приходят клиенты, а сайт прямо говорит «дистанционно, личный визит не
требуется». Заявлять приём посетителей мы не будем. В `areaServed` те же
строки, что в блоке «География работы»: с 01.10.2026 — тринадцать субъектов
РФ (после правки `regions.ts` разметку пересобирают командой
`node scripts/build-jsonld.mjs && node scripts/set-domain.mjs biznesgrp.ru`:
генератор пишет плейсхолдер example.com, домен подставляет второй скрипт).

**Страница 404** — `public/404.html`. Обычный статический файл без React
и без сборки: на неё уводит сам хостинг, когда адреса не существует, и она
обязана открыться, даже если скрипты сайта не загрузились. Поэтому шрифт
системный, а стили внутри файла — ни одной внешней зависимости. Контакты
в ней записаны отдельно от `contacts.ts`, и набор `jsonld-404.mjs` сверяет
их с подвалом сайта, чтобы при смене телефона они не разъехались.

**Иконка для iOS** — `public/apple-touch-icon.png`, 180×180. Safari не умеет
SVG-фавиконку для ярлыка «на экран Домой»: без PNG вместо знака компании там
окажется уменьшенный скриншот страницы. Рисуется из того же `favicon.svg`
скриптом `scripts/build-icons.mjs`, прозрачности нет намеренно — iOS
подкладывает под ярлык чёрный фон.

Сторожит всё набор `jsonld-404.mjs` (194 проверки). Главное, что он делает,
— сверяет разметку с тем, что реально отрисовано: имя и ИНН из разметки
обязаны находиться в подвале, телефон, почта и улица — в разделе
«Связаться» (с 24.09.2026 контакты там, а не в подвале), а название
последней крошки — совпадать с заголовком. Разметка, разошедшаяся с текстом,

## Принципы контента

На сайте нет отзывов, выдуманных цифр, достижений, лицензий, цен и сроков —
только описание услуг и формата работы. Всё, что требует реальных данных,
вынесено в плейсхолдеры вида `[ИМЯ]`; пока плейсхолдер не заменён, блок с ним
не показывается, а не выводит скобки на экран.

Фотографий шесть. У пяти источник и лицензия подтверждены заказчиком; у шестой —
фона секции заявки — файл прислан заказчиком напрямую, а источник он пока не
назвал, и в учёте так и написано. Всё — в `public/img/CREDITS.md`. Логотипы СРО, НОСТРОЙ, НОПРИЗ, Минстроя, гербы и
флаги не ставятся: чужие обозначения плюс намёк на аккредитацию, которой нет.

Обещаний результата и сроков («вступление за 1 день», «гарантия внесения в
реестр», «ответ за 24 часа») на сайте нет и быть не должно: это не зависит от
исполнителя.

Единственное прямое обязательство — бесплатная консультация: она бесплатна
всегда, а не только в первый разговор. Это условие задал заказчик, в исходном
ТЗ его не было. Сказано оно в «Стоимости» (подзаголовок и карточка
формата), в FAQ и в разделе «Связаться»; формулировки разные, смысл один.
Дословная оговорка «и первая, и все следующие» стоит на каждой странице
ровно один раз — в «Связаться» (`Contact.tsx` и подпись к нему
в `DetailPage.tsx`, `ServicePage.tsx`). До 24.09.2026 она была в подвале;
с разделом «Связаться» прямо над ним она стояла бы дважды подряд.
Меняете условие — правьте все места, иначе сайт начнёт противоречить
сам себе.

## Ссылки мессенджеров и открытие приложения

Кнопки WhatsApp, Telegram и MAX ведут на универсальные ссылки самих
мессенджеров (`wa.me`, `t.me`, `max.ru`) и ведут себя по-разному на телефоне
и на компьютере. Логика — в одном компоненте `components/MessengerLink.tsx`;
устройство определяется по указателю (`(hover: hover) and (pointer: fine)`),
а не по ширине экрана: планшет в альбомной ориентации шире ноутбука, а
приложения на нём открываются как на телефоне.

**Телефон и планшет** — обычная ссылка в той же вкладке, без
`target="_blank"`. Это условие работы, а не упущение: ни iOS, ни Chrome на
Android не запускают universal link / app link, если переход идёт в новую
вкладку. С `target="_blank"` нажатие открывало пустую страницу или веб-версию
вместо приложения — заказчик поймал это на живом сайте.

**Компьютер** — та же ссылка, но в новой вкладке: сайт остаётся открытым.
Выбор «веб-версия или приложение» делает страница самого мессенджера: `t.me`
предлагает «Open in Web» и «Open chat», `wa.me` — «Continue to chat» с
переходом в WhatsApp Web или в программу, а браузер спрашивает, открыть ли
приложение. Своего меню выбора на сайте нет намеренно: такой вариант был
собран и показан, заказчик попросил именно привычный выбор на странице
мессенджера. Открывается диалог без готового текста: с квизом ушёл
и экран, который собирал текст заявки для WhatsApp.

Сторожит это `deeplinks.mjs`, в двух режимах: с сенсорным экраном все каналы
— ссылки на https без `target="_blank"`; с мышью — те же ссылки с
`target="_blank"` и `rel="noopener noreferrer"`. Мессенджеры на странице
помечены атрибутом `data-channel`, чтобы проверки не зависели от того, есть у
ссылки `target` или нет.

Две вещи, которые кодом не чинятся, если чат всё-таки не открывается:

- **Telegram.** Ссылка стоит на @username (`t.me/Igor_bgspb`), а не на номер.
  Форма `t.me/+<номер>` тоже рабочая, но открывает чат лишь у тех, кому
  владелец номера разрешил находить себя по телефону; у остальных приложение
  открывалось без чата. Заказчик поймал это вживую — с именем пользователя
  условия нет.
- **WhatsApp заблокирован в России.** Роскомнадзор исключил домены
  `whatsapp.com` и `web.whatsapp.com` из национальной системы доменных имён
  в феврале 2026 года; доступ то появляется, то пропадает, устойчиво работает
  только через VPN. Ссылка на сайте корректна, но у посетителя из России
  канал может не сработать — и это не чинится кодом. Решение, оставлять ли
  WhatsApp на сайте, за заказчиком; рабочие каналы для российской аудитории —
  Telegram, MAX и телефон.
- **Встроенный браузер мессенджера.** Если сайт открыт изнутри Telegram или
  VK, их встроенный браузер обрабатывает ссылки по-своему. Проверять нужно
  в обычном Chrome или Safari.

**Не одностраничник с роутером, а четыре обычных html.** Каждая страница —
своя точка входа Vite (`vite.config.ts`, `build.rollupOptions.input`). Так у
неё настоящий адрес: ссылку можно прислать, поисковик видит три отдельные
страницы, а хостингу не нужен фолбэк на `index.html`, без которого адрес,
открытый напрямую, отдавал бы 404.

**Что на страницах** (с 28.09.2026, вторая редакция того же дня). Заказчик
посмотрел компактную раскладку и сказал: «информации куча написано, хотелось
бы структурированно, понятно и профессионально». Дело было не в рамках,
а в объёме текста, поэтому страница собрана заново вокруг того, что человек
ищет глазами:
- **ключевые цифры** сразу под шапкой (`KeyFacts`): порог по договору
  (у строителей 10 млн ₽, у остальных «без порога» — поле `threshold`),
  от 2 специалистов в НРС, 2 месяца на рассмотрение, минимальный взнос
  в фонд возмещения вреда; у каждой — статья. Под ними — виды работ;
- **«Кому нужно членство»** — таблица «ситуация → ответ» (поле `cases`
  в `sroDetails.ts`): слева ситуация и статья, справа ответ и короткое
  уточнение. Раньше это были абзацы по три-четыре строки, и ответ приходилось
  вычитывать из середины. С 01.10.2026 оформление другое (заказчик:
  «красиво и эстетично, но главное не по-ИИ-шному»): меток-пилюль пяти
  видов больше нет — пилюли и есть примета шаблона, — ответ набран словом,
  антиквой, как заголовки: «Нужно» чернилами, «Не нужно» серым, «Есть
  исключения» латунью; над колонками подписи «Ситуация» и «Членство в СРО»,
  под ними тёмная линейка, как у таблицы в документе. В таблице остались
  только ответы на «нужно ли членство»; закупки (второй фонд), регион
  (по полю `regional`) и «допусков нет» — общие правила, они стоят под
  таблицей строкой из трёх пунктов (`Rules` в `DetailPage.tsx`), на телефоне
  друг под другом;
- **шаги** — одной-двумя строками каждый (`STEPS`, общие со страницей
  услуги «Вступление в СРО»), три колонки, номер; кто делает шаг — словом
  в заголовке: «Проверяю…», «Подбираю…», «Готовим…», «СРО принимает
  решение…», «Вы оплачиваете…», «СРО вносит компанию в реестр». До 01.10.2026
  рядом с номером стояли метки-пилюли «делаю я / от вас / делает СРО»;
  заказчик спросил, нужны ли они и верны ли. Не верны: у третьего шага
  стояло «от вас», а в тексте — «документы собираю и проверяю я»;
  заголовки при этом говорили «мы» («Проверяем») рядом с «делаю я».
  Пилюли-бирки к тому же — примета шаблона. На телефоне номер слева
  от текста, как в шагах на главной: раздел короче на 226 px (1612 → 1386);
- **документы** — только названия, три колонки: «Требует закон»,
  «Специалисты в НРС», «Запрашивает СРО» с переключателем ООО / ИП
  (кнопки с `role="tab"`, а не радиокнопки: полей ввода на сайте нет).
  Что входит в каждый документ — на странице «Подготовка документов»,
  ссылка стоит под колонками;
- **компенсационные фонды** — две таблицы минимумов, у каждой одна строка
  «кто платит и от чего уровень», под ними одна строка оговорок;
- ссылка на норму — сноской, а не серой плашкой: перед номером статьи
  короткая латунная черта, как перед подписью источника (`Law`
  в `PageParts.tsx`). До 01.10.2026 там стоял значок весов, но весы — знак
  компании: повторённый у каждой нормы (на странице вида их полтора
  десятка), он становился маркером списка, а в 14 px сливался в пятно.
Карточки «Срок рассмотрения» и «Региональный принцип» сняты: срок стоит
в ключевых цифрах и в четвёртом шаге, регион — строкой таблицы.
Заголовки разделов — сверху, как на главной: под ними сетки в две-три
колонки, которым левая рейка первой редакции оставляла треть ширины.
Длина страницы строителей: телефон 16,3 → 12,1 экрана, компьютер
8,8 → 6,7. Факты не менялись — ушли повторы и пересказ.

**Заголовок шапки на телефоне** — 1,95rem, с 380 px — 2,35rem. На прежних
2,9rem «проектировщиков» и «ответственности» были шире экрана и обрезались
краем шапки. Горизонтальной прокрутки при этом нет, поэтому проверки этого
не видели; теперь `test-site.mjs` меряет строки каждого заголовка
(«заголовки не шире своей колонки»).

прямо. Про цены и сроки нашей работы там нет ни слова — таких данных
заказчик не давал.

**Глубина вложенности.** Пути к картинкам из `public/` и ссылки на секции
главной написаны руками, и на странице в подпапке они ломаются молча:
`./img/x.webp` превращается в `/sro-stroiteley/img/x.webp`, а `#services`
ведёт в никуда. Поэтому оба вида ссылок проходят через `src/lib/site.ts`, а
точка входа объявляет свою глубину один раз — `setSiteRoot('../')`. Сторожит
это набор `pages.mjs`: он открывает каждую страницу и требует, чтобы
картинки реально загрузились, а ссылки реально отвечали 200.

**Кнопки ведут в «Связаться» на той же странице.** До 24.09.2026 кнопка
вела в квиз на главной с уже выбранным видом (`/?sro=construction#quiz`);
квиз снят, и теперь раздел «Связаться» стоит внизу каждой страницы.

и якорь в них отрабатывает не сам: браузер прыгает к нему сразу после

## Проверка цифр 04.09.2026 и почему таблиц взносов нет

Все нормы на страницах видов СРО прошли состязательную проверку: восемнадцать
утверждений, у каждого три независимых проверяющих с прямой задачей
**опровергнуть**, а не согласиться. Что она изменила:

| Было | Стало | Почему |
|---|---|---|
| изыскания — ч. 4 ст. 47 | **ч. 2 ст. 47** | ч. 4 к членству в СРО не относится |
| строители — ч. 2.1 ст. 52 как «обязанность» | **ч. 2 ст. 52** — обязанность, **ч. 2.1** — случай, когда членство НЕ нужно | порог сам по себе ничего не решает: сначала важно, с кем заключён договор |
| срок — ч. 5 ст. 55.6 | **ст. 55.6** без части | проверяющие разошлись: часть 4 или 5 |
| взносы — ч. 10–13 ст. 55.16 | **ст. 55.16** без части | порядок частей не подтверждён |
| снос — ст. 55.31 как «норма о сносе» | снос назван в области деятельности | ст. 55.31 — требования к сносу, а обязанность членства идёт из ст. 52 |
| «участвуете в 44-ФЗ и 223-ФЗ» | «**намерены** заключать договоры конкурентными способами» | взнос в КФ ОДО привязан к заявленному намерению, а не к факту участия |

**Правило, которое из этого следует: номер части статьи ставим только там, где
на нём сошлись все проверяющие.** Неверный номер части выглядит точнее, чем
есть, и подрывает доверие ко всей странице.

### Таблицы взносов: сняты и возвращены в тот же день

Проверка оставила два возражения:

1. **Первый уровень для строителей.** Три проверяющих с высокой уверенностью
   называют 60 млн ₽, а не 90 млн ₽. Значение 90 млн взято из уже сверенных
   данных соседнего проекта (`norma-site/src/config/facts.ts`) со ссылкой на
   435-ФЗ от 04.08.2023.
2. **Порядок частей ст. 55.16** — где строители, а где проектировщики.

Проверить по первоисточнику отсюда нельзя: правовые сайты закрыты сетевой
политикой — `consultant.ru`, `pravo.gov.ru`, `garant`, `cntd`, `sudact` дают
403 на CONNECT. Поэтому таблицы со страниц сняли: цифра, по которой человек
переводит деньги, не может стоять «примерно».

**В тот же день спор разрешился.** Заказчик прислал сохранённые страницы
работающего сайта конкурента по всем трём видам СРО. Все четыре таблицы там
совпали с нашими до рубля, включая спорный первый уровень 90 млн ₽. Итого
за 90 млн: наши данные, уже сверенные данные соседнего проекта и три живые
коммерческие страницы. Против — только память трёх проверяющих. Таблицы
возвращены, `FUNDS_CONFIRMED = true`.

Чего это не отменяет: сайт конкурента подтверждает, что так считает рынок,
но он не первоисточник. Перед выходом на боевой домен таблицы стоит сверить
с действующей редакцией ст. 55.16 ГрК РФ.

**Номера частей ст. 55.16 не проставлены и не будут** — проверяющие в них
разошлись, а страницами конкурента их не подтвердить: он частей не указывает
вовсе. Проверка `pages.mjs` отдельно следит, чтобы они не появились.

## Понятные переходы (25.09.2026)

Заказчик прислал ролик с apple.com («минималистично и понятно, по делу,
переходы красивые») и попросил, чтобы по каждой иконке-стрелке было

главной и все одиннадцать страниц. Что нашлось и что сделано:

- **Карточки услуг расходились со страницами.** Их было восемь со своими

- **Типовые ситуации вели на телефон.** Две из трёх стрелок раздела

- **Висячие предлоги.** «в», «и», «по», «до» и другие короткие слова
  оставались в конце строки, а слово за ними уходило на следующую:
  «Срочное вступление в / СРО». `nbsp()` из `src/lib/typo.ts` склеивает
  их неразрывным пробелом со следующим словом; применяется в заголовках
  и подзаголовках разделов, шапках страниц, карточках услуг и ситуациях.

Вес сайта от этого не вырос: движение — на CSS, новых картинок и шрифтов
нет. На медленном 4G главная целиком ~420 КБ, первый экран на компьютере
~286 КБ (около 2,2 с), на телефоне около 1 с.

## Шапка: выпадающие меню

В шапке два раскрывающихся пункта — «Виды СРО» и «Услуги» — и три обычных:
«Стоимость», «О нас», «FAQ». Навигация целиком лежит в `src/content/nav.ts`
(`MENU`): её перечисляют шапка, мобильное меню и подвал, и расходиться эти
списки не должны. Ссылки двух видов: якорь секции главной (`kind: 'anchor'`)
и папка страницы вида СРО (`kind: 'page'`); адрес собирает `navHref()`, чтобы
со страницы вида якорь получил `../`, а страница — полный путь.

**Пункт меню — название с подсказкой, а не голое слово.** Человек ещё не
знает, «строители» он или «проектировщики», и три названия подряд ему не
помогают. Подсказка под видом — слова из области деятельности на его странице
(у изыскателей пять пунктов на «инженерно-…» не перечисляются целиком: в меню
они занимали четыре строки). Набор `header.mjs` сверяет, что каждое слово
подсказки есть на странице вида — подсказка не может уйти от того, что там
написано. У «Услуг» подсказки ведут по секциям главной: вступление и
сопровождение, специалисты НРС, документы, регионы.

**Три способа ввода — три разных поломки, поэтому логика такая:**

- мышь: открывает наведением, закрывает уходом курсора с задержкой 120 мс;
  между кнопкой и карточкой «мостик» `pt-3`, иначе курсор по дороге к пункту
  выходил за кнопку и меню схлопывалось под рукой. Щелчок по открытому меню
  его не закрывает: намерение щелчка — «открой», а не «переключи»;
- касание (планшет шире 1024px): наведение не считается вовсе — касание
  порождает синтетический mouseenter, меню открывалось от него, а следующий
  click тут же закрывал. Тап переключает, тап мимо закрывает (слушаем
  `pointerdown` на документе: iOS не переводит фокус на кнопку при касании,
  и на `onBlur` там рассчитывать нельзя);
- клавиатура: фокус сам по себе не открывает (иначе на Android тап открывал
  бы фокусом и закрывал щелчком), Enter и пробел переключают, Tab идёт по
  пунктам, уход фокуса и Escape закрывают. Закрытая карточка — `invisible`,
  а не `display: none`: анимация появления остаётся, а ссылки внутри Tab
  всё равно пропускает.

На странице вида его пункт помечен `aria-current="page"` и подсвечен. В
мобильном меню группы не сворачиваются: два лишних тапа ради трёх строк —
плохой размен; заголовок группы набран подписью, пункты под ним с подсказками.

**Панели по содержимому (29.09.2026, разбор интерфейса).** «Виды СРО» —
три строки с миниатюрами тех же кадров, что в списке на первом экране
(поле `thumb` в `TYPES_GROUP`): вид узнаётся по картинке раньше, чем по
названию; те же миниатюры — в мобильном меню. «Услуги» — панель 40rem
в две колонки по четыре: семь пунктов одним столбцом давали карточку
в полэкрана высотой. Латунных точек перед пунктами больше нет ни в шапке,
ни в мобильном меню: у пункта есть название и подсказка, точка ничего
к ним не добавляла и повторяла приём шаблонов. Миниатюры в выпадающем
меню грузятся с первым открытием (`seen`): на телефоне меню шапки скрыто
целиком, картинки в нём не загрузились бы никогда, и `test-site.mjs`
ловил их как битые на страницах, где тех же кадров больше нет.

Ширина: на 1024–1279px пять пунктов с двумя стрелками умещаются с `gap-5`,
с 1280 — `gap-7`; телефон на этих ширинах по-прежнему иконкой. `header.mjs`
проверяет на 1024, 1280 и 1440, что шапка стоит в одну строку.

## Специалисты НРС: ответ на самый частый стопор

Блок `#nrs` стоит сразу за «Документами» — там о специалистах впервые заходит
речь, там же у человека возникает «а у меня их нет». Ответ должен стоять рядом
с вопросом, а не в FAQ внизу страницы.

**Почему отдельная секция, а не строчка в услугах.** В «Услугах» НРС и НОК
стоят карточками «помогу с тем-то» — это ответ на вопрос «что вы делаете».
Вопрос у посетителя другой: «мне вообще можно?». В FAQ ответ был, но короткий
— «разберём вашу ситуацию и обсудим законные варианты», после чего человек
уходил ровно с тем же непониманием, с каким пришёл.

**Порядок внутри блока: сначала норма, потом варианты.** Иначе получается
разговор о способах обойти требование, а требование настоящее: не менее двух
специалистов, сведения о которых включены в национальный реестр, по основному
месту работы (ст. 55.5-1, ст. 55.6 ГрК РФ). Дальше три пути — посмотреть своих,
внести своего в реестр, взять специалиста со стороны.

**Оговорка «чего я делать не буду» — половина смысла блока.** «Аренда»
специалиста и фиктивное трудоустройство — первое, что предлагают посредники;
честнее сказать об этом самому. Там же названы два риска: соответствие
требованиям проверяют не только на входе, и свидетельство о независимой оценке
квалификации действует ограниченное время — истекло, специалист выбывает из
реестра, компания перестаёт соответствовать требованию о двух специалистах.
С 01.10.2026 оговорка, цитата нормы и пояснения к трём путям стоят на странице
услуги «Специалисты НРС», а на главной — короткий блок: требование
со статьёй, три пути названиями и строка-переход «Что нужно для реестра,
«аренда» специалистов и срок НОК» (см. «Правки 01.10.2026 по разбору
дизайнера»): главная повторяла страницу услуги слово в слово.

**Чего в блоке намеренно нет.** Обучения и страхования гражданской
ответственности: в списке услуг заказчика их нет, а подтверждения, что он их
оказывает, у меня тоже нет. Придумывать услугу нельзя — это то же самое, что
придумать цифру. Появится подтверждение — впишем.

Из FAQ на блок ведёт ссылка, в навигации подвала он назван «Специалисты НРС»
(`SECTIONS` в `src/content/nav.ts`; в шапку не поставлен — там помещается
ровно четыре пункта). Отдельного набора проверок у блока нет (упоминавшегося
здесь раньше `nrs.mjs` в репозитории нет): ссылки, плейсхолдеры и вёрстку
блока проверяет общий `scripts/test-site.mjs`.

## География: карта охвата

Последний блок перед подвалом — карта России, где выделены регионы работы,
и список под ней. Список от заказчика, лежит в `src/content/regions.ts`;
контуры — в `src/content/mapData.ts` (сгенерирован `scripts/build-map.py`).

**Цвет регионов подбирался четыре раза.** Насыщенная латунь — огромные
Красноярский край и Якутия перетягивали на себя раздел. Тёплый серый
(26.09.2026) — карта потухла, заказчик попросил «ярче и профессиональнее».
Точечная сетка (28.09.2026) — заказчику не понравилась: «карту вернуть как
было, и сделать её чуть ярче». Сейчас — заливка контуров светлой латунью
(#E0C49A → #CBA671, между `accent-200` и `accent-300`), регион под курсором —
густая латунь (#A57B47 → #86602F), тень под картой прежняя. Точечный вариант
лежит в истории git (коммит «sro-site: виды СРО с миниатюрами, точечная
карта…»).

На телефоне список регионов идёт в поток, как слова в строке: в один
столбик пятнадцать строк тянулись на полтора экрана. Вместо булавок —
латунные кружки: булавка в каждой из пятнадцати строк рябила сильнее карты.

**Почему карта И список, а не что-то одно.** Карта одним взглядом показывает
главное: работа идёт от Петербурга до Якутска. Но на телефоне карта России
шириной 360 пикселей превращает Кострому в пиксель — ни прочитать, ни попасть
пальцем. Поэтому рабочая часть всегда список, а карта показывает охват.
Карта идёт во всю ширину, список — под ней: в две колонки рядом карта
ужималась до трети экрана, а ради неё блок и делался.

**Связь в обе стороны.** Наводите на строку — загорается регион; наводите на
регион — подсвечивается строка. Москва и Московская область — одно пятно,
Петербург с Ленинградской областью тоже, поэтому у пятнадцати строк
тринадцать пятен, и общее пятно подсвечивает обе свои строки. На телефоне
наведения нет, поэтому по региону работает и тап.

**Границы настоящие.** Раньше контур был нарисован от руки по опорным точкам:
узнаваемый силуэт, но показать на нём регион было нечем — только булавка.
Разница не косметическая: закрашенная Якутия сразу показывает масштаб работы,
точка на её месте говорила ровно столько же, сколько точка на Костроме.

Источник границ — [click_that_hood](https://github.com/codeforamerica/click_that_hood)
(Code for America, лицензия MIT), файл `public/data/russia.geojson`: 83 субъекта
с русскими названиями. Крыма в этом наборе нет — данные 2013 года, — его контур
остался прежним, по опорным точкам; они в генераторе. Источник и лицензия
записаны в `public/img/CREDITS.md` по тому же правилу, что и фотографии.

Проекция — равновеликая коническая Альберса (стандартные параллели 52° и 64°,
осевой меридиан 100° в. д.). Она даёт узнаваемую «арку» России, где Калининград
и Чукотка опускаются к краям; линейная проекция по широте и долготе, которая
была здесь раньше, растягивала север и делала страну плоской лентой.

**Генератор — `scripts/build-map.py`.** Файл границ в репозитории не хранится,
скрипт берёт его аргументом:

```bash
curl -sSL -o /tmp/russia.geojson \
  https://raw.githubusercontent.com/codeforamerica/click_that_hood/master/public/data/russia.geojson
python3 scripts/build-map.py /tmp/russia.geojson > src/content/mapData.ts
```

Внутри: проекция, упрощение Дугласа–Пейкера (порог 1,1 пикселя итоговой
карты) и выброс колец мельче 3,5 пикселей — иначе арктические острова дают
крошку, которую всё равно не видно, а весят они как половина Якутии.
Реализация упрощения не рекурсивная намеренно: у Якутии кольца на десятки
тысяч точек, рекурсия упирается в лимит стека.

**Карта грузится отдельным файлом.** Контуры 83 субъектов — 24 КБ после
сжатия, больше половины скрипта главной страницы. Блок стоит перед подвалом,
до него ещё надо долистать, поэтому `mapData.ts` подключается динамическим
`import()` после первой отрисовки: на скорость открытия сайта карта не влияет.
Место под неё держится заранее (`aspect-ratio`), чтобы страница не дёргалась,
когда файл придёт.

Правило заливки — `evenodd`, и это не украшательство: Адыгея лежит внутри
Краснодарского края, Ненецкий округ — внутри Архангельской области. Без
`evenodd` эти дырки залились бы, и анклав пропал бы с карты.

При наведении рядом с городом всплывает подпись региона. Ширина плашки
считается по числу букв — измерить текст в SVG нечем; для одного-двух слов
этого хватает. Плашка прижимается к краям карты и уходит под метку у верхней
кромки: у Крыма и Якутска она иначе обрезалась краем.

Сторожит блок набор `regions.mjs`: полнота списка, наличие контуров, связь
строки с регионом и отсутствие горизонтального скролла на 390px.

## Имя на сайте: компания, не человек

Сайт делался как страница частного специалиста и написан от первого лица.
03.09.2026 заказчик попросил убрать ФИО специалиста и представить компанию из
реквизитов — ООО «БИЗНЕС-ГРУПП». Сделано так:

- компания везде названа одинаково: **ООО «БИЗНЕС-ГРУПП»** (`CONTACTS.brand`),
  подпись под именем — «Вступление в СРО» (`CONTACTS.role`). Это шапка, подвал,
  `<title>`, описание и Open Graph;
- рядом с именем стоит ИНН там, где он к месту: в копирайте подвала и в
  карточке «Реквизиты» полным набором (ИНН, КПП, адрес), в политике и согласии
  — в определении Оператора (`REQUISITES` в `facts.ts`);
- ФИО на странице нет нигде, включая `<title>` и Open Graph;
- фраза «Меня зовут …» из блока «О специалисте» убрана, остальной текст
  первого лица оставлен: он читается как речь специалиста компании и держит
  главное обещание сайта — «работаете с одним человеком, а не с отделом
  продаж». В FAQ «частный специалист» заменён на «один специалист».

Сначала короткий бренд «Бизнес-Групп» стоял в шапке и подвале, а полное имя —
только в копирайте и документах. 03.09.2026 заказчик попросил единое написание:
разнобой читается посетителем как два разных лица, а имя из реестра — то, по
чему компанию проверяют. Длиннее короткого бренда на 6 символов, но помещается
в одну строку и на 1440, и на 360 — проверено на странице. Правило сторожит
набор проверок `naming.mjs`: он сверяет шапку, подвал, `<title>`, Open Graph
и описание, требует ИНН в подвале и запрещает короткое написание без «ООО»
и незаполненные реквизиты в квадратных скобках на экране.

Переводить весь текст на «мы» не стали: это 42 строки в 12 компонентах и
смена характера сайта, а не правка. Если заказчик решит, что компании нужно
«мы», — это отдельная задача.

Банковские реквизиты (счёт, БИК, корр. счёт) в репозиторий не внесены: они
для счетов и договоров, сайту не нужны.

## Подвал

Графит на ступень темнее раздела «Связаться» (`neutral-950` против
`accent-950`): два тёмных блока подряд читаются двумя, а не одним пятном.
Колонки: компания; виды СРО; услуги; разделы главной. Списки берутся
из тех же групп, что и меню шапки (`TYPES_GROUP`, `SERVICES_GROUP`, `MENU`),
разойтись с шапкой они не могут.

Контактов в подвале нет — они в разделе «Связаться» прямо над ним, и второй
раз подряд были бы повтором. Внизу — ИНН, КПП, ОГРН (разметка `<dl>`,
проверки ищут реквизиты в нём) и копирайт с оговоркой про оферту
(п. 2 ст. 437 ГК РФ).

**Раскладка с 29.09.2026** (заказчик: «привести в порядок, структурированно
и профессионально — и на компьютере, и на телефоне»). Было: знак с тремя
строками описания в первой колонке, семь услуг одной колонкой свисали ниже
соседей, на телефоне пятнадцать ссылок шли подряд почти на полтора экрана,
а мессенджеры в «Связаться» разъезжались на две строки (MAX один внизу).
Стало:
- знак и одна строка описания — отдельной строкой, как шапка бланка
  (перечень услуг стоит ниже, повторять его словами незачем);
- три группы ссылок; на компьютере семь услуг — в две колонки по четыре,
  все колонки одной высоты;
- на телефоне группы раскрываются по нажатию: подпись — кнопка
  с `aria-expanded`, на компьютере — просто текст (у колонки, которая всегда
  открыта, `aria-expanded` был бы неправдой); ссылки всегда в разметке;
- реквизиты строкой пар «ИНН 616…», под ними копирайт и оговорка;
- в «Связаться» на телефоне три мессенджера — ровным рядом равной ширины,
  уже 380 px без значков; номер и название компании на 320 px уменьшаются
  и не переносятся (на 320 px номер рвался на «…02-/19», название давало
  горизонтальную прокрутку).

## Первый экран: «лист и окно» (26.09.2026)

Слева — светлая бумага: подпись «Для строительных, проектных
и изыскательских организаций», заголовок «Вступление в СРО под ключ»,
строка о работе, кнопки «Связаться» и «Позвонить» и под ними «Выберите
вид СРО» — три строки со ссылками на страницы видов. Справа — фотография
крана над вечерним городом во всю высоту раздела, край к краю экрана.

**Почему не слайдер.** С 24.09.2026 здесь стоял слайдер из трёх кадров
по семь секунд. В каждый момент на экране была треть предложения, а на
телефоне — только «СРО строителей»; остальные два вида человек видел,
только если дожидался смены. И слайдеру нужны три сильных фотографии,
а у заказчика это превью 820–960 px. Теперь все три вида видны сразу,
а кадр нужен один. Заказчику показаны три макета («один кадр во весь
экран», «лист и окно», «без фото, графит и знак»); «лист и окно» взят
по рекомендации, с его условием: на телефоне должно быть понятно, что и где.
Остальные два макета не сохранены в репозитории — описаны здесь, чтобы
к ним можно было вернуться.

**Список видов — от задачи клиента (01.10.2026).** Заказчик спросил,
лучший ли это вариант; ему показаны три макета рядом с прежним («Оглавление» —
без миниатюр и кружков; «Основание» — три колонки во всю ширину под первым
экраном; «От задачи клиента»), выбран третий. Над списком вопрос «Чем
занимается ваша компания?», строка — занятие словами клиента
(«Строительство, капремонт, снос», «Проектирование», «Инженерные
изыскания» — `ACTIVITY` в `Hero.tsx`), вид СРО — подписью справа
со стрелкой. Человек знает, чем занимается, но не всегда знает, как
называется нужная ему СРО. «Капремонт», а не «ремонт»: для текущего
ремонта членство не требуется. Название вида и адрес берутся из
`SRO_DETAILS` — как у страниц видов и меню. Прежде (до 01.10.2026)
название и подсказка брались из `TYPES_GROUP`. Оформление — строки с линейками
в 1 px, без номеров: три вида СРО — не очередь.

**С 28.09 по 01.10.2026 у каждого вида была миниатюра своего кадра**
(`sro-thumb-*`) и кружок со стрелкой 44 px; нажатый вид разворачивал
миниатюру в шапку своей страницы. Сняты вместе с выбором варианта
«от задачи клиента»: миниатюра 48 px в монохроме не читалась (кран,
чертёж и геодезист сливались в пятна), а три кружка спорили с кружком
кнопки «Связаться». Файлы `sro-thumb-*` остались — они стоят в меню
«Виды СРО». На телефоне строки плотнее (занятие 17,6 px до 380 px
ширины, вид СРО мелко под ним): на 360 × 740 все три видны без прокрутки.

**Наведение на вид меняет кадр (28.09.2026).** Навели курсор на вид СРО
(или пришли на него табом) — в окне первого экрана проступает кадр этого
вида: план этажа у проектировщиков, изыскатели с прибором у изыскателей;
ушёл курсор со списка — вернулся кран. Кадр меняется в том же окне, а не
разворачивается на весь фон: текст остаётся на бумаге, и его контраст
не зависит от кадра (на весь фон понадобилось бы затемнение и белый текст —
это уже другой первый экран). Новый кадр проступает за секунду и чуть
оседает из приближения, как при загрузке. Два дополнительных кадра — около
200 КБ, поэтому грузятся после загрузки страницы, когда браузер свободен,
и только там, где есть наведение и окно от 640 px: на телефоне касание
сразу ведёт на страницу вида. Какую часть кадра показывать в окне —
`FRAME` в `Hero.tsx`. Контраст текста при каждом кадре меряет
`test-hero-contrast.mjs` (наведение на второй и третий вид).

**Кадр вертикальный в вертикальной рамке.** На компьютере он встаёт почти
в родном размере, поэтому резче, чем был во всю ширину экрана: там
из вертикального снимка вырезалась узкая полоса и растягивалась втрое.

**Кадр растворяется в бумаге** (с 26.09.2026): на компьютере гаснет влево,
к тексту, и книзу; на телефоне — книзу. Сначала край был жёстким: цветной
вечерний кадр при растушёвке давал серую полосу на стыке со светлым листом.
Монохром «светлым ключом» (`scripts/monotone.py`) уводит небо в цвет бумаги,
и стык исчезает — так же лежит статуя на примере, который прислал заказчик.

**Появление при загрузке.** Кадр «проявляется», как отпечаток на фотобумаге:
поверх лежит лист цвета бумаги и медленно гаснет, а сам кадр чуть оседает

## Переходы между страницами (26.09.2026)

Старая страница растворяется, новая проявляется, шапка сайта стоит на месте.
С 28.09 по 01.10.2026 миниатюра вида СРО из списка первого экрана
разворачивалась в шапку страницы этого вида (до того туда перетекал большой
кадр с краном — и у проектировщиков кран превращался в чертёж); миниатюр
в списке больше нет, и имя перехода снято. Назад — так же. Длительность 0,4 с: долгий переход между страницами
делает сайт медленным, вся «красота» при этом — внутри страницы.

Сделано одними стилями (`@view-transition` и `::view-transition-*`
в конце `index.css`; шапка сайта — `.vt-header`). Работает в Chrome,
Яндекс Браузере, Edge и Safari 18.2+; Firefox просто открывает страницу,
как раньше. При «уменьшить движение» перехода нет.

**Тонкость.** Страницы собирает скрипт — в html корень пуст. Браузер снимает
новую страницу для перехода при первой отрисовке, и если скрипт к этому
моменту не отработал, переход «проявлял» бы пустой лист. Поэтому скрипт
страницы помечен `blocking="render"` (плагин в `vite.config.ts`), а первая
отрисовка идёт синхронно (`flushSync` в `main.tsx`, `detail.tsx`,
`service.tsx`). Первого показа это не задерживает: до скрипта на странице
и так пусто. Стережёт `scripts/test-site.mjs` — и проверка там с задержкой
скриптов, как на медленной сети: без неё локальный сервер отдавал скрипт
раньше первого кадра, и подделка (сборка без `blocking="render"`) проходила.
С задержкой она падает.

## Широкий экран: макет растёт целиком (01.10.2026, днём; отменено — см. ниже)

Заказчик: «при уменьшении у меня все слова и картинки в серединке — можно
на всю ширину и красиво, или как лучше?». Уменьшенный браузер для страницы
то же, что широкий монитор: окно в CSS-пикселях становится шире, а колонка
текста оставалась 1152 px, и на 1920 занимала 60 % экрана, на 2560 — 45 %.

Растягивать на всю ширину сами строки нельзя — строку в 200 знаков читать
тяжело. Сделано иначе: шире 1440 px растёт корневой кегль, а с ним весь
макет — текст, отступы, колонки, кадры: всё задано в rem. На мониторе
1920 px сайт выглядит так же, как на ноутбуке 1440, только крупнее,
и занимает ту же долю экрана.

Формула (`html` в `index.css`):
`max(100%, min(100vw / 90, 100vh / 45))`.

- `100vw / 90` — макет растёт вместе с шириной окна: колонка 72rem всегда
  80 % окна.
- `100vh / 45` — предел по высоте окна. Первая версия ограничивала рост
  полутора разами (`clamp(…, 150%)`), и заказчик прислал снимок браузера,
  уменьшенного до 25 %: дальше предела сайт снова стоял посередине. Высота
  при уменьшении растёт вместе с шириной, поэтому предел по высоте
  уменьшению не мешает: на 25 % страница выглядит так же, как на 100 %.
  Зато он держит сверхширокий монитор (21:9, 3440×1440): там по ширине
  буквы стали бы плакатными, а по высоте рост останавливается, и макет
  стоит по центру на бумажном поле.
- `max(100%, …)` — меньше настройки посетителя кегль не бывает: на телефоне
  и ноутбуке до 1440 px не изменилось ничего. Проверено снимками до и после
  по пикселям: все страницы на 390 и 1440 px совпали полностью (разница
  только в цвете подписи-перехода, см. ниже).

- Кегли и мелкие размеры, заданные в px (`text-[15px]` и др.), переведены
  в rem — иначе они не росли бы вместе с остальным. Новые размеры тоже
  писать в rem.
- Привязка кадров к колонке (см. «Правки 28.09.2026: широкий экран…» выше)
  теперь нужна только окну шире 5:2 — там рост остановлен высотой и по бокам
  остаётся поле. Условие — вариант Tailwind
  `[@media(min-width:1440px)_and_(min-aspect-ratio:5/2)]:` в разметке
  (выводится после `lg:` и перебивает его) и такой же `@media` для масок
  в `index.css`; расстояния в rem (56,25rem от центра).
- Настройка размера шрифта в браузере посетителя работает (проценты,
  а не px), приближение тоже: приближение уменьшает окно в CSS-пикселях,
  и кегль возвращается к обычному.

Замер на 1920 нашёл одно: серая подпись «СРО строителей» на первом
экране при наведении на соседний вид лежала на более тёмной части кадра
(кадр иначе обрезан) и давала 4,47:1 при норме 4,5. Серые подписи-переходы
(`GoTo` tone `muted`) теперь `neutral-700`: стало 6,24:1.

Стережёт `test-site.mjs`: ширина 1920 добавлена в обход всех страниц,
отдельно проверяются корневой кегль и колонка 72rem на 1440×900,
1920×1000, 2560×1300 и 5760×3200 (браузер, уменьшенный до 25 %; колонка
обязана занимать 80 % окна) и на 3440×1300 (сверхширокий: рост остановлен,
кадры привязаны к колонке). `test-hero-contrast.mjs` меряет и 1920.

## Старая фотография после заливки: отпечатки картинок (01.10.2026)

Заказчик залил v6 и увидел на первом экране цветной дневной кадр с кранами —

Причина — имя файла: кадр первого экрана с 17.09 лежит под одним и тем же

с очисткой кеша (Ctrl+F5) или открыть сайт в режиме инкогнито.

### Смена без рывка (01.10.2026, поздний вечер)

Заказчик: «когда переходишь, немного подёргивает — чтобы плавно всё

  кнопками; при нажатии React менял элемент целиком, и рамка, тень,
  цвет значка и «Открыть» возникали скачком — переходу не из чего было
  идти. Теперь каждая карточка — ссылка на свою страницу и при выборе

  всегда. Серая вспышка касания на телефоне снята, карточка чуть
  проседает под пальцем.

  и сквозь них проступал тёмный фон — мигание. Теперь новый кадр
  проступает поверх прежнего, прежний держится под ним до конца.
- **Кадр мог проявиться рывком посреди перехода**, если ещё
  не раскодирован: смена теперь начинается после `img.decode()`, слои
  кадров заведены заранее (`will-change`).

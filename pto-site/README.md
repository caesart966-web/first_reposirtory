# Сайт компании: документальное сопровождение строительства

Статический сайт: 18 страниц, из них 13 — отдельные страницы услуг под поисковый трафик.
Никакой CMS, базы данных и админки. Страницы **собираются скриптом на Python** из файлов
с текстами, поэтому шапку, подвал и оформление правят в одном месте, а не в тринадцати.

## 1. С чего начать: 5 обязательных правок

Сейчас в сайте стоят **временные данные-заглушки**. Пока их не заменить, сайт публиковать нельзя.
Всё это — в одном файле `data/site.json`:

| Что заменить | Где именно | Сейчас стоит |
|---|---|---|
| Название компании | `company.name`, `company.legal_name` | «Бюро ПТО», «ООО «Бюро ПТО»» |
| Телефон | `contacts.phone_display` и `contacts.phone_href` | +7 (900) 000-00-00 |
| Почта и Telegram | `contacts.email`, `contacts.telegram_url`, `contacts.telegram_display` | example |
| Адрес сайта | `base_url` | `https://example.com` |
| Логотип | файл `assets/img/logo.svg` | нарисованная заглушка |

**Важно про телефон.** Их два поля, и это не ошибка:
- `phone_display` — как телефон **выглядит** на экране: `+7 (999) 123-45-67`
- `phone_href` — как по нему **звонят**, только цифры и плюс: `+79991234567`

Если перепутать, кнопка «Позвонить» на телефоне работать не будет.

**Про логотип.** Замените `assets/img/logo.svg` своим файлом. Если у вас PNG, положите его как
`assets/img/logo.png` и в файле `templates/base.html` поменяйте два раза `logo.svg` на `logo.png`
(логотип встречается в шапке и в подвале).

После правок — пересоберите сайт (пункт 2).

## 2. Как запустить и посмотреть сайт

Нужен только Python 3.8 или новее. Ничего устанавливать не надо: ни npm, ни библиотек.

Собрать сайт:

```bash
cd pto-site
python3 build.py
```

Готовый сайт появится в папке `dist/`. **Именно её содержимое и заливается на хостинг.**

Собрать и сразу посмотреть в браузере:

```bash
python3 build.py --serve
```

Откройте `http://localhost:8000`. Чтобы остановить — `Ctrl+C`.

> Открывать файлы из `dist/` двойным щелчком не надо — ссылки и стили не подхватятся.
> Смотрите только через `--serve`.

При каждой сборке папка `dist/` **удаляется и создаётся заново**. Никогда не правьте файлы
внутри `dist/` — правки затрутся при следующей сборке. Правят только `data/`, `templates/`,
`assets/`.

```

├── build.py                  ← генератор: собирает сайт
├── genmedia.py               ← рисует картинки-заглушки (постер, картинка для мессенджеров)
│
├── data/                     ← ВСЕ ТЕКСТЫ ЗДЕСЬ
│   ├── site.json             ← контакты, главная, о компании, общие блоки
│   └── services.json         ← 13 услуг, по блоку на каждую
│
├── templates/
│   └── base.html             ← каркас страницы: шапка, подвал, теги <head>
│
├── assets/                   ← общие файлы, одинаковые для всех страниц
│   ├── style.css             ← всё оформление сайта, один файл
│   ├── app.js                ← меню, видео, отправка формы, один файл
│   ├── config.example.js     ← образец настроек заявок
│   ├── config.js             ← ВАШИ настройки. В git не попадает, создаёте сами
│   ├── img/                  ← логотип, иконка, картинка для мессенджеров
│   └── media/                ← видео и постер первого экрана

├── serverless/
│   └── telegram-worker.js    ← обработчик заявок (чтобы токен не лежал на сайте)
│
└── dist/                     ← ГОТОВЫЙ САЙТ. Создаётся автоматически, руками не трогать
```

## 4. Как устроен генератор

Идея простая: **тексты отдельно, оформление отдельно**.

```
data/site.json     ┐
data/services.json ├──→  build.py  ──→  dist/  (готовые HTML-страницы)
templates/base.html┘
```

`build.py` берёт каркас `templates/base.html`, подставляет в него тексты из `data/` и
раскладывает результат по папкам. Одна услуга из `services.json` = одна папка в `dist/uslugi/`.

В каркасе есть места вида `{{title}}`, `{{phone_display}}`, `{{body}}` — это «окошки»,
куда генератор вставляет данные. Всё, что вне окошек — общая для всех страниц вёрстка.

**Отсюда главное свойство:** поправили телефон в шапке `templates/base.html` — он поменялся
сразу на всех 18 страницах. Никаких «пройтись по всем страницам и заменить».

Что генератор создаёт за один запуск:

- `/` — главная
- `/uslugi/` — все услуги списком
- `/uslugi/<адрес-услуги>/` — 13 страниц услуг
- `/o-kompanii/`, `/kontakty/`
- `/404.html` — страница «не найдено»
- `/sitemap.xml` и `/robots.txt` — карта сайта для поисковиков
- копию папки `assets/`

Заодно генератор **проверяет сам себя** и ругается, если:
- у двух страниц совпал `title` или `description` (это вредит поиску);
- одна услуга ссылается на несуществующую смежную;
- два адреса страниц совпали.

## 5. Как поменять тексты

Все тексты — в двух файлах в папке `data/`. Это формат JSON: список «ключ»: «значение».

**Правила, чтобы ничего не сломать:**

1. Меняйте только текст **внутри кавычек**. Названия слева от двоеточия не трогайте.
2. Кавычки, двоеточия и запятые за пределами текста должны остаться на месте.
3. Внутри текста нельзя использовать прямые кавычки `"`. Пишите «ёлочки» — они и типографски правильнее.
4. После последнего элемента списка запятая не ставится.

Проверить, что файл не сломан, можно так — если ошибок нет, команда просто промолчит:

```bash
python3 -c "import json;json.load(open('data/site.json',encoding='utf-8'))"
```

Если сломали — генератор при запуске скажет номер строки с ошибкой.

**Что где лежит в `site.json`:**

| Блок | За что отвечает |
|---|---|
| `company`, `contacts` | название, телефон, почта, режим работы |
| `hero` | первый экран главной: заголовок, подзаголовок, три пункта, кнопки |
| `offer` | блок «Что мы делаем» и три цифры под ним |
| `why` | блок «Почему к нам» (он же на странице «О компании») |
| `process` | блок «Как мы работаем», этапы |
| `faq` | вопросы и ответы на главной |
| `about`, `contacts_page`, `services_index` | тексты соответствующих страниц |
| `groups` | четыре группы, по которым разложены услуги |
| `form` | подписи и сообщения формы заявки |

## 6. Как добавить новую услугу

Это делается **без единой строчки HTML**: дописать блок в файл и запустить сборку.

**Шаг 1.** Откройте `data/services.json`. Скопируйте любой существующий блок целиком —
от `{` до `}` — и вставьте его в конец списка, перед закрывающей `]`. Не забудьте запятую
после предыдущего блока.

**Шаг 2.** Заполните поля:

| Поле | Что это | Пример |
|---|---|---|
| `slug` | адрес страницы, латиницей, без цифр и пробелов | `"tehnadzor"` → `/uslugi/tehnadzor/` |
| `group` | к какой из четырёх групп относится | `"inzhiniring"` |
| `nav_title` | название в меню, подвале и списках | `"Технический надзор"` |
| `short` | одна строка под названием в списке услуг | |
| `h1` | заголовок на самой странице | |
| `title` | заголовок вкладки браузера и ссылки в поиске, до 70 знаков | |
| `description` | описание в поиске, 120–180 знаков | |
| `lead` | вводный абзац под заголовком | |
| `when` | список «когда нужна эта услуга» | 3–5 пунктов |
| `includes` | список «что входит в работу» | 5–8 пунктов |
| `audience` | список «для кого» | 3–4 пункта |
| `steps` | этапы работы, у каждого `title` и `text` | ровно 6 |
| `faq` | вопросы и ответы, у каждого `q` и `a` | 3–5 |
| `related` | адреса смежных услуг для перелинковки | `["geodeziya", "zos"]` |
| `cities` | города, пока оставьте `[]` | |

Допустимые значения `group`: `proektirovanie`, `ispolnitelnaya`, `inzhiniring`, `sdacha`.
Список групп — в `data/site.json`, блок `groups`.

**Шаг 3.** Пересоберите:

```bash
python3 build.py
```

Готово. Новая услуга сама появится: на главной в своей группе, в списке `/uslugi/`,
в подвале всех страниц, в выпадающем списке формы заявки, в `sitemap.xml` и в блоках
«Смежные услуги» тех страниц, где вы её указали в `related`.

> Важно: `title` и `description` должны быть **уникальными**. Если скопировали блок и забыли
> их переписать, генератор при сборке напишет `ВНИМАНИЕ: одинаковый title на страницах…`.
> Не игнорируйте это сообщение — дубли мешают попасть в поиск.

## 7. Как добавить страницу под город

Это **второй этап**, когда станет понятно, откуда идут обращения. Механизм уже готов,
включается одной правкой данных.

У каждой услуги есть поле `cities`. Сейчас оно пустое: `"cities": []`.
Чтобы сделать страницу «Исполнительная документация в Москве», впишите туда город:

```json
"cities": [
  {
    "slug": "moskva",
    "name": "Москва",
    "case_in": "в Москве"
  }
]
```

Пересоберите — появится страница `/uslugi/ispolnitelnaya-dokumentatsiya/moskva/`
со своим заголовком, своим `title`, своими «хлебными крошками» и записью в `sitemap.xml`.

Заголовок соберётся сам: `h1 услуги` + `case_in` → «Исполнительная документация под ключ в Москве».

Если для города нужен особый текст, добавьте в тот же блок любое из полей —
они перебьют автоматические: `h1`, `title`, `description`, `lead`.

```json
{
  "slug": "spb",
  "name": "Санкт-Петербург",
  "case_in": "в Санкт-Петербурге",
  "lead": "Свой вводный абзац для Петербурга, с местной спецификой."
}
```

> Совет: не делайте города «пачкой» ради количества. Страница, отличающаяся от основной
> только названием города, поисковиками считается малополезной. Делайте по одной под те
> регионы, откуда реально идут заявки, и дописывайте туда живой местный текст.

## 8. Видео на первом экране

### Самый простой способ — одна команда

Скачали ролик, выполнили:

```bash
cd pto-site
bash tools/prepare-hero-video.sh ~/Downloads/ваш-ролик.mp4
python3 build.py
```

Скрипт сам обрежет до 15 секунд, уберёт звук, сожмёт, сделает второй файл
в формате webm и вытащит постер. Всё разложит по местам. Нужен установленный
ffmpeg — как поставить, написано в шапке самого скрипта.

Другую длительность можно задать вторым аргументом:

```bash
bash tools/prepare-hero-video.sh ~/Downloads/ролик.mp4 12
```

### Если хочется вручную

**Куда класть файлы:** папка `assets/media/`

| Файл | Что это | Обязателен |
|---|---|---|
| `hero-poster.jpg` (или `.webp`) | статичный кадр: видно сразу и вместо видео на телефонах | желателен |
| `hero.mp4` | видео, формат H.264 | нет |
| `hero.webm` | то же видео в формате webm, грузится быстрее | нет |

Генератор ищет постер сам, в таком порядке: `.webp`, `.jpg`, `.png`, и только
если ничего нет — берёт нарисованную заглушку `hero-poster-placeholder.png`.
Поэтому положить свой файл достаточно, править настройки не нужно.

Видео нет — сайт не ломается: показывается постер. Положили `hero.mp4`,
пересобрали — видео заработало само.

Имена файлов при желании меняются в `data/site.json`, блок `hero`.
Если оставить там пустые строки `""`, видео не будет вообще.

**Требования к видео:** не больше 4–5 МБ, без звука, 10–20 секунд с плавной петлёй.

Команды, если делать без скрипта:

```bash
ffmpeg -i исходник.mp4 -t 15 -an -vf "scale=1920:-2" -c:v libx264 -crf 30 -preset slow hero.mp4
ffmpeg -i исходник.mp4 -t 15 -an -vf "scale=1920:-2" -c:v libvpx-vp9 -crf 38 -b:v 0 hero.webm
ffmpeg -i hero.mp4 -vframes 1 -q:v 3 hero-poster.jpg
```

Проверьте вес: `ls -lh hero.*`. Если mp4 больше 5 МБ — поднимите `-crf` (например до 33).

**Как это ведёт себя (проверено в браузере):**

| Ситуация | Что происходит |
|---|---|
| Компьютер, широкий экран | грузится и играет видео |
| Телефон и планшет до 900px | видео **не скачивается вообще**, показывается постер |
| Включён режим экономии трафика | видео не скачивается, показывается постер |
| В системе отключены анимации | видео не скачивается, показывается постер |
| Видео ещё не загрузилось | виден постер, текст читается сразу |

Видео начинает грузиться только **после** полной загрузки страницы, поэтому первый экран
не ждёт видео и появляется мгновенно.

## 9. Заявки в Telegram

Форма отправляет заявку в Telegram. Есть два способа, выбирать вам.

### Сначала общее: заводим бота

1. В Telegram найдите **@BotFather**, отправьте `/newbot`, придумайте имя.
   В ответ придёт **токен** — длинная строка вида `7123456789:AAF...`
2. Создайте группу для заявок и добавьте туда бота (или пишите себе в личку).
3. Узнайте **chat_id**: добавьте в группу бота **@getmyid_bot** — он пришлёт номер.
   У групп он отрицательный, например `-1001234567890`.

### Вариант А — рекомендуемый: токен не лежит на сайте

Сайт остаётся статическим, но заявка уходит не напрямую в Telegram, а на маленький
бесплатный обработчик, где и хранится токен. Настраивается один раз, минут за десять.

1. Зарегистрируйтесь на [dash.cloudflare.com](https://dash.cloudflare.com) (бесплатно).
2. Workers & Pages → Create → Worker → назовите `zayavki` → Deploy.
3. Нажмите Edit code, удалите содержимое и вставьте файл `serverless/telegram-worker.js`
   из этой папки. Deploy.
4. Settings → Variables and Secrets → добавьте три штуки:
   - `BOT_TOKEN` — токен от BotFather (тип Secret)
   - `CHAT_ID` — номер чата (тип Secret)
   - `ALLOW_ORIGIN` — адрес вашего сайта, например `https://вашсайт.ру`
5. Скопируйте адрес воркера — вида `https://zayavki.ваш-логин.workers.dev`
6. Скопируйте `assets/config.example.js` в `assets/config.js` и впишите этот адрес:

```js
window.SITE_CONFIG = {
  formEndpoint: 'https://zayavki.ваш-логин.workers.dev',
  telegram: { botToken: '', chatId: '' }
};
```

Готово. В коде сайта токена нет — там только адрес обработчика.

### Вариант Б — быстрый: без всякого сервера

Заявка уходит из браузера прямо в Telegram. Настраивается за минуту:

```js
window.SITE_CONFIG = {
  formEndpoint: '',
  telegram: { botToken: '7123456789:AAF...', chatId: '-1001234567890' }
};
```

**Честно о минусе:** на чистой статике браузер посетителя сам обращается к Telegram, а значит
токен обязан быть в коде страницы. Любой, кто откроет исходный код сайта, его увидит. Чем это
грозит: посторонний может слать сообщения в ваш чат заявок от имени бота и читать сообщения,
адресованные боту. Доступа к вашей переписке в Telegram это не даёт.

Так что вариант Б годится, чтобы **запуститься сегодня** и не терять заявки. Как появится
полчаса — переходите на вариант А: меняется только `config.js`, сайт трогать не нужно.

### Важно про config.js

- Файл `assets/config.js` **не попадает в git** (он в `.gitignore`) — токен не утечёт в репозиторий.
- Поэтому при выкладке на хостинг его надо **залить руками** отдельно.
- Без этого файла форма покажет посетителю сообщение об ошибке с вашим телефоном и Telegram —
  то есть заявка всё равно не потеряется, человек позвонит.
- Проверить, что всё работает: откройте сайт, отправьте тестовую заявку, посмотрите в чат.

## 10. Как выложить на хостинг

### Обычный хостинг по FTP — основной вариант

1. `python3 build.py`
2. Подключитесь к хостингу по FTP (FileZilla или любой другой клиент).
3. Скопируйте **содержимое папки `dist/`** (не саму папку!) в корневую папку сайта —
   обычно она называется `public_html`, `www` или `htdocs`.
4. Отдельно залейте `assets/config.js` в папку `assets/` — в git его нет, значит и в `dist/`
   он попадает только если вы его создали локально.
5. Откройте сайт и отправьте тестовую заявку.

При обновлении текстов: пересобрали → залили `dist/` заново с заменой файлов.

### Превью для показа заказчику

Сайт уже публикуется автоматически по адресу:

**https://caesart966-web.github.io/first_reposirtory/pto/**

Это делает workflow `.github/workflows/deploy-orders-app.yml`: при каждом изменении
в папке `pto-site/` в ветке `main` он пересобирает сайт и выкладывает его рядом
с «Заказами» и «Строй-Героем».

Превью собирается с тремя флагами — они нужны только для показа, боевую сборку
не трогают:

```bash
python3 build.py --base-path /first_reposirtory/pto \
                 --base-url https://caesart966-web.github.io \
                 --noindex
```

| Флаг | Зачем |
|---|---|
| `--base-path` | сайт лежит в подпапке, а не в корне домена — без этого не найдутся стили и ссылки |
| `--base-url` | правильные адреса в `canonical` и `sitemap.xml` |
| `--noindex` | закрывает превью от поисковиков, чтобы демо с тестовым телефоном не попало в выдачу |

Форма заявки в превью **не отправляет** ничего: файла `assets/config.js` с токеном
в репозитории нет. Посетитель увидит сообщение с телефоном и Telegram. Для показа
заказчику это нормально.

Когда дойдёт до боевого запуска на своём домене — собирайте **без флагов**,
обычным `python3 build.py`.

### GitHub Pages как основной хостинг

Учтите: в этом репозитории GitHub Pages **занят** — там же лежат «Заказы» и «Строй-Герой»,
а Pages на репозиторий бывает только один, поэтому сайт и живёт в подпапке `/pto/`.
Для коммерческого сайта под поиск этого мало. Пути:

- **Отдельный репозиторий** (рекомендуется). Создайте новый репозиторий, положите туда
  содержимое папки `pto-site/`, включите Pages. Если сайт будет открываться по адресу
  вида `логин.github.io/имя-репозитория/`, обязательно впишите это в `data/site.json`:

  ```json
  "base_url": "https://логин.github.io",
  "base_path": "/имя-репозитория"
  ```

  Без `base_path` все ссылки и картинки на таком адресе не найдутся.
  Для своего домена `base_path` оставьте пустым: `""`.

- **Добавить в существующий workflow.** Тогда сайт ляжет в подпапку общего Pages-сайта,
  и `base_path` тоже придётся заполнить. Способ рабочий, но адрес получится некрасивый —
  для коммерческого сайта, который должен собирать трафик из поиска, лучше свой домен.

Для продвижения в поиске в любом случае нужен **свой домен**: адрес на `github.io`
для этого не годится.

## 11. Что уже сделано для поисковиков

Это то, ради чего сайт собирается генератором, а не пишется руками.

- **У каждой из 18 страниц свои `title`, `description` и `H1`.** Дублей нет, генератор
  проверяет это при каждой сборке и предупреждает.
- **13 отдельных страниц услуг** — каждая под свою группу запросов. Это и есть механика
  сбора трафика: одна страница = один смысловой запрос.
- **Человекочитаемые адреса** латиницей, без цифр и параметров: `/uslugi/zashchita-obemov-ks2-ks3/`.
- **Разметка Schema.org**: `Organization` на всех страницах, `Service` — на страницах услуг,
  `FAQPage` — везде, где есть блок вопросов, плюс `BreadcrumbList` и `ItemList`.
  Благодаря `FAQPage` вопросы могут показываться прямо в выдаче.
- **Open Graph** — ссылка в мессенджере разворачивается с заголовком, описанием и картинкой.
- **`sitemap.xml` и `robots.txt`** генерируются автоматически при каждой сборке.
- **Перелинковка**: блок «Смежные услуги» на каждой странице услуги плюс полный список
  услуг в подвале всех страниц.
- **Заголовки в иерархии**: ровно один `H1` на страницу, дальше `H2` и `H3`.
- **Скорость**: ни одной сторонней библиотеки, ни одного стороннего шрифта, один файл CSS
  и один JS. Видео не задерживает первый экран и не грузится на телефонах.

**Что сделать вам после публикации:**

1. Подключить домен и настроить HTTPS (у хостинга обычно есть бесплатный сертификат).
2. Добавить сайт в [Яндекс.Вебмастер](https://webmaster.yandex.ru) и
   [Google Search Console](https://search.google.com/search-console), скормить им `sitemap.xml`.
3. Поставить счётчик Яндекс.Метрики — код вставляется в `templates/base.html` перед `</body>`,
   один раз, и появится на всех страницах.
4. Заполнить карточку в Яндекс.Бизнесе.
5. Заменить картинку для мессенджеров `assets/img/og-default.png` на нормальную —
   сейчас это заглушка без текста. Размер 1200×630.

## 12. Частые ошибки

| Симптом | Причина и что делать |
|---|---|
| Сайт открылся без оформления, «голый текст» | Открыли файл из `dist/` двойным щелчком. Запускайте `python3 build.py --serve` |
| На хостинге не видно картинок и стилей | Скопировали папку `dist`, а надо было **её содержимое**. Либо сайт лежит в подпапке — заполните `base_path` |
| Форма пишет «Не удалось отправить» | Нет файла `assets/config.js` на хостинге или в нём неверный токен. См. пункт 9 |
| Кнопка «Позвонить» не звонит | В `phone_href` попали скобки и пробелы. Там должны быть только цифры и `+` |
| `json.decoder.JSONDecodeError` при сборке | Сломана запятая или кавычка в `data/*.json`. В сообщении указан номер строки |
| `ВНИМАНИЕ: одинаковый title` | Скопировали услугу и не переписали `title`/`description`. Перепишите |
| `услуга ссылается на несуществующую` | В `related` указан адрес услуги, которой нет. Проверьте `slug` |
| Правки не видны | Забыли пересобрать: `python3 build.py`. Или смотрите старую вкладку — обновите страницу |

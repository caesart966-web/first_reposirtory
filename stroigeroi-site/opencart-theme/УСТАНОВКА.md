# Как поставить новую тему на stroigeroi.ru

Инструкция рассчитана на то, что её читают с доступом к хостингу reg.ru
и к phpMyAdmin. Команд для Shell-клиента здесь нет — всё делается
файловым менеджером и одним запросом в базу.

**Главное, что нужно знать сразу:** старая тема `stroyhero` не трогается
вообще. Наша ложится рядом отдельной папкой, а переключение между ними —
это одно значение в базе. Откат занимает секунду и не требует ничего
восстанавливать.

---

## Что куда кладётся

Из папки `opencart-theme/` в корень сайта
`/var/www/u2934771/data/www/stroigeroi.ru/`, с сохранением структуры:

| Что | Куда |
|---|---|
| `catalog/view/theme/stroigeroi2026/` | новая папка, её раньше не было |
| `catalog/controller/information/callback.php` | новый файл |
| `catalog/controller/information/calculator.php` | новый файл |
| `robots.txt` | в корень сайта, рядом с `index.php`. Отдельным шагом — см. «6. robots.txt и карта сайта» в конце. Если файл там уже есть, **сначала сохраните старый** |
| `htaccess-скорость.txt` | **не копируется и пока не ставится.** Замер 23.09.2026 показал, что почти всё из него сервер уже делает сам, — см. «8. Сжатие и кеш» в конце |

**Ни один существующий файл темы не перезаписывается.** Если файловый
менеджер спросит про замену — значит, что-то пошло не так, остановитесь.
Единственное исключение — `robots.txt`: он лежит в корне сайта, и там
уже может быть чужой. Старый сохраните, прежде чем класть новый.

## Шаг 1. Резервная копия

Даже при том, что мы ничего не перезаписываем.

ispmanager → **Резервные копии** → создать копию сайта и базы. Дождитесь,
пока она появится в списке. Это пять минут, и они окупаются один раз
из ста — но окупаются полностью.

## Шаг 2. Залить файлы

ispmanager → **Менеджер файлов** → перейти в
`/var/www/u2934771/data/www/stroigeroi.ru/`.

Проще всего залить одним архивом:

1. Заархивируйте папку `opencart-theme` целиком (её содержимое, не саму папку).
2. Загрузите архив в корень сайта.
3. Распакуйте прямо там.
4. Удалите архив.

Проверьте, что появилось: в `catalog/view/theme/` теперь три папки —
`default`, `stroyhero` и `stroigeroi2026`.

### Семь шаблонов от старой темы

На сайте стоят модификации (OCFilter, вход во всплывающем окне, «поделиться
корзиной»). Они вставляют в страницы куски разметки и требуют шаблонов,
которых у OpenCart нет в принципе — их принесли с собой сами модификации,
и лежат они только в `stroyhero`. Подмены на `default` для них не бывает:
подменять нечем. Если их не скопировать, сайт после переключения темы
отдаёт белую страницу с `Fatal error` — так и случилось при первом
переключении.

Скопируйте из `stroyhero` в `stroigeroi2026` семь файлов:

```
common/popup_login.twig
common/breadcrumbs.twig
common/categories_aside.twig
checkout/cart_share.twig
product/product_card.twig
extension/module/ocfilter/filter_cats.twig
extension/module/ocfilter/filter_store.twig
```

Через Shell одной строкой (из корня сайта):

```
cd catalog/view/theme
for f in common/popup_login common/breadcrumbs common/categories_aside \
         checkout/cart_share product/product_card \
         extension/module/ocfilter/filter_cats \
         extension/module/ocfilter/filter_store; do
  mkdir -p "stroigeroi2026/template/$(dirname $f)"
  cp -n "stroyhero/template/$f.twig" "stroigeroi2026/template/$f.twig"
done
```

**Папку `stroyhero` не удаляйте** — она единственный источник этих семи
файлов. И держите её на месте ещё и как путь отката: Шаг «Откат» ниже
возвращает сайт именно на неё.

## Шаг 3. Очистить кеш шаблонов

**Этот шаг пропускают чаще всего, и потом кажется, что тема не работает.**

В настройках сайта включён кеш шаблонов (`developer_theme = 1`). Пока он
не очищен, движок продолжает показывать старое.

Менеджер файлов → `system/storage/cache/` → выделить **всё содержимое
папки** и удалить. Саму папку `cache` удалять нельзя.

## Шаг 4. Переключить тему

Два способа, любой на выбор.

### Способ А: через админку

Админка → **Расширения** → выбрать тип расширения **Темы** → у «Theme
Default» нажать **Изменить** → в поле **Каталог темы** выбрать
`stroigeroi2026` → **Сохранить**.

### Способ Б: через phpMyAdmin

phpMyAdmin → слева выбрать базу `u2934771_default` → вкладка **SQL**:

```sql
UPDATE oc_setting
SET `value` = 'stroigeroi2026'
WHERE `key` = 'theme_default_directory';
```

Должно измениться **ровно 1 строка**. Если ноль — запрос ушёл не в ту базу.

## Шаг 4½. Проверить, что шаблоны не переопределены в базе

Один запрос, занимает полминуты, но избавляет от очень неприятного
разбирательства.

У OpenCart есть встроенный редактор шаблонов (Дизайн → Редактор шаблонов).
Всё, что правили через него, хранится **в базе, в таблице `oc_theme`**,
и движок берёт версию оттуда, **игнорируя файл на диске**. Если прежний
разработчик им пользовался, вы будете менять файлы и не понимать, почему
на сайте ничего не меняется.

phpMyAdmin → база `u2934771_default` → вкладка **SQL**:

```sql
SELECT theme, route FROM oc_theme ORDER BY theme, route;
```

- **Пусто** — отлично, ничего не переопределено, идём дальше.
- **Есть строки со `stroyhero`** — они относятся к старой теме и нашей
  не мешают. Трогать не нужно.
- **Есть строки со `stroigeroi2026`** — этого быть не может при первой
  установке; напишите мне.

**Запомните на будущее:** если однажды понадобится поправить шаблон,
правьте файл и перезаливайте его. Как только вы сохраните шаблон через
редактор в админке, файл на диске перестанет действовать для этой
страницы — навсегда, пока запись не удалят из `oc_theme`.

## Шаг 5. Проверить

Откройте с обновлением по Ctrl+F5:

| Страница | Что смотреть |
|---|---|
| `https://stroigeroi.ru` | красно-белая шапка, наш логотип, полоса разделов |
| `https://stroigeroi.ru/index.php?route=product/category&path=79` | список товаров плиткой |
| любой товар | фотография, цена, кнопка «В корзину» |
| `index.php?route=checkout/cart` | корзина |
| `index.php?route=information/contact` | три магазина с картами |
| `index.php?route=information/calculator` | калькулятор |

Если что-то выглядит поломанным — сначала ещё раз очистите кеш (шаг 3).
В девяти случаях из десяти дело в нём.

## Откат

```sql
UPDATE oc_setting
SET `value` = 'stroyhero'
WHERE `key` = 'theme_default_directory';
```

Плюс очистить кеш. Сайт вернётся к прежнему виду полностью. Файлы новой
темы при этом можно не трогать — они просто лежат и ни на что не влияют.

## Что настроить после переключения

Пока это не сделано, сайт работает, но часть ссылок не показывается —
нарочно: ссылка в никуда хуже её отсутствия.

### 1. Почта магазина

Админка → **Система** → **Настройки** → изменить магазин → вкладка
**Магазин**, поле **E-Mail**.

Сейчас там стоит `andrey@tsvetkov-design.ru` — почта прежнего
разработчика. С неё уходят все письма сайта, и на неё же приходят
все заявки. Заменить обязательно.

### 2. Капча на регистрации и восстановлении пароля

**Система** → **Настройки** → вкладка **Опция** → раздел **Капча**.

Без неё повторится история старого сайта: роботы использовали эти две
формы как рассыльщик и отправили 13 389 писем.

### 3. Текстовые страницы

**Каталог** → **Информация** → создать страницы: «Доставка и оплата»,
«Политика обработки персональных данных», «Пользовательское соглашение».
Тексты политики и соглашения готовы — в `stroigeroi-site/policy.html`
и `terms.html`, нужно только подставить реквизиты.

Созданные страницы сами появятся в подвале — там стоит цикл по всем
страницам, руками вписывать ничего не нужно.

А вот ссылки «Доставка» в верхнем меню и «политика» в галочке согласия
знают номер страницы. Узнайте его: откройте страницу на редактирование,
в адресной строке будет `information_id=NN`. Затем в папке проекта:

```
python3 tools/set-page-ids.py --delivery NN --policy MM
```

и перезалейте изменённые шаблоны. Проверить, что стоит сейчас:

```
python3 tools/set-page-ids.py --show
```

### 4. Товарные подборки на главной

Главная показывает две подборки — обе приходят модулями.

**Дизайн** → **Макеты** → **Home** → добавить модули в позиции
`Content Top` и `Content Bottom`. Подойдут «Рекомендуемые» (Featured),
«Новинки» (Latest), «Хиты продаж» (Bestseller), «Акции» (Special) —
для всех четырёх у темы есть своя разметка, они будут выглядеть как
карусели из макета.

Название подборки задаётся там же, при добавлении модуля. Если его
не задать, заголовок просто не выведется.

**Куда модули встают, а куда нет.** `Content Top` и `Content Bottom`
выводятся на всех страницах темы. Левая колонка (`Column Left`) — только
на страницах каталога: в разделе и в «Товарах со скидкой», там она держит
фильтры. Правой колонки в этой вёрстке нет вовсе. Модуль, поставленный
в колонку на любой другой странице, просто не появится, и движок об этом
не предупредит — поэтому всё, что должно быть видно, ставьте
в `Content Top` или `Content Bottom`.

### 5. Размер фотографий товара

Сейчас в настройках темы стоит 300×300 для плитки каталога. Наши
карточки крупнее, и на больших экранах фотографии будут мылить.
Поменять: **Расширения** → **Темы** → Theme Default → **Изменить** →
раздел размеров изображений, поле для списка товаров — поставить 600×600.

### 6. robots.txt и карта сайта

Рядом с темой лежит `robots.txt` — **для корня сайта**, не для папки
темы. Он заменяет стоковый файл ocStore, который лежал там до нас, —
все правила стокового в нём сохранены. Если открыть его в браузере
и браузер предложит перевод («Переведено»), выключите перевод:
иначе вместо `Disallow` будет написано «Запретить», и покажется,
что файл испорчен. Он закрывает от поиска личный кабинет, оформление заказа,
сравнение и страницы каталога с сортировкой (одна и та же страница
с разной сортировкой — это одна страница, а не двадцать).

Порядок такой:

1. **Расширения → Расширения** (пункт со значком пазла, четвёртый сверху:
   в ocStore перед ним стоит «Блог»; под ним четыре подпункта, нужен
   второй) → длинное поле «Выберите тип расширения» (по умолчанию в нём
   «Модули») → **«Каналы продвижения»** → строка **«Sitemap»** (в ocStore
   она без слова Google; адрес ленты при этом прежний,
   `extension/feed/google_sitemap`) → если кнопка зелёная с плюсом,
   сначала установить → синяя с карандашом → Статус «Включено» →
   синяя кнопка с дискетой. Названия пунктов сняты с админки
   stroigeroi.ru 23.09.2026.
2. Открыть в браузере
   `https://stroigeroi.ru/index.php?route=extension/feed/google_sitemap` —
   должен отдаться XML со списком товаров. Если страница пустая,
   ленту не включили.
3. Залить `robots.txt` в корень сайта (туда же, где `index.php`).
4. Открыть `https://stroigeroi.ru/robots.txt` и убедиться, что файл
   отдаётся, а не 404.

**До заливки проверьте ЧПУ:** Система → Настройки → магазин →
Редактировать → Сервер → «Использовать ЧПУ». Если ЧПУ выключены,
все адреса сайта выглядят как `index.php?route=...`, и любое правило
с `Disallow: /index.php` убирает сайт из выдачи целиком. В нашем файле
такого правила нет, но если будете брать готовый из интернета —
это первое, что надо оттуда вычеркнуть.

### 7. Проверить, что сайт вообще открыт для поиска

Открыть главную, нажать Ctrl+U (исходный код страницы) и поискать
словом `noindex`. Если найдётся `<meta name="robots" content="noindex">` —
сайт закрыт от поисковиков, и вся разметка, карта сайта и Метрика
бесполезны, пока эта строка не убрана. Наша тема такой строки
не выводит; она может остаться от прежней темы или от модуля.

### 8. Сжатие и кеш браузера

**Замер 23.09.2026, до всякой правки.** Перед сайтом на Рег.ру стоит
nginx (в ответах `server: nginx`), и большую часть работы сервер уже
делает сам, без нашей правки:

| Что | Сжатие | Срок в браузере |
|---|---|---|
| страница (`/`) | gzip | нет — и не нужно: цена и наличие меняются |
| `style.css` | gzip | 45 дней (`max-age=3888000`) |
| `banner-1280.webp` | не нужно, картинка уже сжата | **нет** |

Поэтому `htaccess-скорость.txt` **целиком не ставится**: сжатие
и кеш стилей в нём — повтор того, что уже работает. Раньше в этом
разделе было написано, что сервер не сжимает ничего, — это была
догадка до замера, и она не подтвердилась.

Открытый вопрос — картинки. Кто отдаёт `.webp` и `.avif` (браузеры
берут баннер в AVIF, он в `<picture>` первый): сам nginx или Apache
за ним. От этого зависит, где чинить: у Apache — парой строк
в `.htaccess`, у nginx — только в настройках хостинга, `.htaccess`
на такие ответы не действует вовсе. Различаются по заголовку `etag`:
у nginx он из двух частей и первая — ровно восемь знаков (время файла
в секундах), у Apache длинная часть стоит в конце (время
в микросекундах, тринадцать знаков).

Замер делается одной командой в Shell хостинга. Она показывает
заголовки картинок и скрипта и трижды засекает, за сколько сервер
собирает главную (`home:` — секунды до первого байта; меряется
с самого хостинга, поэтому дорога до Камчатки в это число не входит):

```
T="https://stroigeroi.ru/catalog/view/theme/stroigeroi2026"; for u in image/banner-1280.avif image/banner-1280.webp image/banner-1280.jpg image/logo.png "javascript/app.js?v=4d04a862"; do echo "== $u"; curl -s -o /dev/null -D - -H 'Accept-Encoding: gzip, br' "$T/$u" | grep -iE '^(content-encoding|cache-control|expires|etag)'; done; for i in 1 2 3; do curl -s -o /dev/null -w "home: %{time_starttransfer}s\n" https://stroigeroi.ru/; done
```

Если всё-таки понадобится править `.htaccess`: **сохраните копию
себе на компьютер до правки** — ошибка в нём кладёт сайт целиком,
с ошибкой 500, — и **сразу после правки откройте сайт**.

## Чего в теме нет и почему

**Оформление заказа** осталось стандартным. Это самая хрупкая часть
OpenCart: многошаговая форма, половина логики которой живёт в самом
шаблоне. Переписать её красиво можно, сломать оформление заказа — тоже,
и это единственное место, где поломка стоит денег. Вид ему поправлен
стилями.

**Личный кабинет** (кроме входа и избранного) — тоже стандартный.
Наши стили на него всё равно действуют: их подключает шапка, а шапка
у всех страниц общая. Раскладка там будет проще, чем в макете, но
чужеродно выглядеть не будет.

**Фильтры по цене и бренду** убраны. У OpenCart на странице раздела их
нет: контроллер не принимает ни цену, ни бренд. Оставить их разметкой
значило бы поставить на сайт органы управления, которые ничего не делают.
Если фильтры нужны — в движке есть модуль фильтра по характеристикам,
он встанет в левую колонку раздела, место для него оставлено.

**Отзывов** нет, хотя движок их умеет: у магазина нет ни одного отзыва,
и блок «Отзывы (0)» на новом сайте хуже, чем его отсутствие. Включить
обратно — несколько строк.

**Значков у разделов каталога** нет. В макете их восемнадцать,
нарисованных под конкретные разделы; к разделам из базы их не привязать.
У категорий заказчика есть свои картинки в базе (поле `image`), но
стандартный контроллер меню их не отдаёт — это отдельная небольшая
доработка.

## Если после переключения сайт «пустой»

Скорее всего, кеш. Порядок действий:

1. Очистить `system/storage/cache/` (всё содержимое).
2. Проверить, что папка называется ровно `stroigeroi2026` и лежит
   в `catalog/view/theme/`.
3. Проверить запросом, что переключение записалось:

```sql
SELECT `value` FROM oc_setting WHERE `key` = 'theme_default_directory';
```

4. Проверить, что тема вообще включена — иначе движок вместо сайта
   выводит одну строку «Error: A theme has not been assigned to this store!»:

```sql
SELECT `value` FROM oc_setting WHERE `key` = 'theme_default_status';
```

   Должна быть единица.

5. Проверить, что страница не переопределена в базе (см. шаг 4½).

6. Если ничего не помогло — откатиться (см. выше) и написать мне,
   что именно видно на экране.

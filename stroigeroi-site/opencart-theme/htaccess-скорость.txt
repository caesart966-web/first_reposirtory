# ============================================================================
#  Строй-Герой: срок хранения в браузере для картинок webp и avif
# ============================================================================
#
#  Куда. В КОНЕЦ файла .htaccess в корне сайта
#  (/var/www/u2934771/data/www/stroigeroi.ru/.htaccess). Удобнее всего -
#  командой из УСТАНОВКА.md, раздел «8. Сжатие и кеш»: она сама делает
#  копию файла, открывает сайт после правки и при ошибке возвращает всё
#  как было. Те же строки записаны в самой команде; что они совпадают
#  с этим файлом, проверяет tools/check-htaccess.py.
#
#  Почему только это. Замер на stroigeroi.ru 23.09.2026: перед сайтом
#  стоит nginx. Страницы, стили и скрипты уже приходят сжатыми, а css,
#  js, jpg и png nginx отдаёт сам и со сроком 45 дней. webp и avif он
#  к своим не относит и передаёт Apache, а тот отдаёт их без срока:
#  баннер на главной браузер спрашивает заново при каждом заходе.
#  Кто отдал файл, видно по заголовку etag: у nginx «время-размер»,
#  у Apache «размер-время», и время у него в микросекундах.
#
#  Раньше здесь лежал полный набор: сжатие, сроки для всех типов файлов,
#  отказ от ETag. Он писался до замера, в расчёте на голый Apache, и
#  повторял то, что уже работает, - а до файлов, которые отдаёт nginx,
#  .htaccess не достаёт вовсе. Набор остался в истории git.
#
#  Срок - 45 дней, как у jpg и png от nginx, а не год: в адресе баннера
#  нет отпечатка, и новый баннер под старым именем постоянные посетители
#  увидели бы только через год.
#
#  Если модуля mod_headers на сервере нет, блок молча пропускается,
#  а не роняет сайт.
# ============================================================================

# stroigeroi-webp-avif: nginx passes webp/avif to Apache with no cache headers; 45 days, as nginx gives jpg/png/css/js
<IfModule mod_headers.c>
  <FilesMatch "\.(webp|avif)$">
    Header set Cache-Control "max-age=3888000"
  </FilesMatch>
</IfModule>

# Парсер реестра НОСТРОЙ + сбор контактов с checko.ru

Автономный Python-скрипт: принимает **один** входной объект — архив `.rar`/`.zip`,
отдельный Excel-файл или папку — и выдаёт **один** итоговый Excel-файл
`final_report_ГГГГ-ММ-ДД.xlsx` с одним листом.

Что делает:

1. распаковывает архив (в том числе вложенные архивы и любую структуру папок);
2. рекурсивно находит все таблицы и читает **все листы** каждой книги;
3. извлекает записи членов СРО: **название**, **ИНН**, **дата вступления**,
   **дата исключения**, **контакты из самого реестра** (телефон, e-mail, адрес,
   руководитель, сайт и любые другие «контактные» колонки);
4. для каждой уникальной компании запрашивает карточку на **checko.ru** и
   забирает оттуда телефоны, e-mail, адреса и руководителя;
5. соблюдает суточный лимит бесплатных запросов checko.ru, **сохраняет прогресс**
   и на следующий день продолжает с того места, где остановился;
6. складывает результат в один файл с одним листом: название, ИНН, телефон,
   email, адрес (один, юридический), ФИО руководителя, дату вступления
   и статус членства.

---

## 1. Требования

* **Python 3.10 или новее** (проверяется при запуске);
* для архивов `.rar` — внешний распаковщик (`unrar`, `unar`, `7z` или `bsdtar`);
  для `.zip` ничего дополнительно не нужно.

## 2. Установка

```bash
# 1. распакуйте/скопируйте папку nostroy-parser и перейдите в неё
cd nostroy-parser

# 2. создайте виртуальное окружение
python -m venv .venv

# Windows:
.venv\Scripts\activate
# macOS / Linux:
source .venv/bin/activate

# 3. поставьте зависимости
pip install -r requirements.txt
```

### Распаковщик RAR (нужен только для `.rar`)

| ОС      | Команда                                                              |
|---------|----------------------------------------------------------------------|
| Windows | установить WinRAR или UnRAR, добавить `unrar.exe` в `PATH`           |
| macOS   | `brew install unar` (или `brew install rar`)                          |
| Ubuntu  | `sudo apt-get install unrar` (либо `unar`, либо `p7zip-full`)         |

Если распаковщика нет, скрипт выведет эту же инструкцию и предложит обходной путь:
распаковать архив вручную и передать папку.

## 3. Запуск

### Самый простой способ — файл-запускалка

Работает «как таблица»: по завершении готовый файл сам открывается в Excel,
а обработанный архив запоминается — на следующий день достаточно двойного
щелчка по `run.bat` и клавиши «1» (продолжить с тем же файлом).

Устанавливать ничего вручную не нужно: при первом запуске скрипт сам создаст
окружение и поставит зависимости.

**Windows.** Перетащите архив с реестром прямо на файл `run.bat` — и всё.
Либо дважды щёлкните `run.bat`, он попросит перетащить файл в открывшееся окно.

Рядом лежит `run-test.bat` — то же самое, но обрабатывает только 3 компании.
С него стоит начинать: проверить, что ключ API работает и контакты приходят,
не потратив на это суточный лимит.

**macOS / Linux.**

```bash
./run.sh                                    # спросит путь к файлу
./run.sh "/путь/Реестр СРО 410.rar"         # сразу с файлом
./run.sh "/путь/Реестр.rar" --no-checko     # можно добавлять любые ключи

./run-test.sh "/путь/Реестр.rar"            # пробный запуск: только 3 компании
```

Результаты появятся в папке `output` рядом со скриптом.

### Обычный запуск из командной строки

```bash
# самый частый случай — архив с выгрузкой реестра
python main.py --input "C:/Данные/Реестр СРО 410.rar"

# один Excel-файл, результаты в свою папку
python main.py --input ./reestr.xlsx --output ./output

# уже распакованная папка
python main.py --input "./Выгрузка НОСТРОЙ"

# только разбор реестра, без обращений к checko.ru (работает без интернета)
python main.py --input ./reestr.zip --no-checko

# на следующий день — ТА ЖЕ команда: скрипт сам продолжит с места остановки
python main.py --input "C:/Данные/Реестр СРО 410.rar"
```

Полный список ключей: `python main.py --help`.

## 3½. Открытый реестр НОСТРОЙ — второй источник данных

**Важно про выгрузки реестра НОСТРОЙ.** В типовой выгрузке (`reestr_nostroy_sro_NNN_*.xlsx`)
дат вступления и исключения нет вообще — там только реквизиты, наименования,
статус членства, взносы и уровни ответственности. Поэтому даты берутся из
открытого реестра по ИНН, и без этого шага колонки с датами останутся пустыми.
Статус членства («Является членом» / «Исключен») при этом читается прямо из
файла и доступен сразу.

Даты берутся прежде всего **из вашего файла**, если они там есть. Если там их
нет, скрипт опрашивает открытые реестры: НОСТРОЙ (reestr.nostroy.ru) для
строителей и НОПРИЗ (reestr.nopriz.ru) для проектировщиков и изыскателей —
компаний из второго в первом попросту нет. Последним источником служат
сведения о членстве в СРО из ответа checko.ru (они уже оплачены запросом).
Ничего не вычисляется и не додумывается: в отчёт попадает только то, что
источник сообщил явно.

Помимо checko.ru скрипт опрашивает открытый Единый реестр НОСТРОЙ
(reestr.nostroy.ru) — бесплатно, без ключей и без суточного лимита. Оттуда
берутся даты вступления/исключения, статус членства, а также адрес, телефон,
почта и руководитель, если реестр их публикует. Приоритет источников:
checko.ru → ваш файл → реестр НОСТРОЙ; телефоны и почта из разных источников
объединяются без дублей. Ответы кэшируются: повторные запуски реестр не
дёргают, и прерванный проход продолжается с места остановки.

Список членов СРО забирается **целиком**, страницами: номер СРО берётся из
выгрузки и из имени файла, и полторы тысячи компаний приезжают за полтора
десятка запросов вместо полутора тысяч — секунды вместо часа. Поштучный поиск
остаётся запасным вариантом для тех, кого в списке не оказалось.

Проход по реестру разовый — он нужен один раз на весь список, дальше работают
только 100 суточных запросов к checko.ru. Скорость настраивается ключами
`--nostroy-workers` (по умолчанию 4 потока) и `--nostroy-rps` (4 запроса в
секунду). Формат запроса определяется на первой компании и запоминается,
поэтому дальше на каждую компанию идёт ровно один запрос.
Отключается ключом `--no-nostroy-dates`.

## 4. Любые базы данных на вход

Скрипт не привязан к выгрузкам НОСТРОЙ: подойдёт любой Excel/CSV/архив, где
есть компании и ИНН — клиентская база CRM, выгрузка 1С, чей-то список
контрагентов. Колонки распознаются по заголовкам и по содержимому (ИНН — по
контрольной сумме), телефоны и почта подбираются из любых колонок, включая
«Примечание». Дальше по каждому ИНН добираются контакты с checko.ru.

## 5. Два способа получить данные с checko.ru

### Официальный API — рекомендуется

Сайт checko.ru закрыт защитой от автоматизации, и обычный HTTP-клиент часто
получает `403` или страницу-заглушку вместо карточки компании. Официальный API
отдаёт те же сведения структурированным JSON, не ломается при смене дизайна
сайта и имеет бесплатный тариф со 100 запросами в сутки — ровно тот лимит,
под который построена вся логика работы «по дням».

Ключ выдаётся в личном кабинете на checko.ru. Передать его можно тремя способами.

**Проще всего** — открыть файл `checko_api_key.txt` рядом со скриптом, стереть
строку `ВСТАВЬТЕ_КЛЮЧ_СЮДА`, вставить свой ключ и сохранить. Больше про ключ
вспоминать не придётся: он подхватывается при каждом запуске.

Либо аргументом командной строки, либо переменной окружения:

```bash
python main.py --input ./reestr.rar --checko-api-key ВАШ_КЛЮЧ

set CHECKO_API_KEY=ВАШ_КЛЮЧ           # Windows
export CHECKO_API_KEY=ВАШ_КЛЮЧ        # macOS / Linux
python main.py --input ./reestr.rar
```

Порядок поиска: аргумент → переменная окружения → файл `checko_api_key.txt`.

С ключом одна компания — ровно один запрос и одна единица квоты.

**Важно:** запрос идёт по реквизитам (ИНН/ОГРН). Записи реестра без ИНН
пропускаются с отметкой в логе — квота на них не тратится, а контакты у таких
компаний останутся только из реестра НОСТРОЙ.

**Первый ответ API сохраняется целиком** в `output/parsed/checko_api_sample.json`
(ключ в файле вырезан). Это страховка: если сервис изменит имена полей и часть
контактов перестанет извлекаться, по этому файлу видно, как ответ выглядит на
самом деле — и разбор правится без траты запросов на эксперименты.

Метод запроса определяется автоматически: сначала GET, при отказе — POST.
Найденный метод запоминается, лишних обращений не будет.

### Разбор страниц сайта — запасной вариант

Без ключа скрипт разбирает обычные страницы checko.ru. Работает, пока сайт не
включит защиту; если в отчёте колонка контактов пустая, а в столбце «Статус
запроса checko.ru» стоит `forbidden` или `not_found` — переходите на API.

## 5. Работа по дням и суточный лимит

checko.ru отдаёт ограниченное число бесплатных запросов в сутки (по умолчанию
**100**, сброс в 00:00). Скрипт устроен так:

* **первый запуск** — сразу делает запросы, пока не израсходует лимит;
* каждый полученный результат немедленно пишется в
  `output/state/checko_state.json` (атомарная запись — прерывание не портит файл);
* **как только 100 запросов израсходованы, скрипт сразу выгружает отчёт** — в том
  же запуске, не дожидаясь ничего: компании, до которых квота дотянулась, идут в
  отчёт с контактами checko.ru, остальные — со статусом `skipped` и заполненными
  данными из реестра НОСТРОЙ. В консоли пишется, сколько компаний осталось;
* **следующий запуск** (на следующие сутки) видит в файле состояния вчерашнюю
  дату, обнуляет счётчик и продолжает **только с необработанных компаний** —
  уже полученные карточки повторно не запрашиваются.

Единица квоты списывается **на компанию** (поиск + открытие карточки считаются
одним запросом — так же, как их считает сам сервис). Если нужно списывать квоту
за каждый HTTP-запрос, добавьте `--count-http-requests`.

Резервирование квоты потокобезопасно: при `--workers 8` лимит всё равно не будет
превышен ни на один запрос (это проверяется автотестом).

### Обработка ошибок checko.ru

| Ситуация                | Поведение скрипта                                                      |
|-------------------------|------------------------------------------------------------------------|
| `429 Too Many Requests` | уважает `Retry-After`; иначе помечает суточный лимит исчерпанным и останавливает запросы |
| `403 Forbidden`         | фиксирует; после 3 подряд считает это блокировкой/капчей и останавливается |
| `404 Not Found`         | статус `not_found`, компания больше не запрашивается                    |
| `5xx`, таймаут, обрыв   | повтор с экспоненциальной задержкой (`--max-retries`, по умолчанию 3)   |
| страница «лимит исчерпан» | распознаётся по тексту, работа останавливается                        |

Ошибка по одной компании **никогда** не останавливает обработку остальных.
Компании с ошибками повторяются автоматически при следующих запусках, но не
более 3 раз — чтобы не тратить дефицитную квоту впустую. Ключ `--retry-failed`
снимает это ограничение. Компании, до которых квота просто «не дотянулась»
(статус `rate_limited`/`skipped`), повторяются всегда и в счёт попыток не идут.

```
output/
├── raw_data/                       # все исходные файлы
│   ├── Реестр СРО 410.rar          #   копия входного архива/файла
│   └── extracted/                  #   распакованное содержимое (структура сохранена)
├── parsed/                         # промежуточные результаты разбора
│   ├── records.json                #   все записи реестра
│   ├── companies.json              #   уникальные компании + данные checko.ru
│   ├── columns_detected.csv        #   как распознан каждый столбец вашего файла
│   ├── unrecognized_rows.csv       #   строки, из которых не удалось извлечь данные
│   ├── checko_api_sample.json      #   первый ответ API целиком (ключ вырезан)
│   └── files_index.csv             #   что и сколько прочитано из каждого файла
├── state/
│   └── checko_state.json           # прогресс: квота + все собранные данные
├── logs/
│   └── run_ГГГГ-ММ-ДД.log          # подробный лог запуска
└── final_report_ГГГГ-ММ-ДД.xlsx    # ← ИТОГОВЫЙ ФАЙЛ
```

### Что в итоговом файле

Один лист «Контакты», девять колонок. В файле — **только обработанные
компании**: обработали сто — в файле сто строк, назавтра добавились следующие —
стало двести. Файл накапливается день за днём, «пустых» компаний, до которых
не дошла квота, в нём нет.

| Колонка | Откуда берётся |
|---------|----------------|
| Название компании | реестр НОСТРОЙ, ОПФ сокращена: `ООО «…»`, `АО «…»`, `ЗАО «…»`, `ИП Фамилия Имя Отчество` |
| ИНН | реестр НОСТРОЙ, текстом — ведущие нули не теряются |
| Телефон | checko.ru; пока данных checko нет — из реестра НОСТРОЙ |
| Email | checko.ru; пока данных checko нет — из реестра НОСТРОЙ |
| Адрес | checko.ru, **ровно один** — юридический; пока данных checko нет — из реестра НОСТРОЙ |
| Руководитель | только ФИО, без должности; checko.ru либо реестр НОСТРОЙ |
| Дата вступления в СРО | ваш файл; если там нет — открытый реестр reestr.nostroy.ru |
| Статус членства | `действует` или `исключён` — для сортировки и фильтра |

Отдельной колонки «Дата исключения из СРО» в отчёте нет: её заменяет
«Статус членства». Сама дата по-прежнему разбирается и участвует в вычислении
статуса — просто не занимает столбец.

### Пересборка адресов по кэшу (без расхода лимита)

Карточки, полученные до исправления разбора, лежат в кэше со слипшимся списком
адресов. **Перезапрашивать их не нужно и делать ничего не нужно:** при обычном
запуске скрипт сам приводит такие карточки к одному адресу по уже сохранённым
данным и пишет в лог, сколько исправил:

```
Адреса пересобраны по кэшу: исправлено карточек 198
(адресов СРО отброшено: 2, спорных: 11, без своего адреса: 20).
Запросы к checko.ru не потребовались
```

Пересборка идемпотентна: на следующем запуске исправлять уже нечего.

Если нужно посмотреть на изменения заранее или пересобрать адреса отдельно,
есть тот же механизм отдельной командой — он тоже **не делает ни одного
запроса к checko.ru**:

```bash
# посмотреть, что изменится, ничего не записывая
python3 rebuild_addresses.py --state output/state/checko_state.json --dry-run

# применить
python3 rebuild_addresses.py --state output/state/checko_state.json
```

Скрипт не трогает суточную квоту, не меняет статусы карточек и не теряет
телефоны, почты и руководителей: правится только поле адреса. Перед записью
создаётся резервная копия `checko_state.json.before-rebuild`.

Выбрать адрес по имени поля здесь нельзя — в кэше лежат разобранные поля, а не
сырой ответ, — поэтому выбор идёт по содержимому строки: адрес СРО опознаётся
по тому, что повторяется у многих компаний; регион сверяется с кодом региона
в ИНН; современный формат ФИАС считается признаком юридического адреса, а
старый формат КЛАДР (`Санкт-Петербург г`) штрафуется как пришедший из выгрузки
НОСТРОЙ. Исходный список сохраняется в `extra.addresses_all`, поэтому скрипт
можно запускать повторно — выбор каждый раз делается из полного набора.

Если у компании в кэше были **только** адреса СРО, ячейка останется пустой:
чужой адрес в отчёте хуже отсутствующего. Такие компании стоит допросить
обычным запуском — они попадут в очередь автоматически.

После пересборки достаточно обычного запуска `main.py`: отчёт соберётся
из кэша, уже пробитые компании повторно не запрашиваются.

### Почему адрес один

Ответ checko.ru содержит несколько адресов: юридический, фактический, адреса
обособленных подразделений и — в блоке о членстве в СРО — адрес самой СРО.
Раньше в ячейку попадали все, склеенные через «;», и адрес СРО оказывался
у сотен членов одной организации.

Теперь адрес выбирается по имени поля в ответе: `ЮрАдрес` — приоритет,
подразделения и филиалы исключены, блок СРО не рассматривается вовсе.
Из выбранного адреса убирается административный довесок формата ФИАС
(`вн. тер. г. муниципальный округ Такой-то`) — он добавляет к строке до
50 символов, из-за чего ячейка переносится на три строки и один адрес
читается как несколько. `вн. тер. г. город Кронштадт` при этом сохраняется
как `г. Кронштадт`: это часть адреса, а не административная единица.

Оформление скупое: жирная шапка, закреплённая первая строка, автофильтр.
Ни заливки, ни цветного текста — таблицу фильтруют и читают.

Даты записаны настоящими датами в формате `ДД.ММ.ГГГГ`, поэтому по ним
работают сортировка и фильтр по периоду.

Отчёт наполняется постепенно, но полезен с первого дня. Всё, что есть в самом
реестре, проставляется **сразу всем компаниям** ещё до обращения к checko.ru:
даты вступления и исключения, статус членства, а также адрес, руководитель,
телефон и почта, если реестр их содержит. Обращения к checko.ru лишь уточняют
и дополняют контакты — по ~100 компаний в день; значение с checko.ru, когда
оно получено, замещает реестровое в этих колонках.

«Статус членства» — короткое `действует` / `исключён`, чтобы фильтровать и
сортировать список. Если в реестре есть дата исключения, статус будет `исключён`. Когда даты нет, учитывается текст
статуса из реестра («прекращено членство», «исключён» и подобные).

Если сервис отклонил доступ (неверный ключ, неактивный тариф), скрипт пишет
об этом крупно прямо в окне с инструкцией, что проверить. Отклонённые запросы
лимит не тратят — исправив ключ, запускайте сразу, ждать завтра не нужно.

Всё, что в таблицу не вошло, лежит рядом в `output/parsed/`: построчные данные
реестра со ссылкой на файл, лист и номер строки — в `records.json`,
нераспознанные строки — в `unrecognized_rows.csv`.

## 7. Какие форматы читаются

| Формат | Как читается |
|--------|--------------|
| `.xlsx`, `.xlsm`, `.xltx`, `.xltm` | `openpyxl` (потоковый режим — файлы на сотни МБ) |
| `.xls` | `xlrd` |
| `.xlsb` | `pyxlsb` (необязательная зависимость) |
| `.csv`, `.tsv`, `.txt` | автоопределение кодировки (utf-8/cp1251/cp866) и разделителя |
| HTML-таблица с расширением `.xls`/`.xlsx` | встроенный HTML-парсер — частая выгрузка из 1С и с сайтов СРО |
| `.zip`, `.rar` | `zipfile` / `rarfile` (+ внешние распаковщики), включая вложенные архивы |

Реальный формат определяется по сигнатуре файла, а не по расширению. Если
профильный ридер не справился, включается запасной путь через
`pandas.read_excel(..., sheet_name=None, header=None)` — он читает сразу все листы.

## 8. Как распознаются колонки

Никаких предположений о названиях столбцов не делается. Работают два механизма.

**По заголовкам.** Шапка ищется в первых `--header-scan-rows` строках листа
(по умолчанию 60) и может занимать до `--header-max-span` строк — это покрывает
«многоэтажные» шапки с объединёнными ячейками. Заголовок нормализуется (регистр,
«ё», пунктуация, переносы) и сопоставляется с набором шаблонов, поэтому
одинаково опознаются `Наименование`, `Полное фирменное наименование`,
`Наименование члена СРО`, `Контрагент`, `ФИО`, а также `ИНН`,
`Идентификационный номер налогоплательщика`, `Дата вступления в СРО`,
`Членство с`, `дата приёма`, `Дата исключения`, `Тел.`, `E-mail`,
`Место нахождения` и десятки других вариантов.

**По содержимому.** Всё, что не определилось по заголовку (или если шапки нет
вообще), определяется по самим данным:

* ИНН — по **контрольной сумме** ФНС (10 и 12 знаков);
* даты — по успешному разбору, включая серийные числа Excel;
* телефоны, e-mail, сайты, адреса — по формату значений;
* наименование — по организационно-правовой форме (`ООО`, `АО`, `ИП`, …) и кавычкам.

Дополнительно **каждая строка целиком** просматривается на предмет ИНН,
телефонов и e-mail: контакты часто «спрятаны» в колонках вроде «Примечание»
или склеены с другими данными.

**Реквизиты самой СРО отсекаются.** В выгрузках НОСТРОЙ рядом с данными члена
идут телефон, адрес и почта самой саморегулируемой организации. Без защиты у
всех компаний в отчёте оказался бы один и тот же телефон. Отсекаются они двумя
независимыми способами: по заголовку («Телефон СРО», «Адрес места нахождения
саморегулируемой организации») и по данным — контактная колонка с одинаковым
значением во всех строках файла физически не может быть контактом конкретного
члена. Такие колонки перечисляются в логе, а их значения сохраняются в
`parsed/records.json`, то есть не теряются.

Учтите: в большинстве выгрузок НОСТРОЙ телефонов и почты членов попросту нет —
публикуются только название, ИНН, адрес, руководитель и даты. Поэтому колонки
«Телефон (реестр)» и «Email (реестр)» у вас, скорее всего, будут пустыми, и
единственный источник телефонов — checko.ru.

## 9. Гарантии полноты

* обходятся **все** файлы, **все** листы и **все** строки;
* строка, из которой не удалось извлечь ни ИНН, ни названия, **не выбрасывается
  молча** — она попадает в `output/parsed/unrecognized_rows.csv` (и на вкладку
  `unrecognized_rows` при `--with-diagnostics`) вместе с полным содержимым и
  причиной;
* ошибка чтения одного файла, листа или строки не останавливает обработку
  остальных — она пишется в лог;
* вкладка `nostroy_contacts` содержит по строке на каждую исходную запись, со
  ссылкой на файл, лист и номер строки.

### Про дедупликацию

Запрос к checko.ru стоит единицы дефицитной суточной квоты, поэтому по умолчанию
(`--dedupe-by inn`) компании группируются **по ИНН**: одинаковый ИНН — это одно
юрлицо и одна карточка на checko.ru, сколько бы написаний названия ни встретилось
в разных файлах. Все варианты названия сохраняются в колонке «Варианты написания
названия», а все вхождения — в `nostroy_contacts`.

Если нужен буквальный вариант «уникальная пара название + ИНН» (и вы готовы
потратить на это больше квоты), укажите `--dedupe-by name_inn`.

## 10. Ключи командной строки

### Вход и выход
| Ключ | Назначение |
|------|-----------|
| `--input`, `-i` | архив `.rar`/`.zip`, Excel-файл или папка **(обязательный)** |
| `--output`, `-o` | папка результатов (по умолчанию `output`) |
| `--report-date` | дата в имени итогового файла (по умолчанию — сегодня) |

### Разбор таблиц
| Ключ | Назначение |
|------|-----------|
| `--dedupe-by {inn,name_inn}` | правило уникальности компании (по умолчанию `inn`) |
| `--header-scan-rows N` | сколько верхних строк искать шапку (60) |
| `--header-max-span N` | максимальная высота шапки в строках (3) |
| `--content-sample N` | сколько значений колонки анализировать при автодетекте (400) |

### checko.ru
| Ключ | Назначение |
|------|-----------|
| `--checko-api-key КЛЮЧ` | ключ официального API checko.ru (или переменная `CHECKO_API_KEY`) |
| `--no-checko` | не обращаться к checko.ru, только разобрать реестр |
| `--daily-limit N` | суточный лимит запросов (100) |
| `--workers N`, `-w` | число параллельных потоков (4) |
| `--rps ЧИСЛО` | максимум запросов в секунду суммарно (1.0) |
| `--timeout СЕК` | таймаут HTTP-запроса (25) |
| `--max-retries N` | повторов при сетевых сбоях и 5xx (3) |
| `--user-agent СТРОКА` | заголовок User-Agent |
| `--proxy URL` | прокси (по умолчанию берётся из `HTTPS_PROXY`) |
| `--no-query-by-name` | не искать по названию, если в реестре нет ИНН |
| `--count-http-requests` | списывать квоту за каждый HTTP-запрос |
| `--retry-failed` | повторить компании с ошибками, игнорируя лимит в 3 автопопытки |
| `--reset-state` | удалить сохранённый прогресс и начать сбор с нуля |
| `--max-companies N` | обработать не более N компаний за запуск (отладка) |

### Прочее
| Ключ | Назначение |
|------|-----------|
| `--no-progress-bar` | отключить прогресс-бар |
| `--log-level {DEBUG,INFO,WARNING,ERROR}` | подробность вывода |
| `--version` | версия скрипта |

## 12. Тесты

```bash
python -m unittest discover -s tests -v
```

71 тест, интернет не требуется: обращения к checko.ru эмулируются локальным
HTTP-сервером, который отдаёт заготовленные страницы и коды `200/403/404/429/503`.
Проверяются в том числе главные сценарии ТЗ:

* исчерпание суточного лимита и **продолжение на следующий день** без повторных
  запросов по уже собранным компаниям;
* соблюдение лимита при работе в несколько потоков (ровно N запросов при лимите N);
* чтение всех листов всех форматов, включая HTML с расширением `.xls`;
* определение колонок при нестандартных заголовках и при полном их отсутствии;
* сохранение нераспознанных строк;
* разбор ответа официального API и его ошибок (неверный ключ, лимит, «не найдено»);
* отсечение реквизитов самой СРО от контактов её членов.

Сгенерировать тестовый архив отдельно (чтобы попробовать скрипт «вживую»):

```bash
python tests/make_fixtures.py ./demo
python main.py --input "./demo/Реестр НОСТРОЙ.zip" --output ./demo/output --no-checko
```

## 13. Частые вопросы

**В отчёте пусто там, где в исходном файле данные есть.** Откройте
`output/parsed/columns_detected.csv` — там по каждому столбцу вашего файла
написано, чем он распознан («date_join», «name», «—») и три примера значений.
Сразу видно, какая колонка не опозналась. Этот файл маленький, его удобно
переслать разработчику вместо всей выгрузки.

**Скрипт нашёл 0 записей.** Посмотрите `output/parsed/files_index.csv` и лог: там
видно, сколько строк прочитано из каждого файла. Если строки прочитаны, но записей
нет — все строки попали в `unrecognized_rows.csv` с указанием причины.

**Не распознались колонки.** Запустите с `--log-level DEBUG`: в логе для каждого
листа печатается итоговая карта колонок. Помогает увеличить `--header-scan-rows`,
если шапка находится глубже 60-й строки.

**Колонка контактов checko.ru пустая.** Посмотрите на вкладке `checko_contacts`
столбец «Статус запроса»: `forbidden` — сайт заблокировал автоматизацию,
`not_found` — карточка не найдена, `rate_limited` — кончился лимит. В первых
двух случаях используйте официальный API: `--checko-api-key ВАШ_КЛЮЧ`
(см. раздел 4). Прогресс не потеряется — уже собранное сохранено.

**checko.ru отдаёт 403 или «неверный ключ».** Запросы останавливаются, но
суточный лимит при этом НЕ считается потраченным: исправьте причину (ключ,
тариф, нагрузку `--workers 1 --rps 0.3`) и запускайте снова сразу — ждать
следующего дня не нужно.

**У всех компаний одинаковый телефон.** Это реквизит самой СРО, попавший в
колонку контактов. Скрипт такие колонки отсекает автоматически (см. раздел 8);
если что-то всё же просочилось, пришлите строку из лога — добавлю правило.

**Сменился аккаунт или ключ API.** Ничего специально делать не нужно: результат
запоминает, чем он получен. Если раньше работал разбор страниц сайта, а теперь
появился ключ API, все неудачные компании будут перезапрошены автоматически.
Успешно собранные данные при этом сохраняются и квоту не тратят.

**Нужно начать сбор заново.** `--reset-state` удаляет сохранённый прогресс
(данные с checko.ru придётся собирать снова, расходуя квоту). Тот же эффект
даёт удаление папки `output`.

**Как переносить прогресс между машинами.** Скопируйте
`output/state/checko_state.json` — в нём и счётчик квоты, и все собранные данные.

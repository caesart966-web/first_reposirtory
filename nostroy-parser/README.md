# Парсер реестра НОСТРОЙ + сбор контактов с checko.ru

Автономный Python-скрипт: принимает **один** входной объект — архив `.rar`/`.zip`,
отдельный Excel-файл или папку — и выдаёт **один** итоговый Excel-файл
`final_report_ГГГГ-ММ-ДД.xlsx` с тремя вкладками.

Что делает:

1. распаковывает архив (в том числе вложенные архивы и любую структуру папок);
2. рекурсивно находит все таблицы и читает **все листы** каждой книги;
3. извлекает записи членов СРО: **название**, **ИНН**, **дата вступления**,
   **дата исключения**, **контакты из самого реестра** (телефон, e-mail, адрес,
   руководитель, сайт и любые другие «контактные» колонки);
4. для каждой уникальной компании запрашивает карточку на **checko.ru** и
   забирает оттуда телефоны, e-mail, адреса и руководителя;
5. соблюдает суточный лимит бесплатных запросов checko.ru, **сохраняет прогресс**
   и на следующий день продолжает с того места, где остановился;
6. складывает всё в один отчёт с вкладками `checko_contacts`,
   `nostroy_contacts`, `combined`.

---

## 1. Требования

* **Python 3.10 или новее** (проверяется при запуске);
* для архивов `.rar` — внешний распаковщик (`unrar`, `unar`, `7z` или `bsdtar`);
  для `.zip` ничего дополнительно не нужно.

## 2. Установка

```bash
# 1. распакуйте/скопируйте папку nostroy-parser и перейдите в неё
cd nostroy-parser

# 2. создайте виртуальное окружение
python -m venv .venv

# Windows:
.venv\Scripts\activate
# macOS / Linux:
source .venv/bin/activate

# 3. поставьте зависимости
pip install -r requirements.txt
```

### Распаковщик RAR (нужен только для `.rar`)

| ОС      | Команда                                                              |
|---------|----------------------------------------------------------------------|
| Windows | установить WinRAR или UnRAR, добавить `unrar.exe` в `PATH`           |
| macOS   | `brew install unar` (или `brew install rar`)                          |
| Ubuntu  | `sudo apt-get install unrar` (либо `unar`, либо `p7zip-full`)         |

Если распаковщика нет, скрипт выведет эту же инструкцию и предложит обходной путь:
распаковать архив вручную и передать папку.

## 3. Запуск

### Самый простой способ — файл-запускалка

Устанавливать ничего вручную не нужно: при первом запуске скрипт сам создаст
окружение и поставит зависимости.

**Windows.** Перетащите архив с реестром прямо на файл `run.bat` — и всё.
Либо дважды щёлкните `run.bat`, он попросит перетащить файл в открывшееся окно.

**macOS / Linux.**

```bash
./run.sh                                    # спросит путь к файлу
./run.sh "/путь/Реестр СРО 410.rar"         # сразу с файлом
./run.sh "/путь/Реестр.rar" --no-checko     # можно добавлять любые ключи
```

Результаты появятся в папке `output` рядом со скриптом.

### Обычный запуск из командной строки

```bash
# самый частый случай — архив с выгрузкой реестра
python main.py --input "C:/Данные/Реестр СРО 410.rar"

# один Excel-файл, результаты в свою папку
python main.py --input ./reestr.xlsx --output ./output

# уже распакованная папка
python main.py --input "./Выгрузка НОСТРОЙ"

# только разбор реестра, без обращений к checko.ru (работает без интернета)
python main.py --input ./reestr.zip --no-checko

# на следующий день — ТА ЖЕ команда: скрипт сам продолжит с места остановки
python main.py --input "C:/Данные/Реестр СРО 410.rar"
```

Полный список ключей: `python main.py --help`.

## 4. Работа по дням и суточный лимит

checko.ru отдаёт ограниченное число бесплатных запросов в сутки (по умолчанию
**100**, сброс в 00:00). Скрипт устроен так:

* **первый запуск** — сразу делает запросы, пока не израсходует лимит;
* каждый полученный результат немедленно пишется в
  `output/state/checko_state.json` (атомарная запись — прерывание не портит файл);
* **как только 100 запросов израсходованы, скрипт сразу выгружает отчёт** — в том
  же запуске, не дожидаясь ничего: компании, до которых квота дотянулась, идут в
  отчёт с контактами checko.ru, остальные — со статусом `skipped` и заполненными
  данными из реестра НОСТРОЙ. В консоли пишется, сколько компаний осталось;
* **следующий запуск** (на следующие сутки) видит в файле состояния вчерашнюю
  дату, обнуляет счётчик и продолжает **только с необработанных компаний** —
  уже полученные карточки повторно не запрашиваются.

Единица квоты списывается **на компанию** (поиск + открытие карточки считаются
одним запросом — так же, как их считает сам сервис). Если нужно списывать квоту
за каждый HTTP-запрос, добавьте `--count-http-requests`.

Резервирование квоты потокобезопасно: при `--workers 8` лимит всё равно не будет
превышен ни на один запрос (это проверяется автотестом).

### Обработка ошибок checko.ru

| Ситуация                | Поведение скрипта                                                      |
|-------------------------|------------------------------------------------------------------------|
| `429 Too Many Requests` | уважает `Retry-After`; иначе помечает суточный лимит исчерпанным и останавливает запросы |
| `403 Forbidden`         | фиксирует; после 3 подряд считает это блокировкой/капчей и останавливается |
| `404 Not Found`         | статус `not_found`, компания больше не запрашивается                    |
| `5xx`, таймаут, обрыв   | повтор с экспоненциальной задержкой (`--max-retries`, по умолчанию 3)   |
| страница «лимит исчерпан» | распознаётся по тексту, работа останавливается                        |

Ошибка по одной компании **никогда** не останавливает обработку остальных.
Компании с ошибками повторяются автоматически при следующих запусках, но не
более 3 раз — чтобы не тратить дефицитную квоту впустую. Ключ `--retry-failed`
снимает это ограничение. Компании, до которых квота просто «не дотянулась»
(статус `rate_limited`/`skipped`), повторяются всегда и в счёт попыток не идут.

## 5. Структура результатов

```
output/
├── raw_data/                       # все исходные файлы
│   ├── Реестр СРО 410.rar          #   копия входного архива/файла
│   └── extracted/                  #   распакованное содержимое (структура сохранена)
├── parsed/                         # промежуточные результаты разбора
│   ├── records.json                #   все записи реестра
│   ├── companies.json              #   уникальные компании + данные checko.ru
│   ├── unrecognized_rows.csv       #   строки, из которых не удалось извлечь данные
│   └── files_index.csv             #   что и сколько прочитано из каждого файла
├── state/
│   └── checko_state.json           # прогресс: квота + все собранные данные
├── logs/
│   └── run_ГГГГ-ММ-ДД.log          # подробный лог запуска
└── final_report_ГГГГ-ММ-ДД.xlsx    # ← ИТОГОВЫЙ ФАЙЛ
```

### Вкладки итогового файла

**1. `checko_contacts`** — только данные с checko.ru:
название (в реестре и по checko), ИНН, ОГРН, телефоны, e-mail, адрес,
руководитель, сайт, статус запроса, признак совпадения ИНН, ссылка на карточку,
время получения, текст ошибки.

**2. `nostroy_contacts`** — только данные из реестра НОСТРОЙ, **по одной строке
на каждую исходную запись** (ничего не «схлопывается»): название, ИНН, ОГРН,
дата вступления, дата исключения, статус членства, телефон, e-mail, адрес,
руководитель, сайт, прочие контакты, регистрационный номер, СРО, а также
файл-источник, лист и номер строки.

**3. `combined`** — сводная таблица по уникальным компаниям:

| Блок | Колонки |
|------|---------|
| Идентификация | Название компании, ИНН |
| Контакты checko.ru | Телефон, Email, Адрес, Руководитель, «одной строкой» |
| Членство | Дата вступления, Дата исключения |
| Контакты реестра НОСТРОЙ | Телефон, Email, Адрес, Руководитель, «одной строкой» |
| Объединённые | Все телефоны, Все email, Все адреса, Все руководители, Сайт |
| Служебное | ОГРН, статус членства, статус запроса checko.ru, ссылка, варианты написания названия, число записей в реестре, источники |

С ключом `--with-diagnostics` добавляются вкладки `unrecognized_rows`
(нераспознанные строки) и `run_summary` (сводка по запуску).

ИНН, ОГРН и телефоны записываются **текстом** — Excel не съедает ведущие нули и
не превращает их в `7,70708E+09`. Даты записываются настоящими датами в формате
`ДД.ММ.ГГГГ`.

## 6. Какие форматы читаются

| Формат | Как читается |
|--------|--------------|
| `.xlsx`, `.xlsm`, `.xltx`, `.xltm` | `openpyxl` (потоковый режим — файлы на сотни МБ) |
| `.xls` | `xlrd` |
| `.xlsb` | `pyxlsb` (необязательная зависимость) |
| `.csv`, `.tsv`, `.txt` | автоопределение кодировки (utf-8/cp1251/cp866) и разделителя |
| HTML-таблица с расширением `.xls`/`.xlsx` | встроенный HTML-парсер — частая выгрузка из 1С и с сайтов СРО |
| `.zip`, `.rar` | `zipfile` / `rarfile` (+ внешние распаковщики), включая вложенные архивы |

Реальный формат определяется по сигнатуре файла, а не по расширению. Если
профильный ридер не справился, включается запасной путь через
`pandas.read_excel(..., sheet_name=None, header=None)` — он читает сразу все листы.

## 7. Как распознаются колонки

Никаких предположений о названиях столбцов не делается. Работают два механизма.

**По заголовкам.** Шапка ищется в первых `--header-scan-rows` строках листа
(по умолчанию 60) и может занимать до `--header-max-span` строк — это покрывает
«многоэтажные» шапки с объединёнными ячейками. Заголовок нормализуется (регистр,
«ё», пунктуация, переносы) и сопоставляется с набором шаблонов, поэтому
одинаково опознаются `Наименование`, `Полное фирменное наименование`,
`Наименование члена СРО`, `Контрагент`, `ФИО`, а также `ИНН`,
`Идентификационный номер налогоплательщика`, `Дата вступления в СРО`,
`Членство с`, `дата приёма`, `Дата исключения`, `Тел.`, `E-mail`,
`Место нахождения` и десятки других вариантов.

**По содержимому.** Всё, что не определилось по заголовку (или если шапки нет
вообще), определяется по самим данным:

* ИНН — по **контрольной сумме** ФНС (10 и 12 знаков);
* даты — по успешному разбору, включая серийные числа Excel;
* телефоны, e-mail, сайты, адреса — по формату значений;
* наименование — по организационно-правовой форме (`ООО`, `АО`, `ИП`, …) и кавычкам.

Дополнительно **каждая строка целиком** просматривается на предмет ИНН,
телефонов и e-mail: контакты часто «спрятаны» в колонках вроде «Примечание»
или склеены с другими данными.

## 8. Гарантии полноты

* обходятся **все** файлы, **все** листы и **все** строки;
* строка, из которой не удалось извлечь ни ИНН, ни названия, **не выбрасывается
  молча** — она попадает в `output/parsed/unrecognized_rows.csv` (и на вкладку
  `unrecognized_rows` при `--with-diagnostics`) вместе с полным содержимым и
  причиной;
* ошибка чтения одного файла, листа или строки не останавливает обработку
  остальных — она пишется в лог;
* вкладка `nostroy_contacts` содержит по строке на каждую исходную запись, со
  ссылкой на файл, лист и номер строки.

### Про дедупликацию

Запрос к checko.ru стоит единицы дефицитной суточной квоты, поэтому по умолчанию
(`--dedupe-by inn`) компании группируются **по ИНН**: одинаковый ИНН — это одно
юрлицо и одна карточка на checko.ru, сколько бы написаний названия ни встретилось
в разных файлах. Все варианты названия сохраняются в колонке «Варианты написания
названия», а все вхождения — в `nostroy_contacts`.

Если нужен буквальный вариант «уникальная пара название + ИНН» (и вы готовы
потратить на это больше квоты), укажите `--dedupe-by name_inn`.

## 9. Ключи командной строки

### Вход и выход
| Ключ | Назначение |
|------|-----------|
| `--input`, `-i` | архив `.rar`/`.zip`, Excel-файл или папка **(обязательный)** |
| `--output`, `-o` | папка результатов (по умолчанию `output`) |
| `--report-date` | дата в имени итогового файла (по умолчанию — сегодня) |

### Разбор таблиц
| Ключ | Назначение |
|------|-----------|
| `--dedupe-by {inn,name_inn}` | правило уникальности компании (по умолчанию `inn`) |
| `--header-scan-rows N` | сколько верхних строк искать шапку (60) |
| `--header-max-span N` | максимальная высота шапки в строках (3) |
| `--content-sample N` | сколько значений колонки анализировать при автодетекте (400) |

### checko.ru
| Ключ | Назначение |
|------|-----------|
| `--no-checko` | не обращаться к checko.ru, только разобрать реестр |
| `--daily-limit N` | суточный лимит запросов (100) |
| `--workers N`, `-w` | число параллельных потоков (4) |
| `--rps ЧИСЛО` | максимум запросов в секунду суммарно (1.0) |
| `--timeout СЕК` | таймаут HTTP-запроса (25) |
| `--max-retries N` | повторов при сетевых сбоях и 5xx (3) |
| `--user-agent СТРОКА` | заголовок User-Agent |
| `--proxy URL` | прокси (по умолчанию берётся из `HTTPS_PROXY`) |
| `--no-query-by-name` | не искать по названию, если в реестре нет ИНН |
| `--count-http-requests` | списывать квоту за каждый HTTP-запрос |
| `--retry-failed` | повторить компании с ошибками, игнорируя лимит в 3 автопопытки |
| `--reset-state` | удалить сохранённый прогресс и начать сбор с нуля |
| `--max-companies N` | обработать не более N компаний за запуск (отладка) |

### Прочее
| Ключ | Назначение |
|------|-----------|
| `--with-diagnostics` | добавить служебные вкладки в отчёт |
| `--no-progress-bar` | отключить прогресс-бар |
| `--log-level {DEBUG,INFO,WARNING,ERROR}` | подробность вывода |
| `--version` | версия скрипта |

## 11. Тесты

```bash
python -m unittest discover -s tests -v
```

42 теста, интернет не требуется: обращения к checko.ru эмулируются локальным
HTTP-сервером, который отдаёт заготовленные страницы и коды `200/403/404/429/503`.
Проверяются в том числе главные сценарии ТЗ:

* исчерпание суточного лимита и **продолжение на следующий день** без повторных
  запросов по уже собранным компаниям;
* соблюдение лимита при работе в несколько потоков (ровно N запросов при лимите N);
* чтение всех листов всех форматов, включая HTML с расширением `.xls`;
* определение колонок при нестандартных заголовках и при полном их отсутствии;
* сохранение нераспознанных строк.

Сгенерировать тестовый архив отдельно (чтобы попробовать скрипт «вживую»):

```bash
python tests/make_fixtures.py ./demo
python main.py --input "./demo/Реестр НОСТРОЙ.zip" --output ./demo/output --no-checko
```

## 12. Частые вопросы

**Скрипт нашёл 0 записей.** Посмотрите `output/parsed/files_index.csv` и лог: там
видно, сколько строк прочитано из каждого файла. Если строки прочитаны, но записей
нет — все строки попали в `unrecognized_rows.csv` с указанием причины.

**Не распознались колонки.** Запустите с `--log-level DEBUG`: в логе для каждого
листа печатается итоговая карта колонок. Помогает увеличить `--header-scan-rows`,
если шапка находится глубже 60-й строки.

**checko.ru отдаёт 403.** Сервис заподозрил автоматизацию. Снизьте нагрузку:
`--workers 1 --rps 0.3`. Прогресс не потеряется — уже собранное сохранено.

**Нужно начать сбор заново.** `--reset-state` удаляет сохранённый прогресс
(данные с checko.ru придётся собирать снова, расходуя квоту).

**Как переносить прогресс между машинами.** Скопируйте
`output/state/checko_state.json` — в нём и счётчик квоты, и все собранные данные.

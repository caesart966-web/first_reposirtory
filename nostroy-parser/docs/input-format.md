# Формат входных файлов заказчика

Заказчик работает с выгрузками из базы Единого реестра НОСТРОЙ. Имя файла —
`reestr_nostroy_sro_<НОМЕР_СРО>_<ГГГГММДД>.xlsx`, например
`reestr_nostroy_sro_410_20260811.xlsx`. **Такие файлы будут приходить и дальше**,
поэтому разбор именно этой структуры должен работать без настройки.

## Что внутри

Один лист, названный по номеру СРО (`СРО 410`). Одна строка заголовков,
дальше данные. Размер — порядка 1600 строк, 31 колонка.

Колонки размечены **английскими именами полей базы**, а связанные справочники
разложены тройками `ID / code / title`:

| Колонка | Пример значения | Роль в разборе |
|---------|-----------------|----------------|
| `Регистрационный номер` | `666` | реестровый номер |
| `ИНН` | `7839024647` | ИНН |
| `ОГРН/ОГРНИП` | `1157800000544` | ОГРН |
| `ID` | `5835754` | — (внутренний ключ базы) |
| `member_type → ID / code / title` | `1 / 1 / ЮЛ` | тип лица (ЮЛ, ИП, Иностранное ЮЛ) |
| `member_status → ID / code / title` | `1 / 1 / Является членом` | **статус членства (только из `title`)** |
| `region_number → ID / code / title` | `78 / 78 / Санкт-Петербург` | регион |
| `full_description` | `Акционерное общество «Абсолют»` | **наименование (полное)** |
| `short_description` | `АО «Абсолют»` | наименование (сокращённое) |
| `КФ ОДО (взнос)`, `КФ ВВ (взнос)` | `200000` | — |
| `Уровень ответственности ВВ/ОДО` (по 4 колонки) | `Второй уровень…` | — |
| `СРО → ID / short_description / deactivate_message` | `410 / Ассоциация «ПОС»` | реквизиты самой СРО |
| `inventory_number` | `С-303-007839024647-0664` | — |
| `other_information` | `дата рождения 03.05.1970, место…` | **— (свободный текст, не поле)** |
| `members_total_liability` | `303465982.69` | — |

## Ключевые особенности, которые надо учитывать

1. **Дат вступления и исключения в файле НЕТ.** Ни в каком виде. Их источник —
   только открытый реестр (`reestr.nostroy.ru`, при неудаче `reestr.nopriz.ru`)
   по ИНН. Без этого шага колонки дат останутся пустыми, и это не ошибка разбора.

2. **Статус членства есть в файле** — `member_status → title` со значениями
   `Является членом` и `Исключен`. Он доступен сразу, без единого запроса,
   и должен браться из `title`, а не из `ID` (`1`/`2`).

3. **Контактов членов в файле нет** — ни телефонов, ни почты, ни адресов, ни
   руководителей. Всё это добывается через checko.ru по ИНН.

4. **`other_information` — ловушка.** Там свободный текст: даты рождения ИП,
   заметки вроде «в июле 2021 года ошибочно…». Ни датой, ни контактом эта
   колонка быть не может.

5. **Реквизиты СРО** (`СРО → …`) одинаковы во всех строках и не должны
   попадать в контакты компаний.

## Тесты, закрепляющие этот формат

* `TestColumnMapper.test_database_export_layout` — тройки `ID/code/title`,
  английские имена полей, шапка не поглощает строки данных;
* `TestColumnMapper.test_notes_text_never_yields_invented_dates` — из
  свободного текста даты не «додумываются»;
* `TestSroContactsNotMixedIn` — реквизиты СРО не смешиваются с данными членов.

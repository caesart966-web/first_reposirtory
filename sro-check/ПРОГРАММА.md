# Готовая программа: скачать и запустить

Это самый простой путь: обычное окно с кнопками, двойной клик, **Python
устанавливать не нужно**. Если предпочитаете запуск из исходников — см.
[КАК_ЗАПУСТИТЬ.md](КАК_ЗАПУСТИТЬ.md).

---

## Шаг 1. Скачать

1. Откройте страницу сборок:
   <https://github.com/caesart966-web/first_reposirtory/actions/workflows/build-sro-check.yml>
   (нужно быть залогиненным на GitHub — иначе кнопка скачивания не появится).
2. В списке выберите верхнюю запись с **зелёной галочкой ✓**.
3. Прокрутите страницу вниз до раздела **Artifacts**.
4. Нажмите на нужный файл:
   - **`SRO-Check-Windows`** — для Windows
   - **`SRO-Check-macOS`** — для Mac
5. Скачается ZIP-архив. Распакуйте его (правая кнопка → «Извлечь все…»).

Внутри — **«Проверка СРО.exe»** (или **«Проверка СРО.app»** на Mac) и копия
инструкции. Положите файл куда удобно, например на Рабочий стол.

> Сборки хранятся 90 дней. Если срок вышел и архивов нет — откройте на той же
> странице кнопку **Run workflow** справа сверху, и GitHub соберёт программу
> заново за пару минут.

---

## Шаг 2. Первый запуск: Windows покажет предупреждение

Дважды щёлкните по **«Проверка СРО.exe»**. Скорее всего появится синее окно:

> **Система Windows защитила ваш компьютер**
> Фильтр SmartScreen Microsoft Defender предотвратил запуск неопознанного приложения.

Это нормально и ожидаемо. Нажмите **«Подробнее»** → **«Выполнить в любом случае»**.

**Почему так.** Windows доверяет программам с цифровой подписью издателя.
Подпись — это платный сертификат (несколько сотен долларов в год), и у этой
утилиты его нет. Предупреждение означает ровно одно: «издатель неизвестен», —
а не то, что внутри что-то вредоносное. Исходный код целиком лежит в этом
репозитории, и собирает программу сам GitHub из этого кода — сборку можно
открыть и посмотреть, что именно выполнялось.

По той же причине антивирус изредка ругается на программы, собранные
PyInstaller. Если ваш антивирус удалил файл — добавьте его в исключения либо
пользуйтесь запуском из исходников.

### На Mac

macOS скажет, что программа «из неустановленного источника». Щёлкните по
приложению **правой кнопкой** → **«Открыть»** → в диалоге ещё раз **«Открыть»**.
Обычный двойной клик в первый раз не сработает — нужен именно этот путь.

Если macOS пишет, что файл «повреждён», выполните в Терминале:

```
xattr -dr com.apple.quarantine "/путь/к/Проверка СРО.app"
```

## Шаг 3. Работа в окне

Окно устроено сверху вниз в том порядке, в каком с ним работают.

**1. Файл Excel со списком компаний** — нажмите «Выбрать…» и укажите свой файл.

**2. Лист** — по умолчанию «Лиды по приоритету». Если лист называется иначе,
впишите его название.

**3. Проверить связь.** Введите ИНН компании, которая **точно состоит в СРО**,
и нажмите кнопку. В журнале появится, отвечают ли реестры и правильно ли
программа читает ответ. Это стоит делать каждый раз перед большим прогоном:
у реестров нет официального API, адреса иногда меняются, и лучше узнать об
этом за 10 секунд, чем через полчаса вхолостую.

**4. Начать проверку.** Пойдёт полоса прогресса и счётчики:

```
Проверено 145 из 393   ·   да: 60   нет: 80   не удалось: 5
```

393 компании — примерно 20–35 минут. Между запросами пауза 1–2 секунды,
чтобы не создавать нагрузку на государственный реестр. Окно можно свернуть.

**5. Остановить** — прерывает работу. Всё проверенное сохраняется; при
следующем запуске программа продолжит с места остановки, а не начнёт заново.

**6. Открыть результат / Открыть папку** — станут доступны, когда проверка
закончится.

### Галочка «только строки „не удалось проверить“»

Жёлтые строки — это не ошибка, а честный ответ: реестр не отозвался или
ответил непонятно. Поставьте эту галочку, выберите **файл с результатом**
(`..._с_СРО.xlsx`) и запустите ещё раз — программа обратится к реестру только
по жёлтым строкам, а «да» и «нет» не тронет. Можно повторять хоть на следующий
день.

### Дополнительные настройки

Галочка «дополнительные настройки» открывает то, что почти никогда не нужно:
длительность пауз, что считать ответом «да» (только действующее членство или
любая запись в реестре), опрос обоих реестров, игнорирование сохранённых
результатов и ручной ввод адресов API.

## Что получится

Рядом с вашим файлом появится **`ИмяФайла_с_СРО.xlsx`** — копия с дописанными
колонками:

| Колонка | Что внутри |
|---|---|
| Есть СРО? | `да` / `нет` / `не удалось проверить` |
| **Компания в реестре** | название организации так, как оно записано в реестре |
| Название СРО | саморегулируемая организация |
| Реестровый номер | номер записи |
| Статус членства | `действует` / `приостановлено` / `исключён` |
| Дата проверки, Источник, Примечание | когда, где и что пошло не так |

Колонка с ответом подкрашена: зелёный — «да», красный — «нет»,
жёлтый — «не удалось проверить». Шапка закреплена, автофильтр включён —
393 строки можно сразу отфильтровать по нужному значению.
На отдельном листе **«Итоги проверки»** — сводка: сколько чего вышло,
когда и с какими настройками. **Исходный файл не меняется.**

### Колонка «Компания в реестре» — зачем она

Проверка идёт по ИНН, и опечатка в ИНН не вызывает ошибки: реестр честно
находит запись — только про другую организацию. В файле появится уверенное
«да», и выглядеть оно будет достоверно.

Поэтому программа сравнивает название из вашего файла с названием из реестра
и при явном расхождении пишет в «Примечание»:

```
ВНИМАНИЕ: в реестре по этому ИНН другая компания — «ООО «Мостострой»».
Проверьте ИНН в исходном файле
```

Сравнение снисходительное: организационно-правовая форма и сокращения не
считаются расхождением («ООО "МЕГ"» и «ОБЩЕСТВО С ОГРАНИЧЕННОЙ
ОТВЕТСТВЕННОСТЬЮ "МЕГАПОЛИС"» — одна компания). Ругается только на явно
разные названия, иначе предупреждение обесценилось бы.

Там же появятся `..._кэш.json` (чтобы при повторном запуске не проверять всё
заново) и `..._лог.txt` (полная копия журнала).

## Чем эта версия отличается от запуска через Python

Одним: в неё **не входит запасная проверка через браузер**. Playwright тянет
за собой ещё около 150 МБ браузера, и класть это в файл, который вы скачиваете,
ради редкого сценария не стоит.

Практическая разница появляется, только если реестр сменит адрес API. Версия
из исходников в этом случае умеет открыть сайт в браузере, подсмотреть новый
адрес и подсказать его; готовая программа — нет, она сообщит, что связи нет.
Новый адрес можно вписать вручную в «дополнительных настройках».

Во всём остальном — тот же самый код и те же результаты.

## Если что-то не работает

**Программа не запускается, окно не появляется.**
Проверьте, не удалил ли файл антивирус. Скачайте архив заново и добавьте
папку в исключения.

**«не удалось проверить» у всех строк подряд.**
Сначала нажмите «Проверить связь» и посмотрите на причину.

- `сеть: ConnectionError` / `Timeout` — нет интернета или реестр недоступен.
  Реестры бывают закрыты для доступа из-за границы, тогда нужен российский IP.
- `HTTP 404` — **адрес API устарел**, реестр перенёс его. Это самая частая
  причина: официального API у реестров нет, и адреса меняются без предупреждения.
  Как найти новый — раздел ниже.
- `ошибка сервера 500` — адрес живой, но запрос не понравился серверу.
  В скобках после кода теперь показывается, что именно ответил сервер.

## Адреса API: откуда они берутся

Официального API у реестров нет — ни документации, ни обещания, что адрес
не изменится. Программа обращается по адресам, которые реестры используют
для своего же сайта, и когда те их меняют, проверка начинает возвращать
`HTTP 404`.

**Обычно ничего делать не нужно.** Если все прошитые адреса ответили 404,
программа сама открывает сайт реестра, вытаскивает подключённые к нему
скрипты и ищет в них действующий адрес API — ровно то же, что человек делает
руками через F12, только автоматически. В журнале это выглядит так:

```
[НОСТРОЙ] прошитые адреса не отвечают — ищу действующий в скриптах сайта…
[НОСТРОЙ] в скриптах сайта найдены возможные адреса API: 2
[НОСТРОЙ]    https://reestr.nostroy.ru/api/...
[НОСТРОЙ] рабочий эндпоинт: найден-1:get-inn (https://reestr.nostroy.ru/api/...)
```

Поиск выполняется один раз за запуск, а не по каждой компании.

После «Проверить связь» найденный адрес показывается отдельной строкой —
его стоит скопировать в поле «Адрес API» в дополнительных настройках, чтобы
программа больше не тратила время на поиск.

### Если автоматический поиск не справился

Тогда адрес придётся подсмотреть вручную. Занимает пару минут и делается
один раз. Нужен обычный браузер.

1. Откройте сайт реестра и найдите страницу поиска по членам СРО:
   - НОСТРОЙ — <https://reestr.nostroy.ru>
   - НОПРИЗ — <https://reestr.nopriz.ru>
2. Нажмите **F12** — откроется панель разработчика. Перейдите на вкладку
   **Network** («Сеть»).
3. Не закрывая панель, введите на странице ИНН любой компании и нажмите поиск.
4. В панели появятся строки запросов. Нажмите фильтр **Fetch/XHR** — останутся
   только обращения к API. Нужная строка обычно называется `search`, `list`
   или `member`.
5. Щёлкните по ней правой кнопкой → **Copy** → **Copy link address**
   («Копировать адрес ссылки»).

Полученный адрес вставьте в программе: галочка **«дополнительные настройки»** →
поле **«Адрес API НОСТРОЙ»** (или НОПРИЗ). После этого нажмите «Проверить связь» —
если появилось `[РАБОТАЕТ, найдено]`, можно запускать основную проверку.

В командной строке то же самое:

```
python check_sro.py --probe 7702521529 --nostroy-url "<вставленный адрес>"
```

Если пришлёте мне этот адрес и содержимое вкладки **Response** («Ответ») —
я пропишу его в программе по умолчанию, и настраивать вручную больше не придётся.

**«нет» у всех строк подряд.**
Подозрительно: скорее всего реестр изменил формат ответа. Программа сама
предупредит об этом после 25-й строки. Проверьте кнопкой «Проверить связь»
на ИНН компании, которая точно в СРО, — если её не находит, результату
доверять нельзя.

**Не сохраняется результат.**
Файл открыт в Excel. Закройте его — программа в этом случае не теряет данные,
а сохраняет копию с датой в имени.

# Проверка СРО по ИНН (НОСТРОЙ и НОПРИЗ)

Программа берёт список компаний из Excel, проверяет каждую по ИНН в двух
официальных реестрах саморегулируемых организаций и дописывает результат
новыми колонками в копию вашего файла.

**Главное правило программы:** она никогда не пишет «нет», если не уверена.
Если реестр не ответил, ответил непонятно или отдал чужие записи — в файле
будет «не удалось проверить». Ошибочное «нет СРО» дороже, чем «не проверено».

---

## 1. Что нужно установить (один раз)

Нужен Python 3.9 или новее — скачать с <https://www.python.org/downloads/>
(при установке на Windows поставьте галочку **Add Python to PATH**).

Дальше откройте терминал (Windows: «Командная строка», Mac: «Терминал»),
перейдите в папку с программой и выполните:

```bash
cd sro-check
pip install -r requirements.txt
playwright install chromium
```

Последняя строка нужна только для запасного способа проверки — через браузер.
Если она выдаст ошибку, ничего страшного: программа будет работать без неё,
просто без «плана Б».

---

## 2. Первый запуск — проверка, что реестры отвечают

**Сделайте это до основного запуска.** У реестров нет официально
опубликованного API, и адреса запросов время от времени меняются. Команда ниже
переберёт все известные варианты и покажет, какой работает сейчас:

```bash
python check_sro.py --probe 7702521529
```

Вместо `7702521529` подставьте ИНН любой компании, которая **точно состоит
в СРО** — так вы сразу увидите не только «сайт отвечает», но и «программа
правильно читает ответ».

Что вы увидите в ответе:

* `[РАБОТАЕТ, найдено]` — способ работает и компания найдена. Отлично, можно
  запускать основную обработку.
* `[РАБОТАЕТ, не найдено]` — способ работает, но этой компании в реестре нет.
* `[не подошёл]` — вариант не сработал, рядом написана причина.

Если ни один вариант API не подошёл, программа попробует открыть сайт
в браузере и **подсмотреть настоящий адрес API**. Тогда в конце вывода
появится готовая строка вида:

```
--nostroy-url "https://reestr.nostroy.ru/api/…/search"
```

Скопируйте её и добавьте к основной команде — дальше всё пойдёт быстро
и без браузера.

---

## 3. Основной запуск

```bash
python check_sro.py --input Компании_Список.xlsx
```

Программа сама найдёт лист «Лиды по приоритету» и колонки «ИНН»,
«Поставщик», «Приоритет».

В консоли будет видно, что происходит:

```
Проверено 45 из 393 | ООО «Стройка» | ИНН 7702521529 → да | Ассоциация «СРО Строители…»
  … промежуточный результат сохранён: Компании_Список_с_СРО.xlsx (да: 30, нет: 12, не удалось: 3)
```

Обработка 393 компаний занимает примерно **20–35 минут** — между запросами
стоит пауза 1–2 секунды, чтобы не нагружать государственный реестр.

Прерывать можно в любой момент (Ctrl+C) — всё проверенное сохранится.
Повторный запуск той же команды продолжит с места остановки, уже проверенные
компании заново не опрашиваются.

---

## 4. Что появится в файле

Исходный файл **не меняется никогда**. Результат пишется в новый файл
`Компании_Список_с_СРО.xlsx` рядом с исходным.

| Колонка | Что в ней |
|---|---|
| «Есть СРО? (проверить в НОСТРОЙ)» | `да` / `нет` / `не удалось проверить` — заполняется ваша существующая колонка |
| «Название СРО» | название саморегулируемой организации |
| «Реестровый номер» | номер записи в реестре |
| «Статус членства» | `действует` / `приостановлено` / `исключён` |
| «Дата проверки» | когда проверяли |
| «Источник» | НОСТРОЙ или НОПРИЗ |
| «Примечание» | если проверить не удалось — здесь причина |

Колонка с вердиктом подкрашивается: зелёный — да, красный — нет,
жёлтый — не удалось проверить (отключается флагом `--no-color`).

**Что считается ответом «да».** По умолчанию — только действующее членство.
Если компания в реестре есть, но её членство приостановлено или она исключена,
в колонке «Есть СРО» будет «нет», а колонки «Название СРО» и «Статус членства»
всё равно заполнятся — видно, на каком основании принято решение. Если нужно
наоборот (любая запись в реестре = «да»), добавьте `--verdict-basis found`.

Оформление исходного файла (шрифты, заливки, ширины колонок) сохраняется.
Единственное исключение — диаграммы и вставленные картинки: библиотека,
которая пересохраняет файл, их не переносит. Если на листе такое есть,
программа предупредит об этом при запуске. Ваш исходный файл при этом цел.

Строители проверяются сначала по НОСТРОЙ, проектировщики и изыскатели —
сначала по НОПРИЗ (по колонке «Приоритет»). Если в первом реестре компании
нет, программа на всякий случай проверит и во втором.

---

## 5. Перепроверить только неудачные строки

Ровно то, ради чего колонка «не удалось проверить» и существует:

```bash
python check_sro.py --input Компании_Список_с_СРО.xlsx --retry-failed
```

Строки, где уже стоит «да» или «нет», трогаться не будут — программа
обратится к реестру только по непроверенным.

---

## 6. Если что-то идёт не так

**Все компании подряд получают «не удалось проверить».**
Реестр недоступен или сменился адрес API. Запустите `--probe` (шаг 2).
Если и там всё красное — проверьте интернет; реестры иногда закрывают доступ
из-за рубежа, тогда нужен российский IP.

**Все компании подряд получают «нет».**
Это подозрительно, и программа сама об этом предупредит после первых
25 строк. Скорее всего, изменился формат ответа реестра. Запустите `--probe`
с ИНН компании, которая точно состоит в СРО, и посмотрите, находит ли её
программа.

**«не нашёл строку заголовков».**
Программа ищет строку, где есть колонка со словом «ИНН», в первых 20 строках
листа. Проверьте, что указан правильный лист: `--sheet "Лиды по приоритету"`.

**Медленно.**
Так и задумано — пауза между запросами обязательна. Ускорять
(`--delay-min 0.3 --delay-max 0.6`) не рекомендую: реестр может временно
заблокировать доступ, и вы получите пачку «не удалось проверить».

## 7. Все параметры

| Параметр | Зачем |
|---|---|
| `--input ФАЙЛ` | исходный Excel (по умолчанию `Компании_Список.xlsx`) |
| `--sheet ИМЯ` | лист (по умолчанию `Лиды по приоритету`) |
| `--output ФАЙЛ` | куда сохранить результат |
| `--probe ИНН` | диагностика: проверить один ИНН и показать подробности |
| `--retry-failed` | только строки «не удалось проверить» |
| `--recheck-all` | игнорировать кэш и проверить всё заново |
| `--limit N` | проверить только первые N строк (удобно для пробы) |
| `--delay-min` / `--delay-max` | пауза между запросами, секунды (1 и 2) |
| `--checkpoint-every N` | как часто сохранять промежуточный файл (20) |
| `--browser never\|auto\|always` | использовать ли браузер как запасной способ |
| `--show-browser` | показать окно браузера (посмотреть, что происходит) |
| `--nostroy-url` / `--nopriz-url` | задать адрес API вручную |
| `--check-all` | опрашивать оба реестра, даже если уже нашли в первом |
| `--verdict-basis active\|found` | считать «да» только действующее членство (по умолчанию) или любую запись |
| `--no-color` | не подкрашивать колонку с вердиктом |

Рядом с результатом создаются два служебных файла: `..._кэш.json`
(чтобы не проверять одно и то же дважды) и `..._лог.txt` (журнал работы).
Удалять их можно, но тогда следующий запуск начнёт всё сначала.

---

## 8. Честно о границах проверки

* Программа проверяет **членство компании в СРО** по Единым реестрам НОСТРОЙ
  и НОПРИЗ. Это не то же самое, что Национальный реестр специалистов (НРС) —
  там ищут не компании по ИНН, а физических лиц по фамилии.
* Результат — справочный. Для юридически значимого подтверждения нужна
  выписка из реестра СРО.
* Адреса API в программе — набор наиболее вероятных вариантов; официальной
  документации у реестров нет. Именно поэтому есть режим `--probe` и запасная
  проверка через браузер, который узнаёт актуальный адрес сам.
* Проверить программу на живых реестрах при разработке не удалось: среда,
  в которой она писалась, не имеет доступа в интернет. Логика проверена на
  локальном макете реестра, который воспроизводит и нормальные ответы,
  и типичные поломки (см. `tests/`). Поэтому первый запуск обязательно
  начинайте с `--probe`.

## 9. Тесты

```bash
python -m unittest discover -s tests -t . -v
```

46 тестов, живые реестры не дёргаются — вместо них локальный макет.
Отдельно проверяется главное обещание программы: при обрыве связи, ошибке
сервера, HTML вместо JSON, незнакомом формате ответа и «поиск вернул чужие
записи» в файл попадает «не удалось проверить», а не «нет».

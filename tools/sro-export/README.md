# Выгрузка реестра членов СРО (reestr.nostroy.ru)

Инструмент забирает полный список членов СРО напрямую из API реестра и сохраняет
его в `.xlsx` и `.csv`. Кнопка «сформировать реестр» на сайте не используется.

## Почему штатная выгрузка не работает

- `GET .../register/actual` отвечает `{"success":true,"data":{"actualRegisterIsExists":false}}` —
  это значит «готового файла реестра на сервере нет», а не «идёт подготовка».
- `POST .../register/generate` (генерация файла) отвечает **HTTP 500** — сборка файла
  падает на стороне сайта. Сколько ни жди, файл не появится: ждать нечего.
- При этом сам список членов отдаётся рабочим постраничным API, которым пользуется
  страница реестра. Через него всё выгружается за пару минут.

```
POST https://reestr.nostroy.ru/api/sro/<ID СРО>/member/list
{"filters": {}, "page": 1, "pageCount": "20", "sortBy": {}}
```

## Вариант 1 — в браузере (рекомендуется)

Работает всегда, потому что использует уже открытую сессию Chrome.

1. Открыть в Chrome страницу реестра нужной СРО.
2. `F12` → вкладка **Console**, контекст — `reestr.nostroy.ru`.
3. Вставить содержимое `nostroy-export.js` целиком и нажать Enter.
4. Дождаться в консоли `готово: N записей` — браузер сам скачает
   `reestr_nostroy_sro_<ID>_<дата>.xlsx` и `.csv`.

ID СРО берётся из адреса страницы; если определился неверно, задать вручную
**до** вставки скрипта:

```js
window.SRO_EXPORT_CONFIG = { sroId: 410, concurrency: 4, formats: ['xlsx', 'csv'] };
```

После выгрузки данные лежат в `window.SRO_RESULT`, пересохранить —
`SRO_SAVE('xlsx')` или `SRO_SAVE('csv')`.

## Вариант 2 — из командной строки

Без зависимостей, только стандартная библиотека Python 3.9+.

```bash
python3 nostroy_export.py --sro 410
```

Если API откажет без браузерной сессии (401/403/419), скопировать заголовок
`Cookie` из DevTools → Network и передать его:

```bash
python3 nostroy_export.py --sro 410 --cookie "имя=значение; имя2=значение2"
```

Полезные ключи: `--format xlsx,csv`, `--out имя_файла`, `--headers raw`
(оставить оригинальные имена полей API), `--concurrency`, `--page-count`.

## Что внутри выгрузки

Колонки формируются из фактического ответа API: скрипт разворачивает вложенные
объекты (`sro.name` → «СРО → Наименование») и берёт объединение всех полей по
всем записям, поэтому ничего не теряется, даже если у части организаций есть
дополнительные поля. Известные поля переименовываются по-русски
(Наименование, ИНН, ОГРН/ОГРНИП, Статус, Дата регистрации, взносы в КФ ВВ/ОДО,
уровни ответственности), остальные сохраняют имена из API.

В XLSX: закреплённая жирная шапка, автофильтр, подобранная ширина колонок.
ИНН, ОГРН, КПП и телефоны пишутся текстом — Excel не превратит их в
`1,07785E+12` и не съест ведущие нули. Денежные суммы остаются числами.
CSV — UTF-8 с BOM и разделителем `;`, открывается в русском Excel двойным кликом.

## Как это работает

- Подбирается максимальный `pageCount`, который сервер реально отдаёт
  (пробуются 500 → 100 → 50 → 20). Обычно вместо 80 запросов по 20 записей
  выходит 16 запросов по 100.
- Страницы качаются в 4 потока с паузой 120 мс между запросами.
- HTTP 429 и 5xx повторяются до 4 раз с экспоненциальной задержкой.
- Записи дедуплицируются по `id` — защита от сдвига пагинации, если реестр
  изменится прямо во время выгрузки.
- В конце сверяется количество собранных записей с `count` из ответа API,
  расхождение и незагруженные страницы выводятся предупреждением.

## Проверка

Логика проверена на моке API (1590 записей, сервер урезает `pageCount` до 100,
одна страница отдаёт HTTP 500): обе реализации собирают все 1590 записей,
переспрашивают упавшую страницу и дают идентичную таблицу; полученные `.xlsx`
открываются без ошибок и предупреждений.

```bash
python3 nostroy_export.py --sro 410 --base-url http://127.0.0.1:8731 --out test
```

## Ограничения

- Выгружаются только те поля, что отдаёт API списка. Данных, которые сайт
  подгружает на карточке отдельной организации, здесь нет.
- Реестр открытый, но скрипт создаёт нагрузку на чужой сервер: не стоит
  повышать `concurrency` и убирать паузу без необходимости.

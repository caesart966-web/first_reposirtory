# Состояние работ

Файл для передачи контекста между сессиями. Чат сворачивается в конспект и
детали теряются — здесь они переживают и это, и смену компьютера.

**Правило:** после каждого заметного шага дописывать сюда одну-две строки.
Читать в начале работы.

---

## Главное правило проверки по реестрам

**Не выкачивать реестр целиком — пробивать свои ИНН по одному.** Постраничная
выгрузка обрывается молча: НОПРИЗ заявил 212 074 записи и отдал 147 860,
и по ростовской когорте из-за этого потерялись 47 компаний из 125 (38%).
Команда `проверить` в обоих скриптах спрашивает реестр по каждому ИНН
отдельно — медленнее, зато без потерь.

```cmd
python выгрузка_ностроя.py проверить --file ваш_файл.xlsx --out нострой.xlsx
python нопориз.py          проверить --file ваш_файл.xlsx --out ноприз.xlsx
```

Обе команды кладут рядом файл `.progress.json` и умеют `--resume`.

**Как убедиться, что взяли всё.** Взять компании, про которые ответ известен
заранее (например, члены СРО, реестр которой у вас на руках), прогнать их
той же командой и посчитать, скольких она не нашла. По СФЕРЕ так и поймали
пробел: строительных не нашлось 53 из 640 (8.3%), проектных 2 из 367,
изыскательских 0 из 157.

## Грабли, на которые уже наступали

- **Постраничная выгрузка обрывается молча** — см. главное правило выше.
  Расхождение заявленного и полученного — это потеря данных, пока не
  доказано обратное.
- **«Нет в реестре» и «членство прекращено» — разные вещи.** Раньше скрипты
  писали «нет» и там, и там: исключённые записи просто пропускались. Из-за
  этого было не понять, потеряли мы компанию при выгрузке или она честно
  выбыла. Теперь есть колонки «Было строительное (прекращено)», «Было
  проектное (прекращено)», «Было изыскательское (прекращено)» и дата выхода.
  Для продаж это тоже разное: выбывшая через год после исключения снова
  обязана вступить в СРО, а никогда не состоявшая — совсем другой разговор.
- **Реестры игнорируют `pageSize`** и отдают по 20 записей, не сообщая об
  этом. Правильное поле — `pageCount`, и **строкой**. Тело запроса:
  `{"filters": {}, "page": N, "pageCount": "500", "searchString": "", "sortBy": {}}`.
- **Реестры молча игнорируют незнакомый фильтр** и возвращают общий список
  вместо отфильтрованного.
- **Поиск идёт по строке**, поэтому в ответ попадают чужие компании —
  ИНН каждой записи надо сверять.
- **ID СРО ≠ регистрационный номер.** `reestr.nostroy.ru/sro/247` — это ID,
  а `СРО-С-230-07092010` — номер; `--sro-number` переводит одно в другое.
- **Списка СРО у НОСТРОЯ нет ни по одному известному адресу API** — ID
  приходится смотреть руками на сайте.
- **ИНН в Excel хранятся числом** — у регионов 01–09 теряется ведущий ноль.
- **Вид деятельности СРО — по её регистрационному номеру** (`СРО-П-` /
  `СРО-И-`), а не по названию: ООО «Проектстрой» в изыскательской СРО иначе
  уезжает в проектирование.
- **Телефон в выгрузке ≠ по нему ответят.** У ЦСО собственный номер СРО
  стоял у 2048 членов из 2055. Колонка «Свой телефон» это помечает.
- **Осечка сети не должна закрывать компанию навсегда.** Checko-скрипт
  помечает временные сбои и переспрашивает их на следующем запуске.
- **Долгие команды молчали** и выглядели зависшими — теперь печатают счётчик
  строк каждые 25 тысяч.

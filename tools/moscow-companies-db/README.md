# mosstroybase — база строительных компаний Москвы

CLI-инструмент, который собирает базу **юридических лиц с московским адресом**
и строительными ОКВЭД (стройка, проектирование, инженерные изыскания), находит
их **телефоны и e-mail** и выгружает общую базу в CSV/XLSX.

## Откуда данные

| Шаг | Источник | Что даёт |
|---|---|---|
| `build` | [Реестр МСП ФНС](https://www.nalog.gov.ru/opendata/7707329152-rsmp/) (официальные открытые данные, бесплатно) | базовый список юрлиц: ИНН, ОГРН, название, регион, ОКВЭД |
| `enrich-checko` | [Checko API](https://checko.ru/integration/api) (нужен бесплатный ключ, ~100 запросов/сутки) | телефоны, e-mail, сайт, руководитель (ФИО и должность), полный адрес, статус |
| `enrich-sites` | сайты компаний (страницы контактов) | телефоны, e-mail |
| `enrich-sro` | [реестр НОСТРОЙ](https://reestr.nostroy.ru) (бесплатно) | членство в строительной СРО (для отсева) |
| `enrich-egrul` | ЕГРЮЛ-зеркало — **бесплатный JSON-доступ закрыт** (egrul.itsoft.ru → egrul.org, теперь платная подписка) | шаг стал необязательным: руководителя/адрес/статус/e-mail даёт Checko |

Отбор по умолчанию: регион **77 (Москва)**, ОКВЭД-2 **41, 42, 43** —
чистая стройка (здания, инженерные сооружения, специализированные
работы). Проектирование и изыскания (71.11/71.12) по умолчанию не
берутся — вернуть их можно опцией `--okved 41 42 43 71.11 71.12`.
В работу (`daily`/`enrich-checko`) идут только компании, у которых
строительный ОКВЭД **основной**; флаг `--include-secondary` подключает
и тех, у кого стройка лишь в дополнительных кодах.

## Установка

```bash
cd tools/moscow-companies-db
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

## Использование (конвейер)

```bash
# 1. Скачать выгрузку реестра МСП (~1.5–2 ГБ, обновляется ежемесячно)
python -m mosstroybase fetch-rsmp --out data/rsmp.zip

# 2. Отобрать московские строительные/проектные/изыскательские юрлица в SQLite
python -m mosstroybase build --rsmp-file data/rsmp.zip

# 3. Обогатить из ЕГРЮЛ: e-mail, статус, адрес (небыстро — пауза между запросами)
python -m mosstroybase enrich-egrul

# 4. (опционально) Телефоны и сайты через Checko API
export CHECKO_API_KEY=ваш_ключ
python -m mosstroybase enrich-checko --limit 100

# 5. (опционально) Добрать контакты со страниц сайтов компаний
python -m mosstroybase enrich-sites

# 6. Сводка и выгрузка
python -m mosstroybase stats
python -m mosstroybase export --csv moscow_stroy.csv --xlsx moscow_stroy.xlsx \
    --only-active --with-contacts-only
```

Все команды принимают `--db путь.sqlite3` (по умолчанию `mosstroybase.sqlite3`
в текущей папке). База наполняется инкрементально: повторный запуск дополняет
записи, дубликаты схлопываются по ИНН, контакты из разных источников
объединяются. Обогащение можно прерывать и продолжать — уже обработанные
компании помечены источником и повторно не запрашиваются.

Полезные варианты:

```bash
# Пробный прогон на 200 компаниях
python -m mosstroybase build --rsmp-file data/rsmp.zip --limit 200

# Свои ОКВЭД и регион
python -m mosstroybase build --rsmp-file data/rsmp.zip --okved 41 42 43 71.1 --region 77

# Добавить крупные компании (их нет в реестре МСП) списком ИНН
python -m mosstroybase import-inn --file inns.txt   # затем enrich-egrul
```

## Политика телефонов: две колонки

Телефоны в выгрузке разделены по степени доверия:

- **«Телефоны (Checko)»** — официальный источник, проверенные номера;
  сюда же попадают номера с сайта, совпавшие с Checko.
- **«Телефоны с сайта (проверить)»** — найдены на сайте компании, но не
  подтверждены Checko; прозванивать во вторую очередь.

Мусор отсекается валидацией (реальные коды РФ, запрет матчей внутри
длинных чисел), команда `clean-phones` чистит уже накопленную базу.

## Если главное — телефоны (Checko)

Телефоны в основном приходят из Checko API, а его бесплатный тариф — ~100
запросов в сутки. Программа тратит квоту экономно: по умолчанию
`enrich-checko` пропускает ликвидированные компании и те, у кого телефон уже
найден, а первыми запрашивает компании с **основным** строительным ОКВЭД.
Обработанные помечаются и повторно не запрашиваются, поэтому рабочий режим —
просто запускать команду раз в сутки:

```bash
export CHECKO_API_KEY=ваш_ключ
python -m mosstroybase enrich-checko --limit 100   # ежедневно
python -m mosstroybase enrich-sites                # бесплатно добирает контакты с сайтов,
                                                   # которые дал Checko
```

### Фильтр СРО: члены строительных СРО отсекаются

Если база нужна для поиска компаний, ещё НЕ состоящих в строительной СРО,
программа проверяет каждый ИНН по открытому реестру **НОСТРОЙ** (бесплатно,
без ключей). Действующие члены строительных СРО:

- не тратят квоту Checko (проверка выполняется до запроса);
- не попадают в выгрузки CSV/XLSX (вернуть: `export --include-sro`);
- остаются в SQLite с пометкой — чтобы не проверять их повторно.

Членство в проектно-изыскательских СРО (реестр НОПРИЗ) не проверяется и
поводом для отсечения не является. Исключённые из СРО обрабатываются по
правилу года (ГрК РФ: после исключения год нельзя вступить в новую СРО):
исключённые **менее года назад** отсекаются наравне с членами, **год и
более назад** — остаются лидами с датой исключения в колонке «СРО»;
если дату определить не удалось — компания остаётся с пометкой
«проверьте вручную».

Пометить всю базу разом (рекомендуется после `enrich-egrul`):

```bash
python -m mosstroybase enrich-sro
```

Команда `daily` проверяет СРО сама — по ходу дневной пачки.

### Ежедневный автозапуск: команда `daily`

Одна команда делает всё сразу: обрабатывает дневную пачку через Checko,
добирает контакты с сайтов из этой пачки и кладёт два файла в `exports/`:
`companies_ГГГГ-ММ-ДД.xlsx` (сегодняшние компании) и `companies_all.xlsx`
(вся база: действующие компании с контактами).

```bash
python -m mosstroybase daily            # ключ — из CHECKO_API_KEY
```

Автозапуск по расписанию (компьютер должен быть включён в это время):

```bash
# Linux/macOS: crontab -e, запуск каждый день в 09:00
0 9 * * * cd /путь/до/tools/moscow-companies-db && CHECKO_API_KEY=ключ .venv/bin/python -m mosstroybase daily >> daily.log 2>&1
```

```powershell
# Windows: Планировщик заданий (от имени пользователя), ежедневно в 09:00
schtasks /Create /SC DAILY /ST 09:00 /TN mosstroybase-daily /TR "cmd /c cd /d C:\путь\до\tools\moscow-companies-db && .venv\Scripts\python -m mosstroybase daily >> daily.log 2>&1"
```

Перед первым `daily` база должна быть собрана: `fetch-rsmp` → `build` →
`enrich-egrul` (см. выше).

Математика: 100 запросов/сутки ≈ 36 тыс. компаний в год. Если база в десятки
тысяч компаний и телефоны нужны быстро, варианты:

- **платный тариф Checko** (тысячи запросов в сутки — см. цены на checko.ru);
- **готовая выгрузка ОФДата** (ofdata.ru — поставщик данных Checko): продают
  базу организаций с контактами целиком, для массовой задачи это дешевле и
  быстрее, чем API;
- сузить базу перед обогащением: `--only-active`, только нужные ОКВЭД,
  категории «малое»/«среднее» вместо «микро».

## Ограничения и честные оговорки

- **Реестр МСП покрывает только малый и средний бизнес.** Крупных застройщиков
  и генподрядчиков добавляйте через `import-inn` — остальное дотянет ЕГРЮЛ.
- **Телефонов в ЕГРЮЛ почти нет** (e-mail — есть у заметной части компаний).
  Основные источники телефонов — Checko API и сайты компаний.
- Зеркало egrul.itsoft.ru — сторонний бесплатный сервис: работайте с паузами
  (`--delay`), не гоняйте десятки тысяч запросов подряд.
- Полные коммерческие альтернативы, если нужен масштаб: платная выгрузка ЕГРЮЛ
  ФНС, DaData, Контур.Фокус, СПАРК.

## Правовые заметки

- Сведения ЕГРЮЛ и реестра МСП — открытые данные; контактные данные юрлиц
  не являются персональными данными. Если включаете ИП (`--include-ip`),
  их данные — персональные: соблюдайте 152-ФЗ.
- Массовые рассылки по собранным адресам подпадают под закон «О рекламе»
  (ст. 18: реклама по сетям связи — только с согласия адресата). База
  предназначена для аналитики рынка и адресной B2B-работы.
- Уважайте условия использования сторонних API и сайтов.

## Отдельные скрипты для реестра НОСТРОЙ

Помимо пакета `mosstroybase`, в папке лежат два самостоятельных скрипта —
им нужны только `requests` и `openpyxl`, к базе SQLite они не обращаются.

### `выгрузка_ностроя.py` — кто вступил в конкретные СРО

```bash
# по регистрационному номеру СРО — так их называют в документах и разговоре
python выгрузка_ностроя.py выгрузка --sro-number С-230 С-306 С-265 \
       --since 01.01.2026 --until 31.12.2026 --out новые_члены.xlsx

# то же самое по ID из адреса страницы reestr.nostroy.ru/sro/247
python выгрузка_ностроя.py выгрузка --sro-id 247 75 --out новые_члены.xlsx

python выгрузка_ностроя.py список-сро --out сро.xlsx   # все СРО: ID, номер, название
python выгрузка_ностроя.py образец --sro-id 247        # диагностика: сырые записи
```

У СРО два разных идентификатора, и путать их дорого: **ID** — число в адресе
страницы (`reestr.nostroy.ru/sro/247`), **регистрационный номер** — вида
`СРО-С-230-07092010`. Быстрый путь выгрузки работает по ID, поэтому
`--sro-number` сначала переводит номер в ID по списку СРО; принимаются формы
`С-230`, `СРО-С-230-07092010` и просто `230`, латинская `C` тоже (на
клавиатуре она от кириллической неотличима).

Особенности реестра, выясненные на живых данных:

- дата вступления лежит в поле `registry_registration_date`
  (формат `2018-02-12T00:00:00+03:00`);
- реестр **игнорирует** запрошенный размер страницы и отдаёт по 20 записей,
  поэтому число страниц считается по фактическому размеру ответа — иначе
  читается лишь пятая часть списка;
- на отдельных страницах реестр периодически отвечает HTTP 500; такие
  страницы не обрывают выгрузку, а повторяются в конце, и если не поддались —
  выводится явное предупреждение о неполноте;
- у действующих членов в записи бывает **плановая** дата окончания права,
  поэтому «бывший член» определяется прежде всего по тексту статуса, а не по
  самому факту наличия даты прекращения.

### `разбор_выгрузки.py` — официальная выгрузка членов СРО

На странице СРО (`reestr.nostroy.ru/sro/294`) есть кнопка «Выгрузить реестр
членов СРО». Она отдаёт Excel по 500 членов в файле и **сразу с телефонами** —
это надёжнее API: у НОСТРОЯ не отвечает ни список СРО, ни выборка членов по ID,
а полный перебор реестра это 418 тысяч записей и часы.

```bash
python разбор_выгрузки.py --файлы register*.xlsx \
       --nopriz нопориз_исправленный.xlsx --out экспертстрой.xlsx
```

Листы на выходе: «Нет в НОПРИЗ» (база под обзвон), «Исключённые» (членство
прекращено — СРО у них уже нет, а контакты остались), «Общие телефоны»,
«Все члены».

`--свод все_сро.xlsx` дополнительно собирает все найденные СРО в один файл:
сводка по каждой, общий список под обзвон, отдельный лист «Для Checko» и
исключённые.

Про общие телефоны: один номер у десятка компаний — это почти всегда не они
сами, а агент, который их приводил, либо сама СРО. Телефон СРО берётся из
карточки в самой выгрузке.

Ключевая колонка — **«Свой телефон»**. У «ЦСО» её собственный номер записан
у 2048 членов из 2055: формально телефон есть у всех, а звонить некуда. Такие
компании уходят в Checko наравне с теми, у кого поле пустое, иначе половина
базы под обзвон оказывается мёртвой. По трём московским СРО это 2842 компании
из 4176, причём у «ЭкспертСтроя» таких всего 67, а у «ЦСО» — все до одной.

### `checko_контакты.py` — телефоны к готовому файлу

```bash
set CHECKO_API_KEY=ключ
python checko_контакты.py --file новые_члены.xlsx --limit 100
```

Пробивает ИНН из Excel-файла через Checko и дописывает колонки с пометкой
`(Checko)` — пометка нужна, чтобы не конфликтовать с колонками `Статус` и
`Адрес` из выгрузки НОСТРОЯ. Уже заполненные строки пропускаются, поэтому
команду можно запускать ежедневно, пока не кончатся компании.

Почему не `enrich-checko`: та команда намеренно пропускает членов
строительных СРО (для продаж СРО они не лиды) и требует строительный ОКВЭД.
Здесь задача обратная — добрать контакты как раз для свежих членов СРО.

## Проверка по реестру НОПРИЗ: `нопориз.py`

НОПРИЗ — объединение проектировщиков и изыскателей; его СРО делятся на два
вида деятельности, поэтому в отчёте две отдельные колонки с датами вступления.

```bash
# 1. Один раз скачать реестр целиком (в нём ~212 тыс. членств; можно прерывать
#    и повторять с --resume — прогресс сохраняется)
python нопориз.py выгрузка --out нопориз_реестр.xlsx

# 2. Сверить свой файл: колонка ИНН находится автоматически
python нопориз.py сверить --file реестр_сро.xlsx --nopriz нопориз_реестр.xlsx \
       --out реестр_сро_с_НОПРИЗ.xlsx

# Если результат выглядит подозрительно — посмотреть сырую запись реестра
python нопориз.py образец
```

Дописываются колонки «Проектирование: дата вступления», «Проектирование: СРО»,
«Изыскания: дата вступления», «Изыскания: СРО» и «В НОПРИЗ». Берётся самое
раннее **действующее** членство каждого вида; исключённые не учитываются.
Строки без ИНН помечаются «нет ИНН», а не «нет»: их никто не проверял.

Вторым листом идёт «Нет в НОПРИЗ» — компании, которых в реестре нет: для
продаж проектного или изыскательского СРО это и есть база под обзвон. Строки
без ИНН туда не попадают: «не проверяли» — не то же самое, что «не состоит».

Третьим листом «Вступили после стройки» идут компании, добравшие проектирование
или изыскания **позже** вступления в строительную СРО — то есть расширявшие
профиль уже работающей фирмой. Дата вступления в строительную СРО берётся из
колонки `--дата-стройки` (по умолчанию «Дата вступления НП»). Разница в днях
показана по каждому виду отдельно, в том числе отрицательная: если
проектирование было раньше стройки, а изыскания позже, компания в выборку
попадает, и по знаку это видно.

`--мин-дней 30` отсекает тех, кто оформлял всё одним заходом: на реестре из
1561 компании 12 из 59 вступили в НОПРИЗ через 2–20 дней после строительной
СРО — это не «расширили профиль потом», а один и тот же поход.

Вид деятельности определяется по регистрационному номеру СРО — он прямо
кодирует его буквой (`СРО-П-…` проектные, `СРО-И-…` изыскательские). По
названиям судить нельзя: ООО «Проектстрой» в изыскательской СРО иначе
получало бы «проектирование» из собственного названия. Сам номер сохраняется
в выгрузке, поэтому вид можно пересчитать, не выкачивая реестр заново.

Если вид деятельности определился не у всех (скрипт скажет, у скольких),
чинить это можно **без повторной выгрузки** — реестр качается часами:

```bash
# все СРО из выгрузки: сколько записей и какой вид определился
python нопориз.py виды --nopriz нопориз_реестр.xlsx --out виды_сро.xlsx

# заполнить пустой «Вид деятельности» руками и переписать выгрузку
python нопориз.py пересчитать --nopriz нопориз_реестр.xlsx \
       --справочник виды_сро.xlsx --out нопориз_реестр.xlsx
```

Разных СРО в НОПРИЗ пара сотен, поэтому список проверяется глазами целиком —
в отличие от полутора сотен тысяч записей.

Реестр отдаёт по 20 записей на страницу и обычно игнорирует `pageSize` — это
десять тысяч страниц и пара часов. Поэтому перед выгрузкой скрипт перебирает
имена параметра (`perPage`, `limit`, …) и проверяет, что вторая страница
отличается от первой: без такой проверки параметр вида limit/offset тихо
выдал бы десять тысяч копий первой страницы. Имя можно задать руками:
`--page-size-key limit`.

### Точечная проверка вместо общей выгрузки

```bash
python нопориз.py проверить --file мои_компании.xlsx --out проверка.xlsx
```

**Это основной способ.** Общая выгрузка оказалась неполной: реестр заявил
212 074 записи, отдал 147 860 и закончился, а ручная проверка нашла компании,
которые в НОПРИЗ состоят, но в выгрузку не попали. Точечный поиск по ИНН таких
потерь не даёт.

Формат запроса подсмотрен в браузере и оказался другим, чем мы предполагали:
размер страницы называется `pageCount` и передаётся строкой, поиск — через
`searchString`. Мы слали `pageSize`, реестр молча его игнорировал и отдавал
свои 20 записей на страницу — отсюда и двухчасовая выгрузка, и, судя по всему,
её обрыв.

## Обновление кода на рабочей машине: `update.ps1`

Скачивает из GitHub только папку `tools/moscow-companies-db` — скрипты и пакет
`mosstroybase`. База `mosstroybase.sqlite3`, выгрузки и `.venv` не трогаются.
Список файлов берётся из GitHub API, поэтому новые скрипты подхватываются сами.

```powershell
powershell -ExecutionPolicy Bypass -File update.ps1
```

Если самого `update.ps1` ещё нет (или он старый и не работает), он качается
одной командой из рабочей папки:

```powershell
powershell -ExecutionPolicy Bypass -Command "[Net.ServicePointManager]::SecurityProtocol=[Net.SecurityProtocolType]::Tls12; Invoke-WebRequest 'https://raw.githubusercontent.com/caesart966-web/first_reposirtory/claude/moscow-construction-companies-db-khnge4/tools/moscow-companies-db/update.ps1' -OutFile update.ps1 -UseBasicParsing"
```

Что уже сломалось однажды и учтено здесь: Windows PowerShell 5.1 без явного
`Tls12` не соединяется с GitHub, прогресс-бар `Invoke-WebRequest` замедляет
скачивание в разы, а `$ErrorActionPreference = 'Stop'` рвал весь проход из-за
одного файла. Теперь ошибки собираются и печатаются в конце, а неизменившиеся
файлы вычисляются по git-хешу и вообще не качаются.

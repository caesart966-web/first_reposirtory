# company-intel — автоматический сбор данных о компании

Вы вводите то, что знаете (название, ИНН, домен, телефон или почту) — программа
сама раскручивает остальное: реквизиты из госреестра, контакты с сайта,
поддомены, соцсети, людей и их должности. Каждое найденное значение приходит
со **ссылкой на источник** и **оценкой уверенности**, поэтому его можно
перепроверить, а не принимать на веру.

```bash
company-intel search --name "ООО Ромашка" --city Москва
company-intel search --inn 7707083893 --format md --out romashka.md
company-intel search --domain romashka.ru --guess-emails
```

## Что программа делает

1. **Нормализует вход.** `8 (495) 123-45-67` и `+7 495 1234567` — один номер.
   ИНН и ОГРН проверяются по контрольной сумме сразу: опечатка отсекается до
   первого запроса в сеть.
2. **Запускает источники параллельно** — те, которым хватает входных данных.
3. **Раскручивает клубок по раундам.** Нашёлся домен → включаются DNS, RDAP,
   сертификаты, обход сайта. Нашлось ФИО директора → включаются гипотезы
   корпоративных адресов. Нашёлся ИНН → подтягивается карточка из реестра.
   Источник перезапускается, только если его входные данные изменились.
4. **Сливает находки и считает уверенность** (см. ниже).
5. **Отдаёт отчёт** в text / Markdown / JSON / CSV.

## Границы: что программа не делает

Это инструмент работы с **открытыми и коммерчески доступными** источниками.
В нём намеренно нет и не будет:

- утечек и «слитых баз» (сами по себе нелегальны, а данные в них устаревшие
  и непроверяемые);
- обхода авторизации, подбора паролей, доступа к закрытым системам;
- скрейпинга поисковой выдачи в обход API и обхода капчи;
- SMTP-опроса чужих серверов (`RCPT TO`) для проверки адресов — он грузит
  чужую инфраструктуру и приводит к попаданию IP в чёрные списки.

Закрытые данные, доступные легально, закрываются платными B2B-базами: DaData,
Checko, Hunter.io, 2ГИС — под них в программе есть готовые разъёмы, нужен
только ключ.

## Установка

```bash
cd backend/company-intel
pip install -e .              # или: pip install -r requirements.txt
pip install dnspython         # MX/SPF/NS (опционально, но полезно)
company-intel demo            # разбор встроенного примера, без сети и ключей
company-intel sources         # какие источники готовы, каких ключей не хватает
```

Ключи задаются в переменных окружения или в файле `.env` рядом с проектом
(см. `.env.example`; `.env` в `.gitignore` и в репозиторий не попадает).

## Источники

| Источник | Что даёт | Ключ |
|---|---|---|
| `dadata` | Реквизиты из ЕГРЮЛ/ЕГРИП: полное имя, адрес, руководитель, ОКВЭД, статус | `DADATA_TOKEN` (бесплатно, 10k/сут) |
| `egrul` | То же напрямую с egrul.nalog.ru, если нет токена DaData | — |
| `checko` | Карточка компании, контакты, руководители | `CHECKO_KEY` |
| `website` | Обход сайта: почты, телефоны, адреса, ИНН/ОГРН, люди, соцсети | — |
| `dns` | MX (почтовый провайдер), SPF (смежные домены), NS | — |
| `rdap` | Регистратор домена, даты, контакты (для gTLD) | — |
| `crtsh` | Поддомены из публичных TLS-сертификатов | — |
| `search` | Каталоги, отзывы, вакансии, тендеры через API поисковиков | `SERPAPI_KEY` / `GOOGLE_CSE_KEY`+`GOOGLE_CSE_CX` / `YANDEX_XML_USER`+`YANDEX_XML_KEY` / `BRAVE_API_KEY` |
| `2gis` | Справочник: телефон, адрес, режим работы | `TWOGIS_KEY` |
| `hunter` | Корпоративные адреса по домену, с именами и должностями | `HUNTER_API_KEY` |
| `email_guess` | Гипотезы адресов по шаблону (только с `--guess-emails`) | — |

Без единого ключа работают `website`, `dns`, `rdap`, `crtsh`, `egrul` — этого
хватает, чтобы по домену собрать контакты, инфраструктуру и реквизиты.

## Как считается уверенность

Уверенность — вероятность того, что значение действительно принадлежит
компании. Независимые источники объединяются по правилу «шумного ИЛИ»:

```
P = 1 - Π(1 - c_i)
```

Два источника по 0.6 дают 0.84 — в этом и смысл кросс-проверки. Повторы внутри
одного источника (одна и та же почта на пяти страницах сайта) добавляют
максимум +0.10, а не умножаются как независимые. Потолок — 0.99.

Дальше уверенность корректируется по связи с компанией:

- почта на домене компании — надбавка, помечается `corporate`;
- почта на бесплатном сервисе (`mail.ru`, `gmail.com`) — небольшой штраф;
- почта на чужом домене (`dev@webstudio.ru` в подвале сайта — контакт
  разработчика, а не компании) — штраф ×0.55 и явное замечание в отчёте.

Гипотезы (`email_guess`) идут с уверенностью ~0.2, в отчёте выносятся в
отдельный раздел «Гипотезы» и никогда не смешиваются с подтверждёнными
данными. Если гипотеза подтвердилась настоящей находкой — метка снимается и
проставляется `guess_confirmed`.

## Вежливость к чужим серверам

- `robots.txt` соблюдается по умолчанию (`--ignore-robots` — только для своих
  сайтов и с разрешения владельца);
- пауза между запросами к одному хосту (`--delay`, по умолчанию 1 с);
- ответы кэшируются в SQLite (`--cache`, TTL сутки) — повторный прогон не
  создаёт новой нагрузки;
- ретраи с экспоненциальной паузой и учётом `Retry-After`;
- честный `User-Agent` с описанием бота.

## Правовые рамки (Россия)

- Сведения ЕГРЮЛ/ЕГРИП открыты (ФЗ-129, ст. 6) — их сбор и использование
  законны.
- Корпоративные контакты (`info@`, телефон приёмной) — данные организации.
  ФИО, личная почта и мобильный конкретного человека — **персональные данные**:
  их обработка требует основания по ст. 6 152-ФЗ.
- Реклама по почте и через мессенджеры без предварительного согласия
  адресата запрещена (ст. 18 ФЗ «О рекламе»), штрафы — по ст. 14.3 КоАП.
- Условия использования сайтов и API не отменяются тем, что данные технически
  доступны: скрейпинг вопреки ToS — это спор с владельцем ресурса.

Программа собирает данные; ответственность за то, как они используются, лежит
на пользователе. Поэтому в отчёт всегда подставляется напоминание о 152-ФЗ.

## Использование из кода

```python
import asyncio
from company_intel import Config, Query, run_pipeline, to_markdown

profile = asyncio.run(run_pipeline(
    Query(name="ООО Ромашка", city="Москва"),
    Config.from_env(max_pages_per_site=20, allow_email_guessing=True),
))
print(to_markdown(profile))
print(profile.values("email", min_confidence=0.5))
```

## Как добавить свой источник

```python
# company_intel/sources/my_source.py
from ..models import Finding
from .base import Context, Source

class MySource(Source):
    name = "my_source"
    title = "Мой источник"
    reliability = 0.7                 # базовое доверие
    needs_keys = ("MY_API_KEY",)      # без ключа источник не запускается

    def input_signature(self, ctx: Context) -> str:
        return ctx.inn() or ""        # изменился вход — источник перезапустится

    async def run(self, ctx: Context) -> list[Finding]:
        data = await ctx.fetcher.get_json("https://api.example/company",
                                          params={"inn": ctx.inn()})
        if not data:
            return []
        return [self.finding("phone", data["phone"], url="https://api.example/company")]
```

Дальше — добавить класс в `ALL_SOURCE_CLASSES` в `sources/__init__.py`.
Слияние, дедупликация, уверенность и отчёт подхватят его сами.

## Структура

```
company_intel/
├── models.py      # Query, Finding, Provenance, Attribute, Profile
├── normalize.py   # телефоны, почта, домены, ИНН/ОГРН/КПП, транслитерация
├── extract.py     # разбор HTML и текста: контакты, реквизиты, люди, соцсети
├── merge.py       # дедупликация, «шумное ИЛИ», релевантность
├── http.py        # вежливый асинхронный клиент: robots, лимиты, кэш, ретраи
├── pipeline.py    # оркестратор раундов
├── report.py      # text / Markdown / CSV
├── cli.py         # командная строка
└── sources/       # плагины-источники
```

## Что нужно для промышленной версии

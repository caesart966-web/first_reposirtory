# sro-leads — сбор лидов на вступление в СРО

Ежедневно собирает из открытых источников компании, которым прямо сейчас нужна СРО,
обогащает их контактами и выгружает приоритизированный Excel для обзвона.

Один лид = один ИНН. Сигналы копятся, скор пересчитывается при каждом прогоне, дубли
не создаются (уникальность сигнала: ИНН + тип + дата). Дата сигнала — всегда дата самого
события (исключения, приостановки, вступления, контракта), а не дата обнаружения; если
в записи реестра даты нет, берётся дата снапшота. Откуда пришёл сигнал, видно в колонке
`detected_by` (`backfill`, `diff`, `file`): на дедуп и скоринг она не влияет.

## Что делает прогон `python run.py --full`

1. **collect** — по очереди запускает коллекторы из `config.yaml` (`collectors.enabled`).
   Падение одного коллектора пишется в лог с трейсбеком, остальные продолжают работу.
   - `nostroy_registry` — полный снапшот реестра членов НОСТРОЙ, дифф со вчерашним:
     пропал или стал «исключён» → `excluded_from_sro`, стал «приостановлен» → `suspended`,
     появился впервые → `joined_sro` (не лид, нужен для сверки).
   - `nopriz_registry` — то же по НОПРИЗ (проектирование и изыскания).
   - `tender_match` — читает выгрузки TenderGuru из `data/tenderguru/*.xlsx`, берёт ИНН
     подрядчиков, отбрасывает тех, кто есть в свежем снапшоте (проектирование сверяется с
     НОПРИЗ, стройка — с НОСТРОЙ), остальным ставит `tender_no_sro_design` (ОКПД 71.*),
     `tender_no_sro_build_high` (стройка > 10 млн) или `tender_no_sro_build_mid` (5–10 млн).
     Обработанные файлы уезжают в `data/tenderguru/processed/`.
2. **score** — веса и модификаторы из `config.yaml` (`scoring`), см. ниже.
3. **enrich** — только для организаций со скором ≥ `enrich.min_score`, не чаще раза в
   30 дней: Dadata по ИНН → локальные справочники `data/companies/*.xlsx` → поиск сайта
   и парсинг главной/контактов на почту и телефон. Ликвидированные помечаются и в
   экспорт не попадают. Найденный сайт не отбрасывается: в `orgs.site_verified` пишется,
   как он подтверждён (`inn` — на сайте найден ИНН, `name` — совпало ядро названия,
   `unverified` — взят из поисковой выдачи как есть, `dadata` и `directory` — пришёл из
   Dadata или локального справочника, проверка не требуется). Контакты с неподтверждённых
   сайтов попадают в отдельные колонки «Телефон (не подтверждён)» и «Почта (не
   подтверждена)», решение принимает менеджер.
4. **export** — `output/Лиды_YYYY-MM-DD.xlsx`, листы «Горячие» (приоритет 1, статус new),
   «Все лиды», «История сигналов». Заливка по приоритету: 1 красный, 2 жёлтый, 3 серый.
   ИНН — текстом, ведущие нули на месте.

Логи: `logs/YYYY-MM-DD.log` (INFO, ошибки с трейсбеком).

## Установка (Windows, Python 3.11+)

```bat
cd sro-leads
pip install -r requirements.txt
copy .env.example .env
```

В `.env` вписать `DADATA_TOKEN` (без него Dadata пропускается, работают локальные
справочники и парсинг сайтов). Секреты только в `.env`, он в git не попадает.

## Первый запуск и планировщик

```bat
python run.py --check-api nostroy                     # один запрос к API: сошлась ли карта полей
python run.py --check-api nopriz
python run.py --only nostroy_registry --backfill 90   # первый снапшот НОСТРОЙ + исключения за 90 дней
python run.py --only nopriz_registry --backfill 90    # то же по НОПРИЗ
python run.py --full                                  # далее ежедневно: диффы, тендеры, обогащение, Excel
```

`--check-api` делает один запрос минимальной страницей и печатает HTTP-статус и время
ответа, ключи верхнего уровня, первые три записи целиком и таблицу сверки: какое поле
из `registry.<источник>.fields` в какой ключ ответа легло и что в нём лежит. Ненайденные
поля помечены явно. В БД команда не пишет. Если показано расхождение, сначала правится
`config.yaml`, только потом снимается снапшот.

Режим `--backfill N` (по умолчанию 90 дней) не ждёт второго снапшота: он разбирает сами
записи реестра и берёт те, у которых членство прекращено или приостановлено, а дата
события попадает в последние N дней. Снапшот пишется в любом режиме. Поля с датой и
кодом статуса заданы в `registry.<источник>.fields` (`status_date`, `status_code`); если
в ответе API этого поля нет, коллектор падает с понятной ошибкой, а не отдаёт «ноль лидов».
Без `--backfill` работает штатный дифф со вчерашним снапшотом: первый снапшот сигналов
не даёт, диффы начинаются со второго дня.
Если снапшот за сегодня уже есть, повторный запуск его не пересобирает и ложных диффов
не создаёт. Снапшот меньше 50 % вчерашнего считается сбоем API: дифф не строится,
ошибка в логе, сырой ответ сохраняется как `*.failed.json.gz`.

Планировщик задач Windows: ежедневно в 08:00 запускать `run.bat` (рабочая папка —
папка проекта). После прогона откроется папка `output`.

Флаги `run.py`:

```
--only nostroy_registry     прогнать один коллектор (можно несколько через запятую)
--backfill [N]              реестры: сигналы из самих записей за N дней (по умолчанию 90) вместо диффа
--no-enrich                 собрать без обогащения
--export-only               только пересобрать Excel из БД
--full                      всё подряд (то же, что без флагов)
--mark ИНН статус [комментарий]   статус обзвона: new | called | in_progress | won | dead
--check-api nostroy|nopriz  один запрос к API реестра и сверка карты полей, в БД не пишет
```

Статусы обзвона живут в таблице `outreach`: экспорт по умолчанию берёт только `new`,
поэтому одного и того же дважды не долбим. После звонка:

```bat
python run.py --mark 7814858513 called "перезвонить в четверг"
```

## Скоринг

| Тип сигнала | Баллы |
|---|---|
| excluded_from_sro | 100 |
| tender_no_sro_design | 90 |
| tender_no_sro_build_high | 80 |
| suspended | 70 |
| tender_no_sro_build_mid | 50 |

Модификаторы: сигнал свежее 7 дней ×1.3, старше 90 дней ×0.5, два и более разных
типа по одному ИНН +30. Скор = сумма по всем сигналам. Приоритет: 1 при ≥ 100,
2 при 60–99, 3 ниже 60. Лидовый сигнал гасится сигналом `joined_sro` по тому же реестру,
только если дата вступления строго позже даты исключения или приостановки: компания,
вступившая в январе и исключённая в марте, остаётся лидом. Если у одной из записей даты
события нет, лид остаётся, а в экспорте в колонке «Конфликт дат» стоит «да» для ручной
проверки.

## Конфигурация

Всё в `config.yaml`: пути, эндпоинты и карта полей реестров, распознавание колонок
TenderGuru, веса скоринга, пороги обогащения, фильтры экспорта. Регион не фильтруется
на входе, только при экспорте. Блок `export`:

- `regions` — подстроки региона, пусто = без фильтра;
- `max_rows` — потолок строк на листе «Горячие» (по умолчанию 300), на «Все лиды» не действует;
- `min_score` — нижняя отсечка по скору (по умолчанию 0; организации без лидовых
  сигналов не выводятся в любом случае);
- `signal_max_age_days` — не выводить лиды, у которых свежайший сигнал старше N дней
  (по умолчанию 180);
- `outreach_statuses` — какие статусы обзвона выгружать (по умолчанию только `new`).

Эндпоинты реестров (`registry.nostroy`, `registry.nopriz`) заданы по открытому API
реестров; если рабочий пайплайн использует другие адреса или параметры — правится
только этот блок. Поддерживаются два режима: общий список членов одним эндпоинтом
или обход по СРО (`sro_list_endpoint` + `{sro_id}` в `members_endpoint`). Параметр
`pageCount` передаётся строкой (`page_count_as_string: true`), иначе API отдаёт пустоту.

## Структура

```
run.py                оркестратор: collect -> score -> enrich -> export
run.bat               запуск под Планировщик задач
config.yaml           источники, эндпоинты, веса, пути
core/db.py            схема SQLite (orgs, signals, registry_snapshots, outreach)
core/models.py        Signal, Org, RegistryRow, Snapshot
core/scoring.py       скоринг
core/enrich.py        обогащение
core/export.py        Excel
core/utils.py         конфиг, логи, нормализация ИНН, HTTP с ретраями
collectors/base.py    базовый Collector и общая логика реестров (снапшот, дифф)
collectors/*.py       коллекторы; новый = один файл с подклассом Collector
data/                 sro_leads.db, snapshots/, tenderguru/, companies/
output/               готовые Excel
logs/                 логи по дням
tests/                pytest
```

## Новый коллектор

Файл `collectors/имя.py` с классом-наследником `Collector`, у которого задано `name`
и реализован `collect() -> list[Signal]`. В БД коллектор не пишет: снапшот реестра
кладёт в `self.snapshot`, сигналы возвращает, а запись делает оркестратор одной
транзакцией; после успешной записи вызывается `finalize()` (например, переложить
обработанные файлы). Добавить имя в `collectors.enabled` в `config.yaml`.

## Правила по данным

В базу попадают только юрлица и ИП: ИНН, название, сайт, корпоративные контакты из
открытых источников. Личные телефоны, соцсети и переписка физлиц не собираются и не
хранятся. Список готовится для ручного обзвона и адресных писем, не для массовой
рассылки.

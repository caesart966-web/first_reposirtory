# Сайт «НОРМА» — вступление в СРО

Сайт ИП Багишева А. А.: помощь во вступлении в СРО, внесении специалистов в НРС,
прохождении НОК и получении лицензий.

**Эта инструкция написана для владельца сайта, а не для программиста.**
Всё, что нужно менять регулярно, лежит в двух-трёх файлах, и менять это можно
прямо на сайте github.com, ничего не устанавливая.

## 1. Как поменять телефон, почту и другие контакты

Всё — в одном файле: **`norma-site/src/config/site.ts`**

Открываете его на github.com, нажимаете карандаш (Edit), меняете нужную строку
в кавычках, внизу нажимаете «Commit changes». Через 2–3 минуты сайт обновится сам.

| Что меняем | Строка в файле | Замечание |
| --- | --- | --- |
| Телефон | `phone: '+7 931 969-86-64'` | **Обязательно поменяйте и строку ниже** — `phoneHref: 'tel:+79319698664'`. Это тот же номер без пробелов и дефисов. Если они разойдутся, посетитель увидит один номер, а позвонит на другой |
| Почта для заявок | `email: 'bagishevdelo@inbox.ru'` | |
| WhatsApp | `whatsapp: 'https://wa.me/79319698664'` | Номер без плюса и пробелов |
| Telegram | `telegram: 'https://t.me/+79319698664'` | Если появится имя вида `@alihan`, замените на `https://t.me/alihan` |
| MAX | `maxLink: ''` | Пока пусто — MAX не показывается на сайте. Ссылку вида `https://max.ru/u/XXXX` берут в приложении MAX («Поделиться» или QR-код), по номеру телефона её получить нельзя. Впишите её в кавычки — кнопка MAX появится сама |
| ОГРНИП | `ogrnip: ''` | Пока пусто — строка не показывается. Впишите номер, и он появится в подвале, контактах и политике |
| Название в шапке | `brand: 'НОРМА'` | И подпись под ним — `brandTag` |
| География | `geo: 'Санкт-Петербург · Ростов-на-Дону · работаем по всей России'` | |

Телефон в шапке, в подвале, в контактах, в кнопках и в мобильной панели берётся
из этого же файла — исправлять в нескольких местах не нужно.

### Как поменять логотип

Знак лежит в двух местах, и оба нужно менять вместе:

| Файл | Где виден |
| --- | --- |
| `src/components/LogoMark.astro` | шапка, подвал, картинка-превью для мессенджеров |
| `public/favicon.svg` | иконка вкладки браузера |

Знак векторный — остаётся чётким на любом экране и весит около трёхсот байт.
Цвет он берёт от родителя, поэтому один и тот же файл работает светлым
на тёмно-синем и тёмным на белом: отдельных версий не нужно.

### Как поменять цвет сайта

Акцентный цвет задан шестью строками в начале файла **`src/styles/global.css`**.
Поменяете их — перекрасится всё сразу: кнопки, ссылки, знак в шапке, иконки,
чипы с номерами статей. Прямо в комментарии рядом лежат бирюзовые значения,
которые были на сайте раньше, — можно вернуть их копированием.

Если знак понадобится заменить — пришлите новый в любом виде, я переведу
его в вектор и подставлю во все места разом. Картинку (PNG или JPG) вместо
вектора ставить не стоит: она размывается на крупных экранах и весит
в сотни раз больше.

После смены логотипа перегенерируйте картинку-превью для мессенджеров:

```bash
cd norma-site
npm run og
```

## 2. Как добавить статью в базу знаний

Каждая статья — отдельный текстовый файл в папке **`norma-site/src/content/articles/`**.

**Шаг 1.** Зайдите в эту папку на github.com и нажмите «Add file» → «Create new file».

**Шаг 2.** Придумайте имя файла латиницей, через дефис, с окончанием `.md`.
Имя файла станет адресом статьи:
`vznosy-sro-2027.md` → `ваш-домен.ru/baza-znaniy/vznosy-sro-2027/`

**Шаг 3.** Вставьте эту заготовку и замените текст на свой:

```markdown
---
title: Заголовок статьи, который увидит читатель
metaTitle: Заголовок для поисковика — до 60 знаков
description: Описание для поисковика, 1-2 предложения, до 180 знаков.
published: 2027-01-15
updated: 2027-01-15
excerpt: Одно-два предложения для карточки в списке статей.
order: 5
relatedService:
  label: Вступление в СРО строителей
  url: /uslugi/sro-stroiteley/
---

Первый абзац. Обычный текст, никакой разметки не нужно.

## Это подзаголовок

Ещё абзац. **Так выделяют жирным.** Список делается так:

- первый пункт
- второй пункт

Ссылка на свою же страницу: [страница стоимости](/stoimost/).
```

**Что означают поля вверху:**

| Поле | Что писать |
| --- | --- |
| `title` | Заголовок статьи на сайте. Если в нём есть двоеточие — возьмите весь заголовок в кавычки: `title: "Порог 10 млн: как считать"` |
| `metaTitle` | Заголовок для поисковика. Можно не указывать — тогда возьмётся `title` |
| `description` | Описание для поисковика. **До 180 знаков**, иначе обрежется в выдаче |
| `published` | Дата публикации: год-месяц-день |
| `updated` | Дата последней проверки. **Меняйте её каждый раз, когда обновляете статью** — эта дата видна читателю и работает на доверие |
| `excerpt` | Короткое описание для карточки в списке статей |
| `order` | Просто число, любое |
| `relatedService` | Ссылка на страницу услуги. **Не удаляйте это поле.** Без него читатель прочитает статью и уйдёт — а с ним перейдёт к услуге |

**Шаг 4.** Внизу страницы нажмите «Commit new file». Через 2–3 минуты статья появится
на сайте: в списке базы знаний, в блоке «Свежие разборы» на главной и в карте сайта
для поисковиков. Ничего дополнительно делать не нужно.

**Важно про даты.** Дата последней проверки — главное отличие вашего сайта.
Раз в квартал проходите по статьям, сверяйте цифры с законом и обновляйте `updated`,
даже если текст не менялся. Это две минуты работы и заметное преимущество в нише,
где половина сайтов не обновлялась годами.

## 3. Как поменять текст на странице

Тексты страниц лежат в папке **`norma-site/src/pages/`**:

| Страница на сайте | Файл |
| --- | --- |
| Главная | `index.astro` |
| Стоимость | `stoimost.astro` |
| Кому нужна СРО | `komu-nuzhna-sro.astro` |
| Контакты | `kontakty.astro` |
| Политика обработки данных | `politika.astro` |
| Список услуг | `uslugi/index.astro` |
| СРО строителей | `uslugi/sro-stroiteley.astro` |
| СРО проектировщиков | `uslugi/sro-proektirovshchikov.astro` |
| СРО изыскателей | `uslugi/sro-izyskateley.astro` |
| Специалисты НРС | `uslugi/nrs.astro` |
| НОК | `uslugi/nok.astro` |
| Лицензии | `uslugi/licenzii.astro` |

Открываете файл, находите нужный текст (браузером: Ctrl+F), меняете, сохраняете.

**Три правила, чтобы ничего не сломать:**

1. Меняйте только текст между знаками `>` и `<`, либо внутри кавычек.
2. Не трогайте скобки, кавычки и знаки `<` `>` — они держат разметку.
3. Если что-то сломалось — на странице «Actions» в GitHub будет красный крестик,
   а сайт останется в прежнем виде. Просто отмените последнее изменение
   (в истории файла есть кнопка Revert).

**Ответы на частые вопросы** (блок «Частые вопросы» на главной) — в файле
`index.astro`, ищите слово `const faq`. Там простой список: `q` — вопрос,
`a` — ответ. Можно добавлять свои по образцу.

## 4. Как обновить нормы и суммы взносов

Все цифры закона собраны в одном файле: **`norma-site/src/config/facts.ts`**

Там лежат таблицы взносов в компенсационные фонды по уровням ответственности —
отдельно для строителей, отдельно для проектировщиков и изыскателей. Если закон
изменится, правится только этот файл, и цифры обновятся сразу на всех страницах:
на странице «Стоимость», на страницах услуг и в обоих калькуляторах —
и в том, который отвечает «нужна ли СРО», и в том, который считает взносы.

**Про калькулятор взносов.** Он показывает только суммы компенсационных фондов,
установленные законом, и прямо пишет, чего в этой сумме нет: вступительного
и членских взносов, целевого взноса и страхования. Так сделано намеренно —
размеры этих взносов закон не устанавливает, их назначает каждая СРО своими
документами. Не превращайте итог калькулятора в «стоимость вступления»:
на этом сайте это была бы та самая цифра «под ключ», за которую он критикует
конкурентов.

После обновления цифр **обязательно поменяйте дату проверки** в файле
`src/config/site.ts`:

```
checkedDate: '29 августа 2026',
checkedDateISO: '2026-08-29',
```

Эта дата выводится штампом «Проверено» на видных местах и в подвале каждой страницы.

## 5. Как подключить Яндекс.Метрику

1. Заведите счётчик на metrika.yandex.ru, получите его номер (8 цифр).
2. Откройте `norma-site/src/config/site.ts` и впишите номер:
   ```
   metrikaId: '99999999',
   ```
3. Сохраните. Через 2–3 минуты счётчик заработает вместе с вебвизором.

**Цели уже настроены в коде** — их нужно только создать в интерфейсе Метрики
(«Настройка» → «Цели» → «JavaScript-событие») с такими идентификаторами:

| Идентификатор цели | Когда срабатывает |
| --- | --- |
| `quiz_start` | Посетитель начал проходить калькулятор |
| `quiz_step_2`, `quiz_step_3`, `quiz_step_4` | Дошёл до второго, третьего, четвёртого вопроса |
| `quiz_finish` | Увидел ответ калькулятора |
| `lead_submit` | **Отправил заявку** — главная цель |
| `click_phone` | Нажал на телефон |
| `click_whatsapp` | Нажал на WhatsApp |
| `click_telegram` | Нажал на Telegram |

Цели по шагам калькулятора покажут, на каком вопросе люди отваливаются.

## 6. Как переехать на свой домен

Сейчас сайт живёт по временному адресу-превью и **закрыт от поисковиков** —
чтобы черновик не попал в выдачу.

Когда купите домен:

1. Скажите мне (или разработчику) адрес домена — в настройках публикации меняются
   две строки: адрес сайта и признак «не индексировать».
2. У регистратора домена пропишите записи, которые выдаст хостинг.
3. После переезда сайт откроется для поисковиков автоматически: появятся правильный
   `robots.txt` со ссылкой на карту сайта и правильные адреса страниц.
4. Добавьте сайт в Яндекс.Вебмастер и Google Search Console, укажите там карту сайта:
   `https://ваш-домен.ru/sitemap-index.xml`

## 7. Как настроить приём заявок на почту

**Сейчас (на превью):** форма проверяет данные и, если отправка не настроена,
честно показывает телефон и мессенджеры — а не ложное «заявка отправлена».
Введённые данные при этом сохраняются в браузере посетителя.

**Почему не «как у всех»:** популярные зарубежные сервисы приёма форм
(Web3Forms, Formspree) из России без VPN не открываются. Заявки от ваших клиентов
до вас бы просто не доходили — молча. Поэтому сделан свой обработчик.

**Когда переедете на российский хостинг с PHP** (Beget, Timeweb, REG.RU):

1. Откройте файл `norma-site/public/api/submit.php` и заполните четыре строки вверху:

   | Строка | Что вписать |
   | --- | --- |
   | `MAIL_TO` | Куда приходят заявки: `bagishevdelo@inbox.ru` |
   | `MAIL_FROM` | **Адрес на вашем домене**, например `zayavka@ваш-домен.ru`. Заводится в панели хостинга за минуту. Чужой домен нельзя: письма уйдут в спам |
   | `FORM_TOKEN` | Любая строка-пароль, например `norma-2027-xyz` |
   | `ALLOWED_HOST` | Ваш домен, чтобы чужие сайты не слали заявки от вашего имени |

2. При сборке сайта задайте те же значения:
   `PUBLIC_LEAD_ENDPOINT=/api/submit.php` и `PUBLIC_LEAD_TOKEN=` (та же строка, что `FORM_TOKEN`).

3. **Отправьте себе тестовую заявку и проверьте папку «Спам».** Первое письмо
   почти наверняка попадёт туда. Найдите его, нажмите «Не спам», добавьте отправителя
   в адресную книгу и сделайте фильтр в отдельную папку «Заявки с сайта».

**Заявки не теряются, даже если почта сломается.** Каждая заявка записывается
в файл `api/leads.jsonl` на хостинге **до** отправки письма. Если письмо не ушло,
заявка всё равно там. Файл закрыт от посторонних.

## 8. Как поменять шрифты

На сайте один шрифт на всё — **Inter**. Тот же, что на вашем соседнем сайте.
Заголовки, текст, номера статей закона, телефон и подписи набраны им,
разница только в насыщенности и размере.

Шрифт лежит на самом сайте, а не подгружается с чужих серверов, — он
одинаково быстро открывается и в России, и за границей. Файлов четыре
(кириллица, латиница и по одному на курсив), заранее грузятся только два —
42 КБ. До перехода на один шрифт файлов было десять, а заранее грузилось
157 КБ: страница «Стоимость» после этого стала открываться на 100 баллов
вместо 97.

**Если захотите другой шрифт**, порядок такой (это работа для того, кто
разбирается в коде, — пришлите задачу мне или разработчику):

1. Поставить пакет со шрифтом: `npm install --save-dev @fontsource/название`.
2. Вписать его в `scripts/subset-fonts.py` и запустить `npm run fonts` —
   скрипт вырежет из шрифта всё, кроме нужных букв и цифр.
3. Прописать шрифт в `src/styles/fonts.css` и в `src/styles/global.css`
   (строки `--font-head` и `--font-body`).
4. Обновить список предзагрузки в `src/layouts/Base.astro`.
5. Запустить `node scripts/font-metrics.mjs` и подставить полученные числа
   в запасные шрифты — иначе страница будет дёргаться при загрузке.

## 9. Как поменять видео на первом экране

Файлы лежат в `norma-site/public/video/`:

| Файл | Что это |
| --- | --- |
| `hero.mp4` | Ролик для Safari и айфонов |
| `hero.webm` | Тот же ролик для Chrome, Яндекс.Браузера, Firefox и Edge |
| `hero-poster.webp` | Первый кадр. Показывается, пока ролик грузится |

Чтобы поменять ролик, положите на их место свои файлы **с теми же именами**.
Больше ничего править не нужно.

**Важно про вес.** Исходный ролик весил 4,8 МБ — с таким первый экран
открывался бы на телефоне мучительно долго. Сейчас 0,8 МБ. Если будете
менять ролик, сожмите его так же (это делается программой ffmpeg, команды
записаны в истории проекта — попросите разработчика).

**Как ролик ведёт себя у посетителя.** Он не грузится, пока страница
не открылась полностью: сначала человек видит первый кадр картинкой,
и только потом, в свободную минуту, подтягивается видео. Совсем не грузится,
если в браузере включена экономия трафика или в системе стоит «уменьшить
движение». Звука в файле нет — браузеры всё равно запрещают автозапуск
со звуком.

**Убрать видео совсем:** удалите строку `<BgVideo name="hero" band />` из
`src/components/Hero.astro`. Останется тёмно-синий фон.

**Подготовить свой ролик:** положите исходник куда угодно и выполните
`node scripts/encode-video.mjs путь/к/ролику.mp4 hero`. Скрипт сам сожмёт
файл примерно в семь раз, поднимет контраст, вырежет звук и сделает
все три файла разом.

## 10. Главное предложение: условия вступления

Пять условий, которых нет у конкурентов, лежат в одном файле:
**`norma-site/src/config/offer.ts`**

Поменяли там — обновилось везде: карточка на первом экране, яркий блок
на главной и такой же блок на странице стоимости.

**Правило, которое нельзя нарушать.** Это условия саморегулируемых
организаций, с которыми вы работаете, **а не нормы закона**. Закон таких
льгот не устанавливает: он задаёт размеры компенсационных фондов
и требования к членству, а вступительный взнос, членские взносы
и страхование — внутренние документы каждой СРО.

Поэтому рядом с этими пунктами **не должно появиться чипа со статьёй
закона**. Чип на сайте означает «так написано в законе», и поставить его
здесь значило бы выдать коммерческие условия за норму — ровно за это сайт
критикует конкурентов на странице «Как проверить СРО».

По той же причине внизу блока стоит оговорка о том, что набор условий
зависит от подобранной СРО. **Снимать её нельзя.**

## 11. Как добавить или убрать услугу

Список услуг лежит в **`norma-site/src/config/services.ts`**. Оттуда его берут
и главная, и раздел «Услуги», и подвал — дописали услугу там, и она появится
во всех трёх местах сразу.

У каждой услуги есть `group` — раздел, в который она попадает на странице
«Услуги»:

| group | Раздел на странице |
| --- | --- |
| `sro` | Членство в СРО |
| `people` | Специалисты и разрешения |
| `safety` | Безопасность, охрана труда и право |
| `marketing` | Заказы после вступления |

Кроме записи в списке услуге нужна своя страница:
`src/pages/uslugi/<slug>.astro`, где `<slug>` — тот же, что в списке.
Проще всего скопировать соседнюю страницу и переписать текст.

**Про три последние услуги — промышленная безопасность, охрана труда
и юридические услуги.** Эти темы регулируются не Градостроительным кодексом,
а трудовым законодательством, актами Ростехнадзора и гражданским правом.
Сверить их дословно при сборке сайта не удалось, поэтому на этих страницах
намеренно **нет** ни сроков вроде «раз в три года», ни номеров постановлений,
ни буквенных обозначений областей аттестации: неверная цифра здесь стоила бы
дороже, чем её отсутствие. Появятся сверенные нормы — добавляйте их чипом
со ссылкой на статью, как сделано на страницах про СРО.

## 12. Предложение про бесплатный сайт

Оно живёт в двух местах:

| Где | Файл | Что менять |
| --- | --- | --- |
| Строка внутри главного предложения | `src/components/SpecialOffer.astro` | Подпись «И сайт компании бесплатно» |
| Страница с подробностями | `src/pages/uslugi/marketing.astro` | Всё описание услуг |

Раньше предложение было ещё в двух местах: карточкой в углу экрана при
прокрутке и отдельным ярко-синим блоком на главной. Оба убраны. Карточка
в углу — потому что то же предложение уже стояло на первом экране, и дважды
на одной странице это читается как навязчивость. Ярко-синий блок — потому
что он шёл сразу под таким же ярко-синим блоком главного предложения:
две цветные плиты подряд читались как одна, а строка про сайт и так есть
внутри первой.

**Цены на маркетинг.** На странице `uslugi/marketing.astro` сейчас написано
«обсуждается индивидуально». Пришлите настоящие цены — впишу. Выдумывать
их я не стал: весь сайт держится на том, что цифры можно проверить.

## 13. Две страницы, где важна осторожность с фактами

Две страницы сделаны не как реклама, а как справка, и при правках у них есть
своё правило. Оно записано и в самих файлах, в комментарии сверху.

**«Какие документы нужны»** — `src/pages/dokumenty.astro`

Списки подписаны «обычно просят», а не «требует закон». Причина: закон
устанавливает требования к членству, а конкретный перечень бумаг добирает
каждая СРО своими внутренними документами, и он у разных СРО разный. Поэтому
в списках нет ссылок на пункты вроде «п. 3 ч. 2 ст. 55.6» — статья указана,
пункты указывать было бы домыслом.

**«Как проверить СРО»** — `src/pages/proverit-sro.astro`

Страница учит посетителя обходиться без вас: как самому проверить организацию
по реестру. Это сделано осознанно — на сайте, который стоит на проверяемости,
такая страница работает лучше любых заверений.

Там намеренно **нет** разбора того, что происходит с членами и с компенсационным
фондом, если СРО исключают из государственного реестра. Это требует точной
сверки с действующей редакцией закона; непроверенная деталь именно на этой
странице обесценила бы весь сайт. Понадобится — сверьтесь с законом
и добавьте с чипом статьи, как сделано везде.

### Решения, которые не стоит откатывать

- **`font-display: optional` + предзагрузка урезанных шрифтов.** Даёт CLS = 0.
  С обычным `swap` страница дёргалась при подмене шрифта (CLS 0.26).
- **`font-variant-numeric: lining-nums` в `global.css`.** Playfair по умолчанию
  рисует старостильные цифры: 2, 0 и 1 ростом со строчную букву, у 7 и 9 хвост
  вниз. В книге это красиво, но «10 млн ₽» и «2017 года» начинают выглядеть
  опечаткой. Строка возвращает обычные цифры одной высоты.
- **`{' '}` в конце строки перед `<b>`, `<a>` и `<strong>`.** Astro съедает
  перенос строки перед тегом, и слова слипаются: «конкретной СРО.Мои услуги».
  На рубленом шрифте это было почти незаметно, на антикве — бросается в глаза.
- **`[hidden] { display: none !important }` в `global.css`.** Без этой строки
  собственные `display: grid` в компонентах перебивают атрибут `hidden`, и скрытые
  экраны (успех, ошибка формы, мобильное меню) видны на странице всегда.
- **Класс `.js` на `<html>`.** Блоки прячутся под анимацию появления только когда
  скрипт точно работает. Иначе при осечке JavaScript посетитель увидел бы пустую страницу.
- **`min-width: 0` на колонках сеток с таблицами.** Без него широкая таблица
  распирает страницу, и на телефоне появляется горизонтальная прокрутка.
- **Проверка `success` в ответе сервера при отправке заявки.** Ответ «200» без
  подтверждения — это отказ, а не успех: так выглядит заглушка хостинга или
  невыполненный PHP. Иначе заявки теряются молча.

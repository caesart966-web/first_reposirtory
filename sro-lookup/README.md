# В каких СРО состоят компании

Принимает список компаний (название + ИНН) и отвечает, в каких
саморегулируемых организациях они состоят.

Источник — **открытые реестры**:

* [reestr.nostroy.ru](https://reestr.nostroy.ru) — строители;
* [reestr.nopriz.ru](https://reestr.nopriz.ru) — проектировщики и изыскатели.

Оба бесплатны, ключей не требуют, суточных лимитов нет.

## Запуск

**Windows.** Перетащите Excel со списком компаний на `НАЙТИ-СРО.bat`.
При первом запуске он сам создаст окружение и поставит зависимости.

**Командная строка.**

```bash
pip install -r requirements.txt
python3 find_sro.py компании.xlsx
```

Результат — `компании_СРО.xlsx` рядом с исходным файлом.

## Вернуть телефоны и почты в отчёт

Отчёт по СРО отвечает про членство, но телефонов и почт в нём нет — они
остались в исходном списке. Склеить одно с другим по ИНН:

```bash
python3 merge_sro.py --sro лиды_СРО.xlsx --source лиды.xlsx
```

По умолчанию добавляются «Телефон» и «Email»; другой набор — через
`--columns "Телефон,Email,Руководитель,Приоритет"`. Компания, состоящая
в нескольких СРО, занимает несколько строк, и контакты проставляются
в каждую. Ведущие нули в ИНН восстанавливаются с обеих сторон, поэтому
сопоставление не срывается из-за того, что в одном файле ИНН записан
числом, а в другом текстом.

Оба исходных файла остаются нетронутыми, результат — новый файл.

## Короткая таблица

Когда нужен только ответ «состоит или нет»:

```bash
python3 find_sro.py компании.xlsx --simple
```

Пять колонок: `Поставщик`, `ИНН`, `Есть СРО`, `В какой СРО`, `Реестр`.
Одна строка на компанию — если СРО несколько, они перечисляются в одной
ячейке, иначе таблица перестаёт быть простой.

## Входной файл

Нужны только **название и ИНН**. Ни порядок колонок, ни наличие шапки
значения не имеют. Повторяющиеся ИНН запрашиваются один раз.

Разбор рассчитан на реальные выгрузки, а не на идеальные файлы:

* **лист с данными выбирается сам** — в книге бывают листы с инструкцией
  и легендой, данные могут лежать на втором;
* **колонка наименования берётся из заголовка** (`Поставщик`, `Наименование`,
  `Компания`), потому что текстовых колонок в строке обычно несколько —
  приоритет, регион, должность — и угадывать нечего;
* **ведущий ноль в ИНН восстанавливается**: Excel хранит ИНН числом, если
  ячейку не пометили текстом, и `0274147157` превращается в `274147157`.
  Ноль дописывается только там, где потерян ровно один разряд, и только
  если результат сходится по контрольной сумме — иначе любое число из
  текста стало бы «ИНН»;
* если в строке колонки переставлены, ИНН ищется по всей строке — терять
  компанию из-за сбитой разметки нельзя.

| | |
|---|---|
| `ООО "ОЛЛИ ИТ"` | `7813692784` |
| `ООО "ЭКГК ФАКТСТРОЙ"` | `7817158012` |

## Что в результате

| Колонка | Содержание |
|---|---|
| Название компании | из входного файла, ОПФ сокращена до `ООО «…»`, `АО «…»` |
| ИНН | как во входном файле |
| СРО | наименование организации |
| Рег. номер СРО | `СРО-С-410-16122014` |
| Реестр | НОСТРОЙ или НОПРИЗ |
| Статус членства | как в реестре: «Является членом СРО», «Исключён» |
| Дата вступления | из реестра |
| Результат проверки | пусто, если всё нашлось |

**Компания может состоять сразу в нескольких СРО** — например, в строительной
и в проектной. Тогда на неё приходится несколько строк, по одной на членство.
Поэтому опрашиваются оба реестра, а не первый ответивший.

## Состоит ли в конкретной СРО

Чаще спрашивают не «в каких СРО состоит», а «состоит ли вот в этой».
Ключ `--target-sro` добавляет отдельную колонку с прямым ответом:

```bash
python3 find_sro.py компании.xlsx --target-sro "ОРС"
```

Колонка «Состоит в ОРС» встаёт сразу после ИНН и содержит `Да`, `Нет`
или `не проверено`. Если компания состоит в другой СРО, её наименование
видно в колонке «СРО» — так сразу понятно, где именно.

Короткая аббревиатура ищется по границам слова: иначе «ОРС» нашлось бы
внутри «ПОМОРСКОГО» и любая СРО оказалась бы искомой. Известные сокращения
(`ОРС` → «Объединение Ростовских Строителей») подставляются автоматически;
можно передать и полное наименование, и несколько вариантов через `|`.

Компания может состоять сразу в нескольких СРО и занимать несколько строк —
ответ про искомую СРО во всех её строках один и тот же, потому что вопрос
относится к компании целиком.

## «Не состоит» и «не проверено» — разные вещи

Это главное правило отчёта, и оно важнее скорости.

* **Розовая строка** — реестры ответили, записи нет. Компания действительно
  не состоит в СРО. Это достоверный отрицательный ответ.
* **Жёлтая строка** — реестр не ответил (недоступен, таймаут, сбой сети).
  Проверка **не состоялась**. Такую строку нужно перезапустить позже.

Смешивать их нельзя: выдать «не состоит в СРО» там, где проверка не
выполнялась, значит подсунуть выдумку вместо факта. В сводке после запуска
эти два числа тоже разведены.

## Частота запросов

По умолчанию один запрос в секунду — реестры общие и публичные, частить
невежливо. Для больших списков можно ускорить:

```bash
python3 find_sro.py компании.xlsx --rps 3
```

## Тесты

```bash
python3 -m unittest discover -s tests
```

Сеть не нужна: ответы реестра подменяются образцами.

# CLAUDE.md — путеводитель по репозиторию

В репозитории несколько независимых проектов:

- **`orders-app/`** — PWA «Заказы»: учёт заказов фрилансера (React + Vite + TypeScript +
  Tailwind + Dexie/IndexedDB, офлайн, публикуется на GitHub Pages через
  `.github/workflows/deploy-orders-app.yml`). Структура, правила и инструкции —
  в `orders-app/README.md`. Ключевое правило домена: комиссия хранится снимком
  (`commissionRate`) в самом заказе, поэтому изменение процента у источника
  не меняет уже созданные заказы; производные величины (комиссия, «на руки»,
  остаток, дни до срока) не хранятся, а считаются в `src/lib/calc.ts`.
- **`master-site/`** — сайт строительной компании ООО «МАСТЕР» (Ростов-на-Дону):
  одностраничник на чистой статике (HTML + CSS + vanilla JS, без сборщиков), весь
  контент и все фотографии взяты из PDF презентации компании. Инструкция для
  заказчика — `master-site/README.md`, выписка фактов из презентации —
  `master-site/CONTENT.md`, решения по оформлению — `master-site/DESIGN.md`.
  Ключевое правило: на сайт не попадает ничего, чего нет в презентации.
- **`sro-site/`** — одностраничный сайт частного специалиста по СРО (Игорь Парфенов;
  React + Vite + TypeScript + Tailwind + lucide-react). Все реальные данные — плейсхолдерами
  вида `[ИМЯ]`, `[ТЕЛЕФОН]`, `[ЦЕНА]`; единая точка контактов — `sro-site/src/content/contacts.ts`,
  приём заявок из квиза подключается в `sro-site/src/lib/lead.ts`. Ключевое правило:
  никаких выдуманных фактов, цифр, цен и сроков. Инструкции — `sro-site/README.md`.
- **`norma-site/`** — многостраничный сайт «НОРМА» по вступлению в СРО (ИП Багишев А. А.;
  Astro 7, статическая генерация, без фронтенд-фреймворков в браузере). Отстройка строится
  на двух вещах: **эталонная точность** (у каждого факта — чип со статьёй закона, у страниц
  и статей — штамп «Проверено» с датой) и **честность** (калькулятор «Нужна ли вам СРО»
  умеет отвечать «не нужна» со ссылкой на норму). Единые точки правды:
  `src/config/site.ts` — контакты и реквизиты, `src/config/facts.ts` — нормы и таблицы
  взносов, `src/config/services.ts` — список услуг, `src/content/articles/` — статьи.
  Ключевые правила: порог для строителей — 10 млн ₽ (не 3 млн), «допусков СРО»
  не существует с 2017 года, региональный принцип действует только для строителей,
  КФ ОДО раскрывается отдельной строкой. Отдельное предложение: при вступлении
  через заказчика его маркетологи бесплатно делают компании сайт — этому посвящены
  `BonusOffer.astro`, `OfferToast.astro` и страница `uslugi/marketing.astro`.
  Шрифт один на весь сайт — Inter, тот же, что в `sro-site`.
  На первом экране — видео стройплощадки (`public/video/`), оно грузится только
  после полной загрузки страницы; читаемость текста поверх него проверяется
  скриптом `scripts/test-hero-contrast.mjs` по реальным кадрам.
  Инструкция для заказчика и описание проекта — `norma-site/README.md`.
- **`.claude/skills/construction-control/`** — скилл строительного контроля (ниже).

---

**`/construction-control`** — кастомный Claude Code skill,
ИИ-ассистент строительного контроля: по документам стройки (договор, смета/ВОР,
график, планы помещений, техкарты) и видеообходам объекта он оценивает прогресс,
сравнивает факт с графиком/сметой, находит отклонения, дефекты и риски и формирует
недельный отчёт.

## Где что лежит

- `.claude/skills/construction-control/SKILL.md` — точка входа скилла (принципы,
  5 агентов, оркестрация, рабочий процесс из 13 шагов).
- `.claude/skills/construction-control/references/` — архитектура, модель данных,
  логика агентов, MCP-инструменты, обработка видео, расчёт отклонений,
  human-in-the-loop, workflow, MVP, критерии приёмки, тесты, риски.
- `.claude/skills/construction-control/schemas/` — строгие JSON Schema всех выходов.
- `.claude/skills/construction-control/scripts/` — `deviation.py` (расчёт отклонений),
  `validate.py` (валидация JSON по схемам).
- `.claude/skills/construction-control/templates/weekly-report.md` — шаблон отчёта.

## Как активируется скилл

В сессии Claude Code, открытой на этом репозитории, скилл подхватывается
автоматически. Запуск: пользователь загружает документы/видео и пишет
`/construction-control` либо просто описывает задачу (например: «оцени прогресс по
этому обходу и графику, найди отставания»).

## Незыблемые правила скилла (соблюдать при любой работе в этом репозитории)

- Факт о выполненных работах — только по кадрам-доказательствам (`EvidenceFrame`);
  ссылки на документы — только реальные, иначе `null` и ниже `confidence`.
- Все выходы агентов — строго по JSON Schema из `schemas/` (проверять `validate.py`).
- Расчёты отклонений — детерминированной арифметикой (`deviation.py`), не «на глаз».
- Human-in-the-loop: система НЕ подписывает акты, НЕ подтверждает скрытые работы по
  видео, НЕ принимает работы окончательно; критические/спорные выводы помечаются
  `requires_human_review: true`.

## Статус реализации

Скилл — это полный **проект и оркестрация**: методология, промпты агентов, схемы
данных и рабочие расчётные скрипты. Продовый backend (MCP-сервер `construction-mcp`
с реальными парсерами PDF/DOCX/XLSX, извлечением кадров, OCR/ASR, БД и векторным
поиском) описан в `references/mcp-tools.md`, но как отдельная система ещё не собран.
До его реализации скилл работает в «ассистируемом» режиме: Claude сам читает
загруженные файлы и кадры и следует методологии скилла.

## Быстрая проверка

```bash
cd .claude/skills/construction-control
python3 scripts/deviation.py --demo            # пример расчёта отклонения
pip install jsonschema
python3 scripts/validate.py issue <файл.json>  # валидация проблемы по схеме
```

# Брендбуки

Три руководства по фирменному стилю — по одному на каждый бренд репозитория.
Каждый брендбук — один HTML-файл: открывается двойным щелчком в любом браузере,
его можно переслать дизайнеру, типографии или подрядчику. Фотографии вшиты
в файл, шрифты подгружаются с Google Fonts (нужен интернет).

| Файл | Бренд | Подача |
| --- | --- | --- |
| `norma.html` | НОРМА, вступление в СРО (norma-sro.ru) | «Синяя печать» (редакция 2.0, как сайт с 7 октября 2026): белый лист, синий штемпель, Фемида на первом экране, десять статей, как в кодексе |
| `biznes-grupp.html` | ООО «БИЗНЕС-ГРУПП» (biznesgrp.ru) | Монография: тёплый монохром, латунь, графит |
| `x-pto.html` | X-PTO, документальное сопровождение строительства (x-pto.ru) | Альбом чертежей: листы с рамкой и основной надписью, светлая и тёмная темы |

Что внутри у каждого: идея и позиционирование, знак с построением, логотип
и ошибки применения, цвет с замером контраста по WCAG, шрифты и шкала,
графические приёмы, фотография, тон текстов, носители (визитка, бланк или
титульный лист, обложка для соцсетей). Образцы цвета копируют код по нажатию.

## Правка и сборка

**Готовые `*.html` руками не править** — их пишет сборка. Правится исходник
в `src/`, затем:

```bash
node brandbooks/build.mjs
```

Сборка делает две вещи.

1. **Вшивает фотографии.** В исходнике стоит `{{img:путь от корня репозитория}}`,
   в готовый файл кадр уходит data URI.
2. **Сверяет брендбук с сайтом.** Знак, цвета и контакты в брендбуке нарисованы
   и написаны руками, а живут в исходниках сайтов. Каждый контур знака, каждый
   код цвета и каждый контакт читается из исходника сайта и ищется в брендбуке;
   не нашёлся — сборка падает и называет, что и где. Проверено подделкой:
   изменённый цвет сургуча и телефон «НОРМЫ» роняют сборку.

| Бренд | Откуда берётся |
| --- | --- |
| НОРМА | знак — `norma-site/src/components/LogoMark.astro`; цвета — `norma-site/src/styles/global.css`; контакты, реквизиты, дата печати и фотографии (`heroPhoto`, `headPhoto`) — `norma-site/src/config/site.ts`; число компаний — `norma-site/src/config/about.ts` |
| БИЗНЕС-ГРУПП | знак — `ScalesMark` в `sro-site/src/components/illustrations.tsx`; шкалы цвета — `sro-site/tailwind.config.js`; контакты — `sro-site/src/content/contacts.ts` |
| X-PTO | знак — `pto-site/assets/img/logo.svg`; цвета — `pto-site/assets/style.css`; контакты и реквизиты — `pto-site/data/site.json` |

Поменяли на сайте телефон, оттенок, знак или фотографию — пересоберите брендбуки.
Сборка упадёт и покажет, какие места в `src/` переписать. Так и вышло
16 октября 2026 года: сайт НОРМЫ с 7 октября перекрашен в синий, брендбук
собирался на старой копии и оставался красным, а сборка на свежем `main`
сразу назвала все двенадцать цветов и дату печати. Фотографии сверяются
по исходнику (в готовом файле они уже data URI): раньше смена кадра на сайте
проходила мимо проверки.

Для публикации артефактом (страница без `<head>`):
`node brandbooks/build.mjs --fragments <папка>`.

## PDF

Готовые PDF лежат в `pdf/`: `norma.pdf`, `biznes-grupp.pdf`, `x-pto.pdf`.
Их можно отправить кому угодно: открываются на телефоне и компьютере без
браузера, шрифты и фотографии внутри.

Пересобрать после правки брендбука:

```bash
node brandbooks/build.mjs
node brandbooks/make-pdf.mjs
```

Нужен playwright с Chromium (`npm i -g playwright`, затем
`npx playwright install chromium`). За прокси с собственным сертификатом —
`NODE_USE_ENV_PROXY=1 node brandbooks/make-pdf.mjs`.

Каждый раздел — отдельная страница своей высоты, ширина у всех 1440 px.
На листах A4 разделы рвались бы посередине, а тёмный фон обрывался бы белой
полосой. Короткие блоки (полоса оглавления, выходные данные) уходят на
страницу к соседу. Подсказки «нажмите на образец» и кнопки анимаций в PDF
не попадают (класс `pdf-hide` и `[data-play]`).

Скрипт сам себя проверяет: перед печатью — что фирменные шрифты загрузились
(иначе PDF ушёл бы с запасной Georgia), после — что страниц ровно столько,
сколько разделов. Без ширины страницы по умолчанию браузер верстал печать
под лист Letter, 816 px, то есть мобильной раскладкой, и каждый раздел
расползался на две-три страницы — эту ошибку и ловит счёт страниц.

## Портфолио для Kwork

```bash
node brandbooks/make-portfolio.mjs
```

Собирает в `brandbooks/portfolio/<бренд>/` (в git не идёт, пересобирается):

| Файл | Что это |
| --- | --- |
| `00-oblozhka.jpg` | обложка работы — первый экран брендбука |
| `01-…jpg` … `08-…jpg` | слайды: кадры разделов, «компьютер и телефон», три телефона, все разделы одним полотном |
| `rolik.mp4` | брендбук пролистывается сверху донизу, 1920 × 1080 |

Размеры — по требованиям Kwork: картинки 1920 × 1280 и до 10 МБ, ролик
до 75 секунд и до 50 МБ; скрипт сам проверяет все три лимита.
Только картинки или только ролик: `PORTFOLIO_ONLY=images` или `video`.

**Контактов заказчиков на картинках и в ролике нет.** Телефоны и номера
ИНН/ОГРНИП заменены нулями, почта, сайты и мессенджеры — словами «почта»,
«сайт», «мессенджер», имена — «Имя Фамилия». По отзывам исполнителей,
модерация Kwork правит или отклоняет работы с контактами и ссылками
на сайты, а портфолио исполнителя — не место для телефона заказчика.
После замены скрипт читает текст страницы и падает, если хоть один
настоящий контакт остался: новый контакт в брендбуке без строки в `MASK`
не уйдёт в портфолио молча.

Названия работ (до 40 знаков, рубрика «Дизайн → Логотип и брендинг»,
тип «Фирменный стиль»):

- Брендбук «НОРМА» — вступление в СРО
- Брендбук ООО «БИЗНЕС-ГРУПП»
- Брендбук X-PTO — документация стройки

## Правила, которые брендбуки соблюдают сами

Каждый брендбук свёрстан по правилам своего бренда, а не по общему шаблону:

- **НОРМА** — печать «Сверено» стоит только рядом с нормами закона, у условий
  вступления, цен и на бланке её нет; акцент — синий штемпель, красный только
  у ошибок формы (и в «Так нельзя» — как прежняя редакция знака); заголовки
  антиквой обычным регистром, выделение — цветом, а не курсивом.
- **БИЗНЕС-ГРУПП** — надзаголовков и номеров у разделов нет, номера только
  у шагов работы; тексты без примет нейросети (без заголовков через двоеточие,
  фраз-анонсов, «не X, а Y»); имя компании везде юридическое и не переносится.
- **X-PTO** — две темы, как на сайте; цвет мелких подписей выбран по худшему
  фону; фотографии — только объекты, на которых вели документацию.
